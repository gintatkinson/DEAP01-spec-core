## 1. Normative Statement

The structural compiler SHALL formalize SysML v2 port definitions (`port def`, `PortDefinition`) and port usages (`port`, `PortUsage`) as interaction point classifiers specializing KerML `Structure`. A port definition $P$ defines an interface protocol specifying typed directed features. Every port usage $p$ declared on an enclosing component or part classifier $C$ SHALL possess an explicit or inferred directionality $`\text{dir}(p) \in \{ \text{In}, \text{Out}, \text{InOut} \}`$ and a valid classifier type $\tau(p) \le \text{PortDefinition}$.

The compiler MUST enforce conjugate port instantiation: declaring a port usage with conjugation operator $`\sim`$ ($p : {\sim}P$) SHALL bind the port usage to the conjugated interface where feature directions are inverted according to involution mapping: $`{\sim}\text{In} = \text{Out}`$, $`{\sim}\text{Out} = \text{In}`$, and $`{\sim}\text{InOut} = \text{InOut}`$. Conjugation of non-port classifiers SHALL emit diagnostic `E0200`.

Boundary encapsulation MUST be strictly preserved: external connections to component $C$ SHALL terminate exclusively at declared port usages $p \in \text{ports}(C)$, forbidding direct internal feature bypass. Any connection breaching boundary encapsulation SHALL be rejected with diagnostic `E0200`.

## 2. Formal Invariant

Let $``\mathcal{D}_{\text{port}}``$ denote the set of port definitions and $``\mathcal{U}_{\text{port}}``$ denote port usages:

```math
\begin{aligned}
\text{PortDefinition} &\le \text{Structure} \le \text{Class} \\
p \in \mathcal{U}_{\text{port}} &\implies \tau(p) \le \text{PortDefinition} \quad \wedge \quad \text{dir}(p) \in \{ \text{In}, \text{Out}, \text{InOut} \}
\end{aligned}
```

Conjugate port interface direction inversion invariant:

```math
\begin{aligned}
p : {\sim}P \implies \forall f \in \text{Features}(P), \quad \text{dir}(\pi_f(p)) = {\sim}\text{dir}(f) \\
{\sim}({\sim}d) = d \quad \forall d \in \{ \text{In}, \text{Out}, \text{InOut} \}
\end{aligned}
```

Boundary encapsulation and RFC 4122 UUIDv5 invariants:

```math
\begin{aligned}
\forall (e_1, e_2) \in \mathcal{E}_{\text{conn}}, \quad e_1 \in \text{External}(C) &\implies e_2 \in \text{Ports}(C) \\
\forall n \in \mathcal{D}_{\text{port}} \cup \mathcal{U}_{\text{port}}, \quad \Delta_n &= \text{UUIDv5}(\text{NS}_{\text{DEAP}}, \text{FQN}(n))
\end{aligned}
```

| $``\mathcal{D}_{\text{port}}``$ | Set of lowered `PortDefinition` classifier arena records |
| $``\mathcal{U}_{\text{port}}``$ | Set of lowered `PortUsage` interface feature arena records |

## 3. Computational Complexity & Algorithmic Bounds

The port definition lowering, typing, and direction inversion passes execute strictly within Complexity Class $\mathbf{P}$.

For an input model with $N$ port usages and $F$ total interface features:
1. Node allocation in typed arena and symbol interning execute in amortized $O(1)$ time per node, totaling $O(N)$ time.
2. Port type resolution evaluates via symbol table lookup in $O(1)$ time.
3. Conjugate interface expansion and feature direction inversion evaluate in $O(F)$ time, linear in the number of interface features without combinatorial search.
4. Boundary encapsulation validation executes in $O(1)$ set membership checks per connection endpoint.

Total sequential verification complexity is $O(N + F)$. Parallel package lowering scales as $``O((N + F) / N_{\text{max\_workers}} + \log N_{\text{max\_workers}})``$.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Canonical Port Definition and Conjugate Usage Lowering
- **Given:** A port definition `PortDef_Alpha` declaring directed features `in Flow_A : Real` and `out Flow_B : Real`, and usage `port Port_1 : ~PortDef_Alpha`.
- **When:** The compiler executes port lowering and interface conjugation.
- **Then:** Port usage `Port_1` is lowered into arena storage with inverted feature directions (`out Flow_A` and `in Flow_B`) and zero diagnostic emissions.
- **Diagnostic:** `E0200` emitted if conjugate feature expansion fails.

### AC-02: Non-Port Classifier Conjugation Rejection
- **Given:** A part usage attempting to apply conjugation to a non-port classifier (`port Port_Err : ~PartDef_Beta`).
- **When:** Semantic type checking validates the conjugation target.
- **Then:** The compiler rejects the declaration at compile time and emits diagnostic error code `E0200`.
- **Diagnostic:** `E0200` emitted for invalid conjugation on non-port classifier.

### AC-03: Boundary Encapsulation Breach Rejection
- **Given:** An external connector attempting to bind directly to internal constituent `Part_Alpha.InternalVar` bypassing declared boundary ports.
- **When:** Structural connection routing validates endpoint visibility.
- **Then:** The compiler halts connection lowering and emits diagnostic error code `E0200`.
- **Diagnostic:** `E0200` emitted for boundary encapsulation violation.

### AC-04: Port Multiplicity and Direction Verification
- **Given:** A port usage declared with invalid direction specifier or inverted multiplicity bounds `port Port_Bad : PortDef_Alpha [3..1]`.
- **When:** Semantic validation checks port multiplicity intervals.
- **Then:** The compiler rejects the malformed declaration with exact source spans and diagnostic error code `E0200`.
- **Diagnostic:** `E0200` emitted for invalid port multiplicity interval.
