## 1. Normative Statement

The protocol engine SHALL formalize SysML v2 interface definitions (`interface def`) as contractual association structures specifying complementary end-roles, and interface usages (`interface`) as communication protocol bindings between component ports. `InterfaceDefinition` SHALL specialize KerML `ConnectionDefinition`; `InterfaceUsage` SHALL specialize KerML `ConnectionUsage`.

The lowering engine MUST enforce conjugate duality and port binding:
1. **End-Role Duality**: A binary interface definition $I$ SHALL declare two end-roles $``\text{ends}(I) = (e_1, e_2)``$ satisfying conjugate duality $``\tau(e_2) \equiv {\sim}\tau(e_1)``$. Arity $\ne 2$ SHALL emit diagnostic `E0200`; non-conjugate types SHALL emit `E0201`.
2. **Port Binding**: Interface usage $u$ MUST bind two endpoints $``(p_1, p_2)``$ conforming to end-roles $``(e_1, e_2)``$ of interface $`I = \tau(u)`$: $``\text{type}(p_1) \le \tau(e_1) \wedge \text{type}(p_2) \le \tau(e_2)``$, ensuring $``\text{type}(p_1) \le {\sim}\text{type}(p_2)``$. Non-conforming port types SHALL emit `E0201`; dangling ends SHALL emit `E0220`.
3. **Owned Flows**: Declared item flows MUST preserve payload compatibility ($`\tau(\text{payload}) \le \tau(\text{flow})`$). Incompatible payloads SHALL emit `E0202`.
4. **Interface Inheritance**: Specialization hierarchies MUST form a bounded monotonic meet-semilattice resolved via C3 linearization in $O(V + E)$ time. Cyclic inheritance SHALL emit `E0200`.

## 2. Formal Invariant

Let $``\mathcal{D}_{\text{intf}}``$ denote interface definitions and $``\mathcal{U}_{\text{intf}}``$ denote lowered interface usages:

```math
\begin{aligned}
\text{InterfaceDefinition} &\le \text{ConnectionDefinition} \le \text{AssociationStructure} \\
\text{InterfaceUsage} &\le \text{ConnectionUsage} \le \text{Feature} \\
\text{ends}(I) = (e_1, e_2) &\implies \tau(e_2) \equiv {\sim}\tau(e_1) \\
u : I \wedge \mathcal{B}_u = (p_1, p_2) &\implies \text{type}(p_1) \le \tau(e_1) \wedge \text{type}(p_2) \le \tau(e_2) \\
|\text{ends}(I)| = 2 &\wedge |\mathcal{B}_u| = 2 \\
\forall w \in \mathcal{F}_I, \quad \tau(\text{payload}(w)) &\le \tau(\text{flow}(w)) \\
\forall n \in \mathcal{D}_{\text{intf}} \cup \mathcal{U}_{\text{intf}}, \quad \Delta_n &= \text{UUIDv5}(\text{NS}_{\text{DEAP}}, \text{FQN}(n))
\end{aligned}
```

## 3. Computational Complexity & Algorithmic Bounds

Interface lowering and verification execute within Complexity Class $\mathbf{P}$.

For an AST model with $M$ interface definitions, $N$ interface usages, $F$ features, and $E$ specialization edges:
- **Dual End-Role Conjugation**: $O(1)$ nominal type comparisons per definition ($O(M)$ total).
- **Port Binding Subtyping**: $O(1)$ amortized check per usage via cached bitsets ($O(N)$ total).
- **Flow Payload Conformance**: $O(1)$ check per declared flow feature ($O(F)$ total).
- **C3 Linearization**: Resolves the monotonic meet-semilattice hierarchy (tractable fragment of NP-3) in $O(V + E)$ time without backtracking.

Total sequential complexity is $O(M + N + F + E)$. Bounded work-stealing parallel lowering scales as $``O((M + N + F + E) / N_{\text{max\_workers}} + \log N_{\text{max\_workers}})``$.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Canonical Lowering and Binding
- **Given:** `InterfaceDef_Alpha` (ends `e1 : PortDef_0`, `e2 : ~PortDef_0`) and ports `Port_1 : PortDef_0`, `Port_2 : ~PortDef_0`.
- **When:** Lowering `interface InterfaceUsage_1 : InterfaceDef_Alpha connect part_1.Port_1 to part_2.Port_2;`.
- **Then:** Usage lowers into arena storage with bound endpoints and empty diagnostic sink.
- **Diagnostic:** Diagnostic sink remains empty.

### AC-02: Non-Conjugate End-Role Rejection
- **Given:** Definition `interface def InterfaceDef_Invalid { end e1 : PortDef_0; end e2 : PortDef_0; }`.
- **When:** Validating end-role conjugate duality.
- **Then:** Lowering rejects definition and emits diagnostic `E0201`.
- **Diagnostic:** `E0201` on conjugate duality mismatch.

### AC-03: Incompatible Port Binding Rejection
- **Given:** `InterfaceDef_Alpha` and binding `Port_1 : PortDef_0` to `Port_3 : PortDef_Beta` ($``\text{PortDef\_Beta} \not\le {\sim}\text{PortDef\_0}``$).
- **When:** Verifying port binding subtyping conformance.
- **Then:** Lowering rejects binding and emits diagnostic `E0201`.
- **Diagnostic:** `E0201` on port binding subtyping mismatch.

### AC-04: Dangling End-Role and Arity Rejection
- **Given:** Ternary definition `interface def InterfaceDef_Ternary`, or usage binding only one port.
- **When:** Validating arity and endpoint completeness.
- **Then:** Lowering rejects ternary definition with `E0200` and dangling usage with `E0220`.
- **Diagnostic:** `E0200` on invalid arity; `E0220` on dangling usage.
