## 1. Normative Statement

The compiler platform shall generate all synthetic entity identifiers, specification document anchors (Epics, Features, User Stories, Use Cases), intermediate representation node handles, and downstream artifact keys exclusively via deterministic RFC 4122 UUIDv5 namespace hashing. In accordance with Architectural Directive 1, time-based UUIDs (UUIDv1, UUIDv6, UUIDv7) and pseudo-random UUIDs (UUIDv4) are strictly prohibited across all passes to eliminate entropy injection and preserve bitwise reproducibility and Merkle root digests.

The hashing engine shall accept a fixed compiler namespace UUID constant ($``\text{NS}_{\text{DEAP}}``$) and the canonical fully qualified topological path string ($``\mathcal{N}_{\text{topological}}``$) of the target AST entity (e.g., `Package_0::Subsystem_Alpha::Classifier_Beta`). Canonical topological paths must strictly use uniform scope delimiters (`::`), case-sensitive ASCII representation, and abstract entity naming without host-dependent filesystem path prefixes, mount roots, or process descriptors.

The UUIDv5 engine shall compute the SHA-1 digest over the big-endian concatenation of the 16 namespace octets and the UTF-8 encoded canonical path string. The resulting 160-bit digest shall be truncated to 16 octets, setting version bits to $``0101_2``$ (Version 5, octet 6) and variant bits to $``10_2``$ (RFC 4122 variant, octet 8). Emitted strings shall conform to the canonical 36-character hyphenated lowercase hexadecimal format (`8-4-4-4-12`).

Identifiers must remain strictly invariant across execution environments, CPU architectures, endianness, host operating systems, filesystem mount points, thread allocations in the bounded work-stealing pool, and physical build timestamps. On detection of an invalid path, host path prefix, hash collision, or non-deterministic UUID, the compiler shall halt execution immediately and emit diagnostic error code `E0100`.

## 2. Formal Invariant

Let $``\text{NS}_{\text{DEAP}} \in \{0, 1\}^{128}``$ denote the fixed 128-bit RFC 4122 namespace UUID constant in network byte order. Let $``\mathcal{N}_{\text{topological}}(v) \in \Sigma^*``$ denote the canonical fully qualified topological path of element $`v \in \mathcal{V}`$:

```math
\mathcal{N}_{\text{topological}}(v) = p_0 \mathbin{::} p_1 \mathbin{::} \dots \mathbin{::} \text{Name}(v)
```

where each $``p_i``$ is a sanitized identifier token and $`::`$ is the scope delimiter. Let $`\text{Bytes}(\cdot)`$ denote UTF-8 byte serialization and $`\mathbin{\Vert}`$ byte concatenation. The 160-bit SHA-1 digest is:

```math
H(v) = \text{SHA1}(\text{NS}_{\text{DEAP}} \mathbin{\Vert} \text{Bytes}(\mathcal{N}_{\text{topological}}(v))) = (h_0, h_1, \dots, h_{19}) \in (\mathbb{Z}_{256})^{20}
```

The 128-bit RFC 4122 UUIDv5 octet sequence $``U(v) = (u_0, u_1, \dots, u_{15}) \in (\mathbb{Z}_{256})^{16}``$ satisfies:

```math
\begin{aligned}
u_i &= h_i \quad \forall i \in \{0, \dots, 15\} \setminus \{6, 8\} \\
u_6 &= (h_6 \land 0\text{x0F}) \lor 0\text{x50} \\
u_8 &= (h_8 \land 0\text{x3F}) \lor 0\text{x80}
\end{aligned}
```

The generated identifier satisfies the RFC 4122 Version 5 and Leach-Salz Variant invariants:

```math
\text{Version}(U) = (u_6 \gg 4) = 5, \quad \text{Variant}(U) = (u_8 \gg 6) = 2
```

Environmental Invariance Invariant: let runtime context be $`\mathcal{E} = (\text{Host}, \text{Timestamp}, \text{MountPath}, \text{ThreadID}, \text{Arch})`$. Across any two contexts $``\mathcal{E}_1, \mathcal{E}_2``$:

```math
\forall v \in \mathcal{V}, \quad U(v; \mathcal{E}_1) = U(v; \mathcal{E}_2)
```

Bijective Determinism and Cryptographic Collision Resistance:

```math
\forall \mathcal{N}_1, \mathcal{N}_2 \in \Sigma^*, \quad \mathcal{N}_1 = \mathcal{N}_2 \iff U(\mathcal{N}_1) = U(\mathcal{N}_2)
```

```math
\forall \mathcal{N}_1 \neq \mathcal{N}_2, \quad \Pr(U(\mathcal{N}_1) = U(\mathcal{N}_2)) \le 2^{-128}
```

## 3. Computational Complexity & Algorithmic Bounds

The RFC 4122 UUIDv5 generation pipeline executes strictly within Complexity Class $`\mathbf{P}`$. For a canonical path string of byte length $``L = |\text{Bytes}(\mathcal{N}_{\text{topological}})|``$, SHA-1 hashing processes $`16 + L`$ bytes across $`\lceil (L + 25) / 64 \rceil`$ fixed 512-bit compression blocks, taking deterministic linear time $``O(L) = O(|\mathcal{N}_{\text{topological}}|)``$. Truncation, version/variant bitwise masking, and formatting execute in strictly $`O(1)`$ constant time.

For an AST graph $`\mathcal{A} = (\mathcal{V}, \mathcal{E})`$ with $`V = |\mathcal{V}|`$ nodes and total qualified path length $``L_{\text{total}} = \sum_{v \in \mathcal{V}} |\mathcal{N}_{\text{topological}}(v)|``$, computing UUIDv5 identifiers across all nodes using path memoization executes in deterministic time $``O(V + L_{\text{total}}) = O(N)``$, where $`N`$ is total token count. Auxiliary memory is bounded by $`O(1)`$ stack space and $``O(L_{\max})``$ scratch buffer where $``L_{\max} = \max_{v \in \mathcal{V}} |\mathcal{N}_{\text{topological}}(v)|``$, with zero heap allocations. The pipeline involves zero combinatorial search, bypassing NP-hard frontiers (e.g., NP-1 through NP-8) with guaranteed polynomial termination.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: RFC 4122 Standard Conformance & Bitwise Fields

- **Given:** Canonical topological path $``p = \text{Package\_0::Classifier\_Alpha::Port\_1}``$ and fixed namespace identifier $``\text{NS}_{\text{DEAP}}``$.
- **When:** The compiler synthesizes identifier $``U = \text{UUIDv5}(\text{NS}_{\text{DEAP}}, p)``$.
- **Then:** The identifier satisfies Version 5 bits $``(u_6 \land 0\text{xF0}) = 0\text{x50}``$ and Variant bits $``(u_8 \land 0\text{xC0}) = 0\text{x80}``$, matching regex `^[0-9a-f]{8}-[0-9a-f]{4}-5[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}\$`.
- **Diagnostic:** `E0100` emitted on bitwise mask or string formatting violation.

### AC-02: Environmental Invariance & Zero Diff Churn

- **Given:** A schema declaring entity path `Package_0::Subsystem_Alpha::Classifier_Beta` compiled in two environments $``\mathcal{E}_1``$ and $``\mathcal{E}_2``$ differing in OS, architecture, endianness, mount path, thread allocation, and timestamp.
- **When:** The compiler synthesizes UUIDv5 identifiers in both environments.
- **Then:** Emitted bytes and strings satisfy $``U(\mathcal{N}; \mathcal{E}_1) = U(\mathcal{N}; \mathcal{E}_2)``$, ensuring 0-byte diff churn.
- **Diagnostic:** `E0100` emitted if emitted representations differ between environments.

### AC-03: Strict Prohibition of Time-Based & Random UUIDs

- **Given:** An AST pass requiring entity handles or an input model containing entity identifier attributes.
- **When:** Identifier generation or ingestion is evaluated.
- **Then:** Per Directive 1, the compiler rejects all time-based UUIDs (UUIDv1, UUIDv6, UUIDv7) and random UUIDs (UUIDv4), enforcing deterministic RFC 4122 UUIDv5 exclusively to protect Merkle root digests.
- **Diagnostic:** `E0100` emitted on detection of unauthorized UUID variants or time-dependent identifier schemes.

### AC-04: Host Filesystem Path Stripping & Canonical Scope Normalization

- **Given:** An AST node originating from an absolute host filesystem path (e.g., `/opt/workspace/model/Package_0.sysml`).
- **When:** Canonical path $``\mathcal{N}_{\text{topological}}``$ is constructed for UUIDv5 generation.
- **Then:** The compiler strips all filesystem roots, drive letters, and host paths, constructing $``\mathcal{N}_{\text{topological}}``$ strictly from model-relative package qualifiers (`Package_0::Classifier_Alpha`).
- **Diagnostic:** `E0100` emitted if un-sanitized filesystem mount paths or host environment strings contaminate the topological namespace.
