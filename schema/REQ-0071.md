## 1. Normative Statement

The structural compiler SHALL formalize SysML v2 part definitions (`part def`, `PartDefinition`) and part usages (`part`, `PartUsage`) into strongly typed, compositely owned structural elements anchored within the core KerML classifier subtyping lattice $`(\mathcal{K}, \le)`$. `PartDefinition` SHALL specialize KerML `Structure`, which transitively specializes `Class`, `Classifier`, and `Type` ($`\text{PartDef} \le \text{Structure} \le \text{Class}`$). `PartDefinition` represents an identity-bearing classifier strictly disjoint from identity-free value types ($`⟦ \text{PartDef} ⟧ \cap ⟦ \text{DataType} ⟧ = \emptyset`$); any declaration specializing a `DataType` SHALL emit diagnostic `E0200`.

Every `part` usage declaration SHALL lower into a `PartUsage` AST node specializing KerML `Feature` and SysML v2 `ItemUsage`, with the composite ownership flag set strictly to true ($``\text{is\_composite}(u) \equiv \text{true}``$). Composite ownership establishes an existential lifetime dependency: deallocation of containing parent instance $x$ SHALL cause the destruction of all constituent part instances $``y \in \pi_u(x)``$. Every composite part instance $y$ SHALL belong to at most one parent instance ($``|\text{owning\_composite}(y)| \le 1``$); shared composite ownership SHALL emit diagnostic `E0200`.

Omitted multiplicity intervals SHALL default to exact singleton $`\mu(u) = [1, 1]`$. Explicit multiplicity intervals $``[m_{\min}, m_{\max}]``$ MUST satisfy $``0 \le m_{\min} \le m_{\max}``$, or emit diagnostic `E0200`. The sub-assembly containment graph $``G_{\text{contain}} = (\mathcal{D}_{\text{part}}, \mathcal{E}_{\text{contain}})``$ MUST be cycle-free for non-zero lower multiplicities ($``m_{\min} \ge 1``$); circular containment cycles SHALL emit diagnostic `E0203`.

## 2. Formal Invariant

Let $``\mathcal{D}_{\text{part}}``$ denote the set of lowered part definitions and $``\mathcal{U}_{\text{part}}``$ denote composite part usages:

```math
\begin{aligned}
\text{PartDef} &\le \text{Structure} \le \text{Class} \le \text{Classifier} \\
⟦ \text{PartDef} ⟧ &\cap ⟦ \text{DataType} ⟧ = \emptyset
\end{aligned}
```

Existential lifetime dependency and anti-aliasing invariant:

```math
\begin{aligned}
\forall x \in ⟦ D ⟧, \quad \text{Destroy}(x) &\implies \forall y \in \pi_u(x), \quad \text{Destroy}(y) \\
\forall y \in \mathcal{O}_{\text{part}}, \quad &|\text{owning\_composite}(y)| \le 1
\end{aligned}
```

Sub-assembly containment graph acyclicity and RFC 4122 UUIDv5 invariants:

```math
\begin{aligned}
\forall D \in \mathcal{D}_{\text{part}}, \quad &(D, D) \notin \mathcal{E}_{\text{contain}}^+ \quad \text{where} \quad m_{\min} \ge 1 \\
\forall n \in \mathcal{D}_{\text{part}} \cup \mathcal{U}_{\text{part}}, \quad &\Delta_n = \text{UUIDv5}(\text{NS}_{\text{DEAP}}, \text{FQN}(n))
\end{aligned}
```

## 3. Computational Complexity & Algorithmic Bounds

The part definition lowering, typing, and containment validation passes execute strictly within Complexity Class $\mathbf{P}$.

For an input model with $``V = |\mathcal{D}_{\text{part}}|``$ part definition nodes and $``E = |\mathcal{E}_{\text{contain}}|``$ containment edges:
1. Node allocation in AST memory and symbol interning execute in amortized $O(1)$ time per node, totaling $O(V)$ time.
2. Multiplicity validation $``m_{\min} \le m_{\max}``$ executes in $O(1)$ scalar comparisons per usage.
3. Subtyping conformance against the precomputed KerML lattice evaluates in $O(1)$ time per part usage, grounding the tractable fragment of NP-3.
4. Sub-assembly containment acyclicity checking executes in $O(V + E)$ time and $O(V)$ space via Tarjan's strongly connected components algorithm.

Total sequential verification complexity is $O(V + E)$. Parallel package execution scales as $``O((V + E) / N_{\text{max\_workers}} + \log N_{\text{max\_workers}})``$.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Canonical Part Definition and Composite Usage Lowering
- **Given:** A valid schema declaring `PartDef_Alpha` containing composite `part Part_1 : PartDef_Beta [1..*]`.
- **When:** The compiler executes metamodel lowering and structural validation.
- **Then:** Both elements are lowered into contiguous arena storage with `is_composite = true`, default multiplicity preserved, and zero diagnostic emissions.
- **Diagnostic:** `E0200` emitted if typing or composite ownership fails.

### AC-02: Rejection of DataType Inheritance
- **Given:** A part definition declared specializing a primitive value type (`PartDef_Err : DataType_Beta`).
- **When:** Semantic type checking is evaluated against the classifier lattice.
- **Then:** The compiler rejects the declaration at compile time and emits diagnostic error code `E0200`.
- **Diagnostic:** `E0200` emitted for identity-free value type inheritance on part definitions.

### AC-03: Malformed Multiplicity Range Rejection
- **Given:** A part usage declared with inverted multiplicity bounds `part Part_Inv : PartDef_Alpha [5..2]`.
- **When:** Semantic validation checks multiplicity interval bounds.
- **Then:** The compiler rejects the inverted interval and emits diagnostic error code `E0200`.
- **Diagnostic:** `E0200` emitted for invalid multiplicity interval ($``m_{\min} \gt m_{\max}``$).

### AC-04: Sub-Assembly Containment Cycle Detection
- **Given:** A recursive physical containment cycle (`PartDef_Alpha` containing `Part_0 : PartDef_Beta [1..1]`, and `PartDef_Beta` containing `Part_1 : PartDef_Alpha [1..1]`).
- **When:** The topological cycle detection pass traverses the containment graph.
- **Then:** The compiler detects the cyclic dependency with non-zero lower multiplicity and emits diagnostic error code `E0203`.
- **Diagnostic:** `E0203` emitted for circular composite containment.
