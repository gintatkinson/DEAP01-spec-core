## 1. Normative Statement

The compiler shall support multi-file models partitioned across hierarchical directories, deterministically mapping relative filesystem paths to nested package namespaces within the abstract syntax tree (AST). For every source file ingested beneath the workspace schema root directory ($``\mathcal{R}_{\text{schema}}``$), the compiler shall decompose the relative path into directory segments and bind the file's top-level declarations to an enclosing leaf package namespace whose fully qualified name matches the PascalCase-normalized directory hierarchy.

The ingestion engine shall enforce the following normative rules:
1. **Directory Mapping**: Relative path $``p_1 / p_2 / \dots / p_k / \text{name}.\text{ext}``$ shall deterministically map to package namespace $``\text{PascalCase}(p_1) \mathbin{::} \dots \mathbin{::} \text{PascalCase}(p_k)``$. Files at the schema root ($`k = 0`$) shall bind to canonical root package `RootPackage`.
2. **Intermediate Package Synthesis**: If an intermediate package in the prefix chain does not exist in the AST, the compiler shall synthesize an intermediate package container node in the AST. Sibling files sharing directory prefixes shall resolve to identical synthesized package node handles.
3. **Declaration Containment**: All top-level declarations within an ingested file shall be registered as owned members of the resolved leaf package container node.
4. **Package Declaration Reconciliation**: Explicit top-level package declarations must match the directory-derived leaf namespace or represent an explicit child subpackage. Incompatible declarations shall be rejected with diagnostic `E0200`.
5. **Path Normalization & Collision Detection**: Segments shall be normalized to valid PascalCase identifiers. Distinct sibling directories that normalize to identical identifiers or contain invalid characters shall be rejected with diagnostic `E0200`.
6. **Nesting Depth Bounds**: Directory nesting depth shall satisfy $``k \le D_{\max} = 16``$. Paths exceeding $``D_{\max}``$ shall be rejected with diagnostic `E0200`.

## 2. Formal Invariant

Let $`\mathcal{W}`$ denote the workspace rooted at $``\mathcal{R}_{\text{schema}}``$, and $``\mathcal{F}_{\text{comp}}``$ the set of compilation units. Each file $``f \in \mathcal{F}_{\text{comp}}``$ has relative path:

```math
P_{\text{rel}}(f) = p_1 / p_2 / \dots / p_k / \text{name}.\text{ext}, \quad 0 \le k \le D_{\max} = 16
```

The directory-to-namespace mapping function $``\Omega_{\text{ns}}``$ evaluates as:

```math
\Omega_{\text{ns}}(P_{\text{rel}}(f)) = \begin{cases}
\text{SymbolId}(\text{PascalCase}(p_1) \mathbin{\Vert} \text{"::"} \mathbin{\Vert} \dots \mathbin{\Vert} \text{PascalCase}(p_k)), & \text{if } k \ge 1 \\
\text{SymbolId}(\text{"RootPackage"}), & \text{if } k = 0
\end{cases}
```

Package Synthesis Invariant:
For every file $``f \in \mathcal{F}_{\text{comp}}``$, the AST package set $`\text{Packages}(\mathcal{A})`$ contains all prefix packages:

```math
\forall i \in \{1, \dots, k\}, \quad \exists! P_i \in \text{Packages}(\mathcal{A}) \quad \text{such that} \quad \text{FQN}(P_i) = \bigodot_{j=1}^i \text{PascalCase}(p_j)
```

UUIDv5 Anchor and Containment Invariants:
Every package node $`P`$ and top-level AST declaration $`e`$ satisfy:

```math
\begin{aligned}
\Delta_{\text{uuid}}(P) &= \text{UUIDv5}(\text{NS}_{\text{DEAP}}, \text{FQN}(P)) \\
\forall e \in \text{TopLevelDeclarations}(f), &\quad \text{Owner}(e) = \Omega_{\text{ns}}(P_{\text{rel}}(f))
\end{aligned}
```

Diagnostic Code Binding Invariant:
Structural and semantic violations trigger diagnostics per REQ-0191:

```math
\begin{aligned}
k \gt D_{\max} &\implies \text{Diagnostic}(f, \text{E0200}, \text{NestingDepthExceeded}) \in \mathcal{D}_{\text{sink}} \\
\text{Conflict}(\text{DeclaredPkg}(f), \Omega_{\text{ns}}(P_{\text{rel}}(f))) &\implies \text{Diagnostic}(f, \text{E0200}, \text{NamespaceMismatch}) \in \mathcal{D}_{\text{sink}} \\
(p_a \ne p_b \wedge \text{PascalCase}(p_a) = \text{PascalCase}(p_b)) &\implies \text{Diagnostic}(p_b, \text{E0200}, \text{NamespaceCollision}) \in \mathcal{D}_{\text{sink}} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{Code}(D_{\text{term}}) = \text{E0199}
\end{aligned}
```

## 3. Computational Complexity & Algorithmic Bounds

Multi-file module ingestion operates strictly within Complexity Class $`\mathbf{P}`$. For $``M = |\mathcal{F}_{\text{comp}}|``$ files with aggregate path byte length $``L = \sum_{f} |P_{\text{rel}}(f)|``$:
1. **Path Normalization**: Decomposing and PascalCase-normalizing segments runs in deterministic linear time $`O(L)`$ across the workspace.
2. **Package Lookup & Synthesis**: Scoped lookup and arena allocation execute in $`O(1)`$ amortized time per level via interned `SymbolId` handles, bounded by $``O(D_{\max}) = O(1)``$ per file.
3. **Aggregate Complexity**: Constructing the namespace forest executes in $`O(L + M) \subseteq O(V + E)`$ time and requires $`O(V + E)`$ space for AST nodes and containment edges. The pass requires zero combinatorial backtracking, operating strictly below NP frontiers (e.g., NP-3 subtyping lattice resolution).

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Canonical Directory-to-Namespace Hierarchy Resolution

- **Given:** A compilation unit at relative path `schema/package_0/module_alpha/unit_beta/model_alpha.sysml`.
- **When:** The compiler executes path normalization and directory-to-namespace mapping.
- **Then:** The file binds deterministically to leaf package `Package0::ModuleAlpha::UnitBeta`, and all top-level AST declarations are registered as owned members of that package node.
- **Diagnostic:** `E0200` emitted on namespace resolution failure or invalid identifier mapping.

### AC-02: Idempotent Intermediate Package Synthesis

- **Given:** Sibling source files sharing common directory prefixes (`schema/package_0/module_alpha/unit_0/part_a.sysml` and `schema/package_0/module_alpha/unit_1/part_b.sysml`).
- **When:** The compiler constructs package hierarchy nodes in the AST.
- **Then:** Intermediate package container nodes for `Package0` and `Package0::ModuleAlpha` are synthesized exactly once, reused across sibling files, and assigned deterministic RFC 4122 UUIDv5 identifiers.
- **Diagnostic:** `E0200` emitted if duplicate package handles are allocated or parent-child linkages diverge.

### AC-03: Explicit Package Declaration Reconciliation and Conflict Rejection

- **Given:** A source file at `schema/package_0/module_alpha/unit_0/part_a.sysml` containing explicit declaration `package ConflictingRoot::ModuleBeta;`.
- **When:** Semantic analysis compares the declared package with directory-derived namespace `Package0::ModuleAlpha::Unit0`.
- **Then:** The compiler rejects the conflicting declaration, emits diagnostic `E0200`, and executes synchronization token error recovery to resume parsing at the next file boundary.
- **Diagnostic:** `E0200` emitted on namespace path discrepancy.

### AC-04: Segment Normalization, Collision Detection, and Depth Bounds

- **Given:** Sibling directories normalizing to identical PascalCase identifiers (e.g., `module_alpha` and `module-alpha`), or a path with nesting depth $`k = 17`$ exceeding $``D_{\max} = 16``$.
- **When:** Directory segment normalization and depth validation execute.
- **Then:** The compiler rejects the offending units, emits diagnostic `E0200` with the source coordinate, and maintains stable compiler arena state.
- **Diagnostic:** `E0200` emitted on segment collision or nesting depth overflow ($`k \gt 16`$).
