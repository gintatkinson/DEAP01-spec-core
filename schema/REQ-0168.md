## 2. Formal Invariant

Let $\mathcal{U}(F)$ denote projected stories for feature $F$. Narrative validation, MoSCoW prioritization, and diagnostic rules satisfy:

```math
\begin{aligned}
\forall u\in\mathcal{U}(F),& u=\langle\text{id}_u,p_u,i_u,b_u,\rho_u,\Delta_u\rangle\land p_u\in\mathcal{A}_{\text{actors}}\land i_u\in\mathcal{C}_{\text{actions}}(F) \\
\forall u\in\mathcal{U}(F),& \text{metric}(b_u)\ge 0\land\text{rationale}(b_u)\ne\epsilon\land\rho_u\in\mathcal{P}_{\text{MoSCoW}} \\
\mathcal{P}_{\text{MoSCoW}}&=\{\text{MustHave},\text{ShouldHave},\text{CouldHave},\text{WontHave}\} \\
(p_u\notin\mathcal{A}_{\text{actors}}\lor i_u\notin\mathcal{C}_{\text{actions}}(F))&\implies\text{Diagnostic}(u,\text{E0300})\in\mathcal{D}_{\text{sink}}\land u\gets\bot_{\text{story}} \\
(\rho_u\notin\mathcal{P}_{\text{MoSCoW}}\lor\text{metric}(b_u)\lt 0)&\implies\text{Diagnostic}(u,\text{E0310})\in\mathcal{D}_{\text{sink}}\land u\gets\bot_{\text{story}} \\
|\mathcal{D}_{\text{sink}}|\ge C_{\text{max\_errors}}&\implies\text{Diagnostic}(\text{E0199})\in\mathcal{D}_{\text{sink}}\land\text{HaltPipeline}() \\
\forall u\in\mathcal{U}(F),& \Delta_u=\text{UUIDv5}(\text{OID}_{\text{DEAP}},\text{FQN}(F)\mathbin{\Vert}\text{"::UserStory::"}\mathbin{\Vert}\text{name}_u)
\end{aligned}
```

## 3. Computational Complexity & Algorithmic Bounds

- **Complexity Class:** Class $\mathbf{P}$ (Deterministic Polynomial Time).
- **Asymptotic Bound:** $O(|U|)$ story cataloging ($|U| = \sum |\mathcal{U}(F)|$). Ingestion and checks take $O(1)$ time via symbol interning. 4-tier MoSCoW distribution sort takes $O(|U|)$ time. Arena storage: $O(|U|)$. Work-stealing: $``O(|U| / N_{\text{max\_workers}} + \log N_{\text{max\_workers}})``$.
- **Tractable Subclass and Frontier:** N/A (Deterministic P). Linear story cataloging avoids NP-2 bin packing (REQ-0147) and NP-8 invariant proving (REQ-0197).

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Canonical User Story Lowering
- **Given:** Feature `Feature_0` with `UserStory_Alpha` (`Persona_0`, `Action_0`, value $100.0$, `MustHave`).
- **When:** Lowering User Story specifications.
- **Then:** Formalizes narrative, assigns MoSCoW rank 1, and passes.
- **Diagnostic:** Diagnostic sink remains empty.

### AC-02: Deterministic MoSCoW Ordering
- **Given:** Stories across `MustHave`, `ShouldHave`, `CouldHave`, `WontHave` in arbitrary order.
- **When:** Sorting catalog sequence $``\prec_{\text{proj}}``$.
- **Then:** Orders stories by MoSCoW rank with value tie-breaking.
- **Diagnostic:** Diagnostic sink remains empty.

### AC-03: Invalid Priority Rejection
- **Given:** Story `UserStory_Beta` with invalid priority `MaybeHave` or negative metric $-5.0$.
- **When:** Validating priority and business value.
- **Then:** Fails closed, binds sentinel $``\bot_{\text{story}}``$, emitting `E0310`.
- **Diagnostic:** `E0310` (PriorityClassificationViolation).

### AC-04: Missing Persona and Delimiter Recovery
- **Given:** Story missing persona, delimiter `;`, and valid `UserStory_Beta`.
- **When:** Delimiter recovery resynchronizes across tokens.
- **Then:** Emits `E0300`, binds $``\bot_{\text{story}}``$, parses `UserStory_Beta`, halting at $``C_{\text{max\_errors}}``$ with `E0199`.
- **Diagnostic:** `E0300`, `E0199`.
