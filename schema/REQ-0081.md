## 1. Normative Statement

The state machine engine SHALL formalize SysML v2 state lifecycle hooks (`entry`, `do`, `exit`) as temporal occurrences bound to state activation, residence, and deactivation intervals. `StateDefinition` and `StateUsage` specialize KerML `Behavior`; `EntryActionUsage`, `DoActionUsage`, and `ExitActionUsage` specialize KerML `ActionUsage`.

The lowering engine MUST enforce the following lifecycle invariants:
1. **Multiplicity Bounding**: States declare at most one hook per category ($[0..1]$ multiplicity). Duplicate un-sequenced hooks emit diagnostic `E0200`.
2. **Behavioral Typing**: Each hook $A$ MUST specialize KerML `Behavior` ($`\tau(A) \le \text{Behavior}`$). Non-behavioral types emit `E0201`.
3. **Temporal Ordering**: Residence interval $``[t_{\text{entry}}(S), t_{\text{exit}}(S)]``$ must be non-inverted ($``t_{\text{entry}} \le t_{\text{exit}}``$; inverted emits `E0200`). Lifecycle phases execute sequentially:
 - *Entry ($``A_{\text{entry}}``$)*: Atomic, run-to-completion step at $``t_{\text{entry}}``$ ($\Delta t = 0$). External events are queued without preemption.
 - *Do ($``A_{\text{do}}``$)*: Initiated post-entry ($``t_{\text{start}} \ge t_{\text{end}}(A_{\text{entry}})``$). Preemptible; autonomous completion posts $``\varepsilon_{\text{complete}}(S)``$. Outgoing transition firing aborts $``A_{\text{do}}``$ immediately, terminating sub-occurrences before exit invocation.
 - *Exit ($``A_{\text{exit}}``$)*: Atomic, run-to-completion step upon deactivation after do completion or abort ($\Delta t = 0$), preceding transition effects.
4. **Ladder Dispatch**: Transitions across states with Least Common Ancestor $\text{LCA}$ execute an ascending exit ladder to LCA, transition effects, and a descending entry ladder from LCA to target. Internal transitions execute effects in-place without invoking hooks or aborting $``A_{\text{do}}``$.

## 2. Formal Invariant

State lifecycle action classification, multiplicity bounding, and temporal ordering:

```math
\begin{aligned}
\text{HookKind} &\in \{ \text{EntryHook}, \text{DoHook}, \text{ExitHook} \} \\
\forall S \in \mathcal{S}_{\text{state}}, \quad &|\text{entry}(S)| \le 1 \;\wedge\; |\text{do}(S)| \le 1 \;\wedge\; |\text{exit}(S)| \le 1 \\
\forall A \in \mathcal{A}_{\text{hook}}, \quad &\tau(A) \le \text{Behavior} \;\wedge\; t_{\text{start}}(A) \le t_{\text{end}}(A) \\
t_{\text{entry}}(S) \le t_{\text{start}}(A_{\text{entry}}) &\le t_{\text{end}}(A_{\text{entry}}) \le t_{\text{start}}(A_{\text{do}}) \le t_{\text{end}}(A_{\text{do}}) \le t_{\text{start}}(A_{\text{exit}}) \le t_{\text{end}}(A_{\text{exit}}) \le t_{\text{exit}}(S) \\
\text{Preemptible}(A) &= (\text{kind}_A = \text{DoHook}) \\
\text{fire}(T, t_{\text{fire}}) \wedge \sigma(A_{\text{do}}) = \text{Executing} &\implies \sigma(A_{\text{do}}) \gets \text{Aborted} \;\wedge\; t_{\text{end}}(A_{\text{do}}) = t_{\text{fire}} \;\wedge\; t_{\text{start}}(A_{\text{exit}}) \ge t_{\text{fire}} \\
\forall n \in \mathcal{S}_{\text{state}} \cup \mathcal{A}_{\text{hook}}, \quad &\Delta_n = \text{UUIDv5}(\text{NS}_{\text{DEAP}}, \text{FQN}(n))
\end{aligned}
```

| $``\mathcal{A}_{\text{hook}}``$ | Lowered state lifecycle action hook nodes |
| $\text{entry}(S), \text{do}(S), \text{exit}(S)$ | Hook selector projections for state $S$ |

## 3. Computational Complexity & Algorithmic Bounds

State lifecycle lowering, verification, and dispatch execute in Complexity Class $\mathbf{P}$.

- **Phase Dispatch**: Deterministic $O(1)$ time per lifecycle phase transition.
- **Ladder Traversal**: $O(d) = O(1)$ for nesting depth $d \le 32$.
- **Model Lowering & Validation**: $``O(V_S + V_A)``$ for $``V_S = |\mathcal{S}_{\text{state}}|``$ and $``V_A = |\mathcal{A}_{\text{hook}}|``$.

Grounds the tractable polynomial fragments of NP-1 (linear temporal intervals without backtracking) and NP-5 ($O(1)$ local dispatch without state-space product exploration). Parallel work-stealing lowering scales as $``O((V_S + V_A) / N_{\text{max\_workers}} + \log N_{\text{max\_workers}})``$.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Canonical State Lifecycle Lowering & Multiplicity
- **Given:** Valid `State_A` declaring `entry Action_Entry`, `do Action_Do`, and `exit Action_Exit`.
- **When:** Lowering constructs lifecycle AST nodes.
- **Then:** All three hooks lower into arena storage with valid handles and zero diagnostics.
- **Diagnostic:** Diagnostic sink remains empty.

### AC-02: Duplicate Lifecycle Hook Rejection
- **Given:** `State_A` declaring duplicate un-sequenced `entry` action hooks.
- **When:** Multiplicity validation executes.
- **Then:** Lowering rejects duplicate hook with sentinel $``\bot_{\text{action}}``$ and emits `E0200`.
- **Diagnostic:** `E0200` on duplicate lifecycle hook.

### AC-03: Non-Behavioral Classifier Typing Rejection
- **Given:** Data type `DataType_Value` and `State_A` declaring `entry : DataType_Value`.
- **When:** Classifier conformance validation evaluates hook typing.
- **Then:** Lowering rejects binding with sentinel $``\bot_{\text{action}}``$ and emits `E0201`.
- **Diagnostic:** `E0201` on invalid action classifier typing.

### AC-04: Atomic Run-to-Completion and Do Preemption
- **Given:** Active `State_A` executing `Action_Do` after atomic `Action_Entry` ($\Delta t = 0$).
- **When:** Outgoing transition $``T : \text{State\_A} \to \text{State\_B}``$ fires at $``t_{\text{fire}}``$.
- **Then:** `Action_Do` aborts immediately ($``t_{\text{end}} = t_{\text{fire}}``$), and `Action_Exit` executes atomically before transition effects.
- **Diagnostic:** Diagnostic sink remains empty.
