## 1. Normative Statement

The compiler front-end, lexical analyzer, parser, and core abstract syntax tree (AST) engine shall utilize zero-copy memory management via contiguous bump allocation arenas for all parsed AST nodes, token streams, syntax trees, and intermediate representation graphs. Lexical tokens and string identifiers representing slices of source text shall directly borrow contiguous byte slice references from read-only memory-mapped source file buffers without intermediate heap string allocations or dynamic buffer cloning.

Bump arenas must allocate AST nodes sequentially along contiguous memory segments, advancing a monotonic bump pointer with strict 64-bit data alignment boundaries (8-byte alignment). Arena lifecycle management must reset or deallocate entire arena chunks in a single bulk operation upon completion of compilation units or compilation phases, eliminating individual node deallocation overhead, per-node allocator metadata headers, and heap fragmentation.

Memory allocation during lexical and parsing passes shall strictly enforce zero individual heap allocations for AST nodes and token strings. Copying string bytes from the source buffer into the deduplicated global symbol interner pool for scalar symbol identifier tokens during the initial lexical pass constitutes the sole permitted exception to the zero-copy invariant, as specified in REQ-0036. If an arena segment exhausts pre-allocated capacity, the arena manager shall allocate a new contiguous chunk without moving, reallocating, or invalidating previously allocated node references. If an allocation exceeds segment capacity without memory availability, or an out-of-bounds slice is accessed, or an unauthorized heap allocation occurs during parsing, the compiler shall halt execution immediately and emit diagnostic error code `E0100`.

## 2. Formal Invariant

Let $``\mathcal{B}_{\text{file}} \in \{0, 1\}^L``$ represent a contiguous read-only memory-mapped byte buffer of length $``L = |\mathcal{B}_{\text{file}}|``$. An AST token slice $`T`$ is defined as a borrowed contiguous byte slice reference over offset $`s`$ and length $`l`$:

```math
T = \text{Slice}(\mathcal{B}_{\text{file}}, s, l) = \mathcal{B}_{\text{file}}[s \dots s+l-1], \quad \text{where } 0 \le s \le s+l \le L
```

Let $``\mathcal{A}_{\text{arena}}``$ be a contiguous arena segment of capacity $`C \in \mathbb{N}`$ at base address $``\text{Base}(\mathcal{A}_{\text{arena}})``$, with monotonic bump pointer offset $``\text{ArenaOffset}_k``$ after allocating $`k`$ nodes. The allocation of $``\text{Node}_k``$ with byte size $``\text{sizeof}(\text{Node}_k)``$ and alignment constraint $`\text{Alignment} = 8`$ satisfies:

```math
\text{ArenaOffset}_{k+1} = \text{Align}(\text{ArenaOffset}_k + \text{sizeof}(\text{Node}_k), \text{Alignment})
```

where the alignment function is defined as:

```math
\text{Align}(x, a) = \left\lceil \frac{x}{a} \right\rceil \cdot a, \quad a \in \{2^p \mid p \in \mathbb{N}\}
```

Monotonic Pointer Progression and Reference Stability Invariants:

```math
\begin{aligned}
\forall k \ge 0, \quad 0 &\le \text{ArenaOffset}_k \le \text{ArenaOffset}_{k+1} \le C \\
\forall t_1, t_2 \in \tau_{\text{arena}}, \quad \text{Addr}(r_k, t_1) &= \text{Addr}(r_k, t_2)
\end{aligned}
```

Let $`\text{HeapAllocs}(\text{Pass})`$ represent dynamic individual heap allocations during primary parsing pass $``\text{ParsePass}(\mathcal{B}_{\text{file}})``$, excluding the scalar symbol interner pool $``\mathcal{I}_{\text{symbols}}``$ per REQ-0036. The Zero Heap Allocation and Bulk Deallocation Invariants satisfy:

```math
\begin{aligned}
\text{HeapAllocs}(\text{ParsePass}(\mathcal{B}_{\text{file}})) &= 0 \\
\text{Reset}(\mathcal{A}_{\text{arena}}) \implies \text{ArenaOffset}_{\text{reset}} &= 0
\end{aligned}
```

## 3. Computational Complexity & Algorithmic Bounds

Arena memory operations execute within Complexity Class $`\mathbf{P}`$. Individual node allocation executes in strict $`O(1)`$ worst-case constant time via integer addition, alignment masking, and pointer comparison against capacity $`C`$. Token byte slice extraction executes in $`O(1)`$ constant time with zero string cloning. Bulk arena chunk deallocation and pointer reset execute in $`O(1)`$ constant time, independent of total allocated AST node count $``N = |\text{Nodes}(\mathcal{A}_{\text{arena}})|``$. Total front-end memory consumption is strictly bounded by $`O(N)`$ linear space proportional to AST node count and alignment padding, eliminating per-object dynamic heap metadata overhead. Arena allocation requires no combinatorial search, operating outside NP-complete frontiers (NP-1 through NP-8) and ensuring deterministic constant-time execution.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Zero-Copy Borrowed Token Byte Slices
- **Given:** A memory-mapped source file buffer $``\mathcal{B}_{\text{file}}``$ of length $`L`$ containing abstract MBSE declarations (`Package_0`, `Classifier_Alpha`, `Port_1`, `Flow_A`, `param_x : Real`).
- **When:** The lexical scanner and parser extract token byte slices for identifiers and keywords.
- **Then:** Every token slice $``T = \text{Slice}(\mathcal{B}_{\text{file}}, s, l)``$ directly references buffer interval $``[\text{Base}(\mathcal{B}_{\text{file}}) + s, \text{Base}(\mathcal{B}_{\text{file}}) + s + l)``$ with $`0 \le s \le s+l \le L`$ without dynamic heap string allocation.
- **Diagnostic:** `E0100` emitted if slice coordinates violate buffer bounds or heap string cloning is detected.

### AC-02: Constant-Time Monotonic Bump Allocation & Alignment
- **Given:** An active bump arena segment $``\mathcal{A}_{\text{arena}}``$ with capacity $`C`$ and current offset $``\text{ArenaOffset}_k``$.
- **When:** The compiler allocates successive AST nodes for structural elements (`Classifier_Alpha`, `Port_1`).
- **Then:** The allocator advances $``\text{ArenaOffset}_{k+1} = \text{Align}(\text{ArenaOffset}_k + \text{sizeof}(\text{Node}_k), 8)``$ in strict $`O(1)`$ time, all allocated addresses satisfy $``\text{Addr}(r_k) \equiv 0 \pmod 8``$, and reference addresses remain immutable throughout $``\tau_{\text{arena}}``$.
- **Diagnostic:** `E0100` emitted if alignment arithmetic fails or an allocation causes segment overflow without chunk chaining.

### AC-03: Zero Individual Heap Allocation Enforcement
- **Given:** Front-end lexical analysis and AST construction executing on input schema buffer $``\mathcal{B}_{\text{file}}``$.
- **When:** A memory profiling test harness intercepts dynamic heap allocator calls during $``\text{ParsePass}(\mathcal{B}_{\text{file}})``$.
- **Then:** The measured individual heap allocation count satisfies $``\text{HeapAllocs}(\text{ParsePass}(\mathcal{B}_{\text{file}})) = 0``$, with the sole permitted exception being string byte copies into the global deduplicated symbol interner pool per REQ-0036.
- **Diagnostic:** `E0100` emitted if an unauthorized individual node or token heap allocation occurs during parsing.

### AC-04: Bulk Arena Deallocation & Lifetime Reset
- **Given:** A bump arena segment $``\mathcal{A}_{\text{arena}}``$ holding $`N`$ allocated AST nodes following completion of a compilation unit pass.
- **When:** The compiler front-end releases AST memory resources via $``\text{Reset}(\mathcal{A}_{\text{arena}})``$.
- **Then:** The entire arena chunk is recycled or deallocated in a single bulk operation with $``\text{ArenaOffset}_{\text{reset}} = 0``$ in $`O(1)`$ constant time, avoiding per-node destructor traversal or individual free list maintenance.
- **Diagnostic:** `E0100` emitted if arena pointer reset fails or individual node deallocations are invoked.
