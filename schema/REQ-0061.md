## 1. Normative Statement

The compiler metamodel lowering engine and semantic type checker shall formalize KerML feature subsetting (`Subsetting`, denoted by operator `:>`) as value-set inclusion within the subtyping meet-semilattice. When a feature subsetting relationship $``f_{\text{sub}} :> f_{\text{sup}}``$ is declared between subsetting feature $``f_{\text{sub}}``$ and subsetted feature $``f_{\text{sup}}``$, the compiler shall enforce that for every semantic instance $`x`$ in the domain of the owning classifier, the value set projected by $``f_{\text{sub}}(x)``$ is a subset of the value set projected by $``f_{\text{sup}}(x)``$ satisfying $``\pi_{f_{\text{sub}}}(x) \subseteq \pi_{f_{\text{sup}}}(x)``$.

The lowering pass shall verify the following structural invariants for every subsetting declaration:
1. **Co-variant Type Specialization**: The declared or inferred type $``\tau(f_{\text{sub}})``$ shall specialize or equal $``\tau(f_{\text{sup}})``$ in the subtyping partial order ($``\tau(f_{\text{sub}}) \le \tau(f_{\text{sup}})``$). Incompatible or contravariant types shall be strictly rejected with diagnostic code `E0200`.
2. **Multiplicity Interval Narrowing**: Multiplicity intervals $``\mu(f) = [m_{\min}, m_{\max}]``$ must preserve value-set inclusion: $``\mu(f_{\text{sub}}).m_{\max} \le \mu(f_{\text{sup}}).m_{\max}``$ and $``\mu(f_{\text{sub}}).m_{\min} \le \mu(f_{\text{sup}}).m_{\max}``$. Widened upper bounds or infeasible lower bounds shall be rejected with diagnostic code `E0200`.
3. **Domain Specialization**: The featuring classifier context $``\text{owner}(f_{\text{sub}})``$ shall specialize or equal $``\text{owner}(f_{\text{sup}})``$ ($``\text{owner}(f_{\text{sub}}) \le \text{owner}(f_{\text{sup}})``$). Subsetting across disjoint classifiers without an inheritance path shall be rejected with diagnostic code `E0200`.
4. **Directional Flow Polarity**: Directed features (ports and parameters with directionality $`\delta \in \{ \text{In}, \text{Out}, \text{InOut} \}`$) must preserve identical flow directionality ($``\delta(f_{\text{sub}}) = \delta(f_{\text{sup}})``$). Conflicting directions shall be rejected with diagnostic code `E0200`.
5. **Acyclicity Enforcement**: Circular subsetting chains among features ($``f_1 :> f_2 :> \dots :> f_1``$) shall be prohibited and detected at compile time via topological cycle detection, emitting diagnostic error code `E0203`.

Lowered subsetting relationship AST nodes shall bind deterministic RFC 4122 UUIDv5 identifiers derived from the fully qualified paths of $``f_{\text{sub}}``$ and $``f_{\text{sup}}``$. On validation failure, the compiler shall record diagnostic `E0200` or `E0203`, assign error sentinel type $``\bot_{\text{type}}``$ to prevent cascade, and recover token synchronization without panicking.

## 2. Formal Invariant

Let $`\mathcal{F}`$ denote the set of allocated feature nodes and $``\mathcal{R}_{\text{subset}} \subset \mathcal{F} \times \mathcal{F}``$ denote the subsetting relation. Each feature node $`f \in \mathcal{F}`$ is defined as a tuple:

```math
f = \langle \text{id}_f, \text{name}_f, \text{owner}_f, \tau(f), \mu(f), \delta(f) \rangle
```

where $`\tau(f) \in \mathcal{T}`$ is the classifier type, $``\mu(f) = [m_{\min}(f), m_{\max}(f)]``$ is the multiplicity interval, and $`\delta(f) \in \{ \text{In}, \text{Out}, \text{InOut}, \text{None} \}`$ is the flow directionality.

Value-Set Containment and Poset Invariants:

```math
\begin{aligned}
\forall (f_{\text{sub}}, f_{\text{sup}}) \in \mathcal{R}_{\text{subset}}, \quad &\forall x \in ⟦ \text{owner}(f_{\text{sub}}) ⟧ : \pi_{f_{\text{sub}}}(x) \subseteq \pi_{f_{\text{sup}}}(x) \\
\forall (f_{\text{sub}}, f_{\text{sup}}) \in \mathcal{R}_{\text{subset}}, \quad &\tau(f_{\text{sub}}) \le \tau(f_{\text{sup}}) \wedge \text{owner}(f_{\text{sub}}) \le \text{owner}(f_{\text{sup}}) \\
\forall (f_{\text{sub}}, f_{\text{sup}}) \in \mathcal{R}_{\text{subset}}, \quad &\mu(f_{\text{sub}}).m_{\max} \le \mu(f_{\text{sup}}).m_{\max} \wedge \mu(f_{\text{sub}}).m_{\min} \le \mu(f_{\text{sup}}).m_{\max} \\
\forall (f_{\text{sub}}, f_{\text{sup}}) \in \mathcal{R}_{\text{subset}}, \quad &\delta(f_{\text{sup}}) \ne \text{None} \implies \delta(f_{\text{sub}}) = \delta(f_{\text{sup}})
\end{aligned}
```

Subsetting Graph Strict Acyclicity:

```math
\forall f \in \mathcal{F}, \quad (f, f) \notin \mathcal{R}_{\text{subset}}^+
```

Deterministic RFC 4122 UUIDv5 Relationship Anchor:

```math
\forall r = (f_{\text{sub}}, f_{\text{sup}}) \in \mathcal{R}_{\text{subset}}, \quad \Delta_{\text{rel}}(r) = \text{UUIDv5}(\text{NS}_{\text{DEAP}}, \text{FQN}(f_{\text{sub}}) \mathbin{\Vert} \text{"::subset::"} \mathbin{\Vert} \text{FQN}(f_{\text{sup}}))
```

## 3. Computational Complexity & Algorithmic Bounds

Feature subsetting lowering and subtyping verification execute within Complexity Class $`\mathbf{P}`$. While general subtyping satisfiability in arbitrary posets is NP-complete (**NP-3**), restricting classifier inheritance to monotonic meet-semilattices $`(\mathcal{T}, \le, \wedge)`$ with deterministic C3 linearization reduces subtyping reachability and subsetting validation to deterministic $`O(V + E)`$ time without backtracking, where $`V = |\mathcal{F}|`$ features and $``E = |\mathcal{R}_{\text{subset}}|``$ edges. Cycle detection via Tarjan strongly connected components and scalar multiplicity checks execute in $`O(V + E)`$ time and $`O(V + E)`$ auxiliary memory.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Canonical Feature Subsetting Lowering

- **Given:** Classifier `Classifier_Alpha` declaring feature `Feature_Sup : Classifier_Alpha [0..10]`, and specializing classifier `Classifier_Beta :> Classifier_Alpha` declaring `Feature_Sub :> Feature_Sup : Classifier_Beta [1..5]`.
- **When:** The compiler executes the metamodel lowering pass.
- **Then:** The subsetting relationship is verified with co-variant typing $``\tau(\text{Feature\_Sub}) \le \tau(\text{Feature\_Sup})``$ and valid multiplicity narrowing, synthesizing an AST relationship edge with deterministic UUIDv5 anchor and zero diagnostics.
- **Diagnostic:** None.

### AC-02: Co-variant Subtyping Incompatibility Rejection

- **Given:** Supertype feature `Feature_Sup : Classifier_Alpha` and subsetting declaration `Feature_Sub :> Feature_Sup : Classifier_Gamma`, where `Classifier_Gamma` does not specialize `Classifier_Alpha`.
- **When:** The compiler performs subtyping verification on the subsetting declaration.
- **Then:** The compiler rejects the incompatible type relationship, binds error sentinel $``\bot_{\text{type}}``$ to prevent downstream failure cascade, and emits diagnostic code `E0200`.
- **Diagnostic:** `E0200`.

### AC-03: Multiplicity Bound Narrowing and Feasibility Violation

- **Given:** Feature `Feature_Sup` with multiplicity `[0..5]` and subsetting declarations specifying invalid intervals `Feature_Sub1 :> Feature_Sup [0..8]` (widened upper bound) or `Feature_Sub2 :> Feature_Sup [6..8]` (infeasible lower bound).
- **When:** The compiler evaluates multiplicity interval constraints during lowering.
- **Then:** The compiler rejects each invalid interval declaration and emits diagnostic code `E0200`.
- **Diagnostic:** `E0200`.

### AC-04: Domain Specialization and Directional Polarity Enforcement

- **Given:** Feature `Feature_Sup` in `Classifier_Alpha` and directed port `Port_1 : in Classifier_Alpha`.
- **When:** The compiler validates cross-classifier subsetting `Feature_Sub :> Feature_Sup` from disjoint `Classifier_Gamma`, or inverted directionality `Port_2 :> Port_1 : out Classifier_Alpha`.
- **Then:** The compiler rejects the domain mismatch and conflicting flow directionality, emitting diagnostic code `E0200`.
- **Diagnostic:** `E0200`.
