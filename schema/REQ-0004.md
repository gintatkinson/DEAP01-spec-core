## 1. Normative Statement

The compiler platform shall operate in a self-contained, sovereign repository architecture wherein all filesystem operations, cross-module schema imports, configuration lookups, and generated artifact paths resolve dynamically using canonical workspace-relative paths derived from an authenticated repository root.

The compiler must discover workspace root $`\mathcal{R}`$ dynamically at runtime by searching parent directories upward from the current working directory for the nearest sovereign repository marker, or by accepting an explicit root path supplied via command-line arguments. All path resolution operations shall strictly enforce boundary containment: every resolved path must reside within the directory subtree rooted at $`\mathcal{R}`$.

The compiler shall strictly reject any path reference attempting directory traversal outside $`\mathcal{R}`$ (including parent traversal sequences `..`, absolute filesystem paths, drive letter prefixes, user home expansions, external symbolic links, and network URIs). Upon detecting an out-of-bounds or invalid path, the compiler shall halt execution and emit diagnostic error code `E0100`.

The compiler shall guarantee bitwise determinism and zero environment leakage: all synthesized intermediate representations, ASTs, and output artifacts must be bit-for-bit identical regardless of the absolute mount path of $`\mathcal{R}`$ on disk. Absolute machine paths, usernames, hostnames, or build-environment paths are strictly forbidden from appearing in generated outputs.

## 2. Formal Invariant

Let $`\mathcal{R}`$ denote the sovereign repository root path determined dynamically at runtime. Let $``\mathcal{P}_{\text{rel}}``$ denote the set of normalized relative paths defined over $`\mathcal{R}`$, and let $`\bowtie`$ denote canonical path concatenation. Every resolved filesystem path $`P`$ satisfies:

```math
P = \mathcal{R} \bowtie p_{\text{rel}}, \quad \text{where } p_{\text{rel}} \in \mathcal{P}_{\text{rel}}
```

Boundary Containment Invariant: For every accessed or resolved path $`P`$, the canonicalized path $`\text{Canonicalize}(P)`$ must satisfy strict prefix containment within the repository subtree:

```math
\text{PrefixOf}(\mathcal{R}, \text{Canonicalize}(P)) \equiv \text{true} \quad \wedge \quad \text{Canonicalize}(P) \in \text{Subtree}(\mathcal{R})
```

Prohibited Path Rejection: Let $``\mathcal{P}_{\text{invalid}}``$ denote the set of path strings attempting directory traversal beyond $`\mathcal{R}`$, specifying absolute machine roots, external symlink targets, or referencing external network protocols. Any attempted resolution of $``p \in \mathcal{P}_{\text{invalid}}``$ fails deterministically:

```math
\forall p \in \mathcal{P}_{\text{invalid}}, \quad \text{Resolve}(p, \mathcal{R}) = \bot \implies \text{Diagnostic}(p) = \text{E0100}
```

Bitwise Determinism Invariance Across Distinct Workspace Mount Locations: Let $`\mathcal{I}`$ denote an identical set of input schema specifications, and let $``\mathcal{R}_A``$ and $``\mathcal{R}_B``$ denote two distinct workspace mount root paths on disk ($``\mathcal{R}_A \neq \mathcal{R}_B``$). Let $`\mathcal{C}(\mathcal{I}, \mathcal{R})`$ denote the complete set of compiled output artifacts generated by compiler execution $`\mathcal{C}`$ within workspace root $`\mathcal{R}`$. The resulting cryptographic digests satisfy:

```math
\text{SHA256}(\mathcal{C}(\mathcal{I}, \mathcal{R}_A)) \equiv \text{SHA256}(\mathcal{C}(\mathcal{I}, \mathcal{R}_B))
```

Absolute Path Non-Leakage Invariant: For every compiled output artifact $`a \in \text{Artifacts}(\mathcal{C}(\mathcal{I}, \mathcal{R}))`$ and for every absolute path string representation $`\text{PathString}(\mathcal{R})`$ of repository root $`\mathcal{R}`$:

```math
\forall a \in \text{Artifacts}(\mathcal{C}(\mathcal{I}, \mathcal{R})), \quad \text{ContainsSubstring}(a, \text{PathString}(\mathcal{R})) \equiv \text{false}
```

Relative Path Normalization Idempotence: For all $``p_{\text{rel}} \in \mathcal{P}_{\text{rel}}``$, the normalization operator satisfies:

```math
\text{Normalize}(\text{Normalize}(p_{\text{rel}})) = \text{Normalize}(p_{\text{rel}})
```

## 3. Computational Complexity & Algorithmic Bounds

Dynamic path resolution and validation execute in Complexity Class $`\mathbf{P}`$. Upward workspace root discovery executes in $`O(D)`$ time for directory nesting depth $``D \le D_{\max} = 64``$. Path normalization, component parsing, and prefix containment verification execute in deterministic linear time $`O(|P|)`$ with respect to path character length $`|P|`$, performing zero recursive filesystem traversal. Cryptographic digest verification executes in $`O(M)`$ time for total artifact byte size $`M`$. Auxiliary space is bounded by $`O(|P|)`$ for canonical path buffers. Path operations are strictly polynomial ($`O(|P|) \in \mathbf{P}`$) with no traversal of NP decision frontiers (NP-1 through NP-8).

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Sovereign Workspace Root Discovery & In-Tree Path Resolution
- **Given:** A valid repository containing package `Package_0` under workspace root $`\mathcal{R}`$, invoked from an arbitrary subdirectory without explicit root arguments.
- **When:** The compiler initializes and resolves internal schema imports for `Package_0::Classifier_Alpha`.
- **Then:** The compiler discovers root $`\mathcal{R}`$ via upward parent inspection ($`D \le 64`$), normalizes relative path $``p_{\text{rel}}``$, and constructs canonical handle $``P = \mathcal{R} \bowtie p_{\text{rel}}``$ within the repository subtree.
- **Diagnostic:** E0100 on root discovery failure.

### AC-02: Boundary Containment & Directory Traversal Rejection
- **Given:** An input schema specifying an external traversal sequence (`../../etc/shadow`), an absolute machine path (`/usr/local/include`), or a user home expansion (`~/models`).
- **When:** The ingestion engine resolves and normalizes import paths during schema loading.
- **Then:** The compiler rejects the path as $``p \in \mathcal{P}_{\text{invalid}}``$, aborts compilation before issuing external filesystem reads, and emits diagnostic error code `E0100` citing the offending token and source span.
- **Diagnostic:** E0100.

### AC-03: Bitwise Output Parity Across Distinct Mount Roots
- **Given:** An identical schema input set $`\mathcal{I}`$ compiled in two distinct workspace mount directories $``\mathcal{R}_A``$ and $``\mathcal{R}_B``$ ($``\mathcal{R}_A \neq \mathcal{R}_B``$) on independent filesystems.
- **When:** The compiler executes full compilation passes $``\mathcal{C}(\mathcal{I}, \mathcal{R}_A)``$ and $``\mathcal{C}(\mathcal{I}, \mathcal{R}_B)``$.
- **Then:** Emitted binary artifacts and serialized model files achieve 0-byte difference, satisfying $``\text{SHA256}(\mathcal{C}(\mathcal{I}, \mathcal{R}_A)) \equiv \text{SHA256}(\mathcal{C}(\mathcal{I}, \mathcal{R}_B))``$.
- **Diagnostic:** E0100 on digest mismatch.

### AC-04: Absolute Path Non-Leakage in Generated Artifacts
- **Given:** A compiled workspace rooted at absolute filesystem path $`\mathcal{R}`$.
- **When:** Downstream code generators and artifact sinks emit generated code, debug metadata, and serialized AST caches.
- **Then:** Binary and textual inspection across 100% of generated artifacts $`a \in \text{Artifacts}(\mathcal{C}(\mathcal{I}, \mathcal{R}))`$ confirms $`\text{ContainsSubstring}(a, \text{PathString}(\mathcal{R})) \equiv \text{false}`$, with zero host usernames or machine prefixes.
- **Diagnostic:** E0100 on path string leakage.
