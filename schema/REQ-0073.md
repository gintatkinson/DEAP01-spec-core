## 1. Normative Statement

The data and flow modeling engine SHALL formalize SysML v2 item definitions (`item def`, `ItemDefinition`) and item usages (`item`, `ItemUsage`) as structural classifiers specializing KerML `Structure`. Item usages represent physical, energetic, or informational payloads flowing across interconnection topologies with value or token identity semantics.

The lowering engine MUST enforce classification duality across all item definitions:
1. **Value Item Payloads**: Item definitions specializing `DataType` represent immutable, identity-free payloads ($`\text{ItemDef} \le \text{DataType}`$). Equality evaluates strictly over structural attribute values.
2. **Discrete Token Payloads**: Item definitions specializing `Class` represent discrete physical or token instances possessing unique extensional identities ($`\text{ItemDef} \le \text{Class}`$, tracking $\text{id}(e)$).

For continuous conservative flow topologies, the compiler MUST verify Kirchhoff mass/energy conservation: the sum of input flow rates SHALL equal the sum of output flow rates at each conservative routing node ($`\sum \text{inflow} = \sum \text{outflow}`$). Flow rate mismatches on conservative items SHALL emit diagnostic `E0200`.

## 2. Formal Invariant

Let $``\mathcal{D}_{\text{item}}``$ denote the set of item definitions and $``\mathcal{U}_{\text{item}}``$ denote item usages:

```math
\begin{aligned}
\text{ItemDefinition} &\le \text{Structure} \\
\mathcal{D}_{\text{item}} &= \mathcal{D}_{\text{item\_val}} \uplus \mathcal{D}_{\text{item\_tok}} \\
\mathcal{D}_{\text{item\_val}} &\subseteq \{ D \in \mathcal{D}_{\text{item}} \mid D \le \text{DataType} \} \\
\mathcal{D}_{\text{item\_tok}} &\subseteq \{ D \in \mathcal{D}_{\text{item}} \mid D \le \text{Class} \}
\end{aligned}
```

Conservative flow balance and token conservation invariant:

```math
\begin{aligned}
\forall v \in \mathcal{V}_{\text{flow}}, \quad &\sum_{e \in \text{InEdges}(v)} \text{rate}(e) = \sum_{e \in \text{OutEdges}(v)} \text{rate}(e) \\
\forall n \in \mathcal{D}_{\text{item}} \cup \mathcal{U}_{\text{item}}, \quad &\Delta_n = \text{UUIDv5}(\text{NS}_{\text{DEAP}}, \text{FQN}(n))
\end{aligned}
```

| Symbol / Term | Domain / Formal Definition |
| :--- | :--- |
| $``\mathcal{D}_{\text{item}}``$ | Set of lowered `ItemDefinition` classifier arena records |
| $``\mathcal{U}_{\text{item}}``$ | Set of lowered `ItemUsage` payload feature arena records |
| $``\mathcal{D}_{\text{item\_val}}``$ | Immutable value-semantic item classifiers specializing `DataType` |
| $``\mathcal{D}_{\text{item\_tok}}``$ | Discrete token-semantic item classifiers specializing `Class` |
| $\text{rate}(e)$ | Scalar quantity flow rate associated with flow edge $e$ |
| $``\Delta_n``$ | Deterministic RFC 4122 UUIDv5 hash derived from namespace $``\text{NS}_{\text{DEAP}}``$ and topological FQN |

## 3. Computational Complexity & Algorithmic Bounds

The item definition lowering, typing, and flow balance checking passes execute strictly within Complexity Class $\mathbf{P}$.

For an input model with $N$ item usages and $F$ flow connections:
1. Node allocation in typed arena and symbol interning execute in amortized $O(1)$ time per node, totaling $O(N)$ time.
2. Duality classification (value vs. token) validates in deterministic $O(1)$ subtyping checks against the precomputed lattice.
3. Flow conservation equations evaluate in $O(F)$ linear time by aggregating incoming and outgoing rates at junction nodes.
4. Multiplicity and token interval checks evaluate in $O(1)$ scalar comparisons per usage.

Total sequential verification complexity is $O(N + F)$. Parallel package lowering scales as $``O((N + F) / N_{\text{max\_workers}} + \log N_{\text{max\_workers}})``$.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Canonical Value Item and Discrete Token Lowering
- **Given:** An immutable value item `ItemDef_Alpha : DataType` and a discrete token item `ItemDef_Beta : Class`.
- **When:** The compiler executes item definition lowering and classification.
- **Then:** Both elements are lowered into arena storage with correct value/token duality tags and zero diagnostic emissions.
- **Diagnostic:** `E0200` emitted if classifier duality resolution fails.

### AC-02: Non-Structural Item Classifier Rejection
- **Given:** An item definition attempting to specialize a behavioral step classifier (`ItemDef_Err : Step`).
- **When:** Semantic type checking validates metamodel classifier conformance.
- **Then:** The compiler rejects the declaration at compile time and emits diagnostic error code `E0200`.
- **Diagnostic:** `E0200` emitted for invalid item metamodel specialization.

### AC-03: Conservative Flow Balance Violation Detection
- **Given:** A junction node with incoming flow rate `Flow_In = 10.0` and outgoing flow rate `Flow_Out = 7.0` for a conservative item.
- **When:** Semantic flow validation evaluates conservation balance equations.
- **Then:** The compiler detects the unbuffered rate discrepancy and emits diagnostic error code `E0200`.
- **Diagnostic:** `E0200` emitted for conservative flow conservation imbalance.

### AC-04: Item Multiplicity Range Conformance
- **Given:** An item usage declared with inverted cardinality bounds `item Item_0 : ItemDef_Alpha [4..1]`.
- **When:** Multiplicity interval validation is executed.
- **Then:** The compiler rejects the inverted interval with exact source spans and diagnostic error code `E0200`.
- **Diagnostic:** `E0200` emitted for invalid item multiplicity interval.
