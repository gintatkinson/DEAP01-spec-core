## 1. Normative Statement

The KerML expression lowering engine and semantic type checker shall transform KerML expressions into an immutable, strongly typed abstract syntax tree (AST) rooted in `Expression`. `Expression` shall specialize `Step`, `Feature`, `Classifier`, and `Type`, formalizing every expression as a computational step producing an authoritative result feature ($``p_{\text{result}}``$).

The engine shall validate four expression families:
1. **Literal Expressions (`LiteralExpression`)**: Lower primitive constants to typed nodes (`Boolean`, `Integer`, `Real`, `String`, `UnlimitedNatural`, and $``\bot_{\text{type}}``$ for `null`). String literals shall be interned into the symbol interner pool per REQ-0036 as the sole exception to zero-copy memory management.
2. **Feature References & Navigation**: Resolve bare identifiers within lexical scopes ($`\Gamma`$) and member access ($`E.f`$) against $`\tau(E)`$. Unresolved identifiers or features shall emit diagnostic code `E0200`.
3. **Operator Expressions (`OperatorExpression`)**: Prefix, postfix, and binary operators shall enforce signature matching against $``\text{dom}(\text{op}_{\odot})``$; incompatible types emit `E0200`. Static division by literal zero ($`E / 0`$) in constant expressions shall emit `E0200`. Conditional selection ($``\text{if } E_{\text{cond}} \text{ then } E_{\text{then}} \text{ else } E_{\text{else}}``$) requires $``E_{\text{cond}} : \text{Boolean}``$ and unifies branches to their least common supertype ($``T_{\text{then}} \vee T_{\text{else}}``$); violations emit `E0200`.
4. **Invocation Expressions (`InvocationExpression`)**: Invocations $``F(a_1, \dots, a_k)``$ bind arguments to formal parameters $``(p_1, \dots, p_k)``$. Target or arity errors emit `E0200`. For $`\text{In}`$ parameters, argument types must conform ($``\tau(a_i) \le \tau(p_i)``$); type mismatches emit `E0200`. For $`\text{Out}`$ and $`\text{InOut}`$ parameters, arguments must be assignable lvalues ($``\tau(p_i) \le \tau(a_i)``$ for $`\text{Out}`$; $``\tau(a_i) \equiv \tau(p_i)``$ for $`\text{InOut}`$); binding immutable literals or rvalues emits `E0201`.

Pure expressions shall be referentially transparent and side-effect free ($``\sigma_{\text{post}} \equiv \sigma_{\text{pre}}``$). Constant expressions shall be evaluated at compile time; cyclic dependencies ($``E_1 \to^+ E_1``$) emit `E0203`.

Lowered nodes receive deterministic RFC 4122 UUIDv5 identifiers (REQ-0010). On faults, the engine records diagnostics in sink $``\mathcal{D}_{\text{sink}}``$, binds sentinel $``\bot_{\text{expr}}``$, and resynchronizes at delimiters; reaching limit $``C_{\text{max\_errors}}``$ emits `E0199` and halts. All models and diagnostics shall employ synthetic MBSE placeholders (e.g., `Package_0`, `Classifier_Alpha`, `Function_Alpha`, `param_x : Real`).

## 2. Formal Invariant

Metamodel Specialization Hierarchy:

```math
\text{Expression} \le_{\text{sub}} \text{Step} \le_{\text{sub}} \text{Feature} \le_{\text{sub}} \text{Type}
```

Expression Node Formalization: Each lowered expression node $``E \in \mathcal{E}_{\text{expr}}``$ is formalized as:

```math
E = \langle \text{id}_E, \kappa_E, \tau(E), \mu(E), \text{Children}_E, \Delta_E, \text{span}_E, \pi_{\text{pure}} \rangle
```

where $``\text{id}_E \in \mathbb{N}_{32}``$, $``\kappa_E \in \{ \text{Literal}, \text{FeatureRef}, \text{MemberAccess}, \text{UnaryOp}, \text{BinaryOp}, \text{Conditional}, \text{Invocation} \}``$, $`\tau(E) \in \mathcal{T}`$, $``\Delta_E \in \{0, 1\}^{128}``$, and $``\pi_{\text{pure}} \in \{ \text{Pure}, \text{Impure} \}``$.

Typing Soundness, Referential Transparency, and Operator Invariants:

```math
\begin{aligned}
\Gamma \vdash E : T &\implies \forall \sigma \in \Sigma_{\text{store}}, \quad \text{eval}(E, \sigma) = (v, \sigma') \implies v \in ⟦ T ⟧ \wedge (\pi_{\text{pure}}(E) = \text{Pure} \implies \sigma' \equiv \sigma) \\
\Gamma \vdash E_1 \odot E_2 : T_{\text{res}} &\iff (\tau(E_1), \tau(E_2)) \in \text{dom}(\text{op}_{\odot}) \wedge T_{\text{res}} = \text{codom}(\text{op}_{\odot}) \\
\Gamma \vdash (\text{if } E_{\text{c}} \text{ then } E_1 \text{ else } E_2) : (T_1 \vee T_2) &\iff \Gamma \vdash E_{\text{c}} : \text{Boolean} \wedge \Gamma \vdash E_1 : T_1 \wedge \Gamma \vdash E_2 : T_2
\end{aligned}
```

Invocation Directionality and Diagnostic Mapping Invariants:

```math
\begin{aligned}
\text{ValidArg}(a_i, p_i) &\iff \begin{cases}
(\tau(a_i) \le \tau(p_i)) \wedge \text{IsReadable}(a_i), & \text{dir}(p_i) = \text{In} \\
(\tau(p_i) \le \tau(a_i)) \wedge \text{IsAssignable}(a_i), & \text{dir}(p_i) = \text{Out} \\
(\tau(a_i) \equiv \tau(p_i)) \wedge \text{IsReadable}(a_i) \wedge \text{IsAssignable}(a_i), & \text{dir}(p_i) = \text{InOut}
\end{cases} \\
\Delta_E &= \text{UUIDv5}(\text{NS}_{\text{DEAP}}, \text{FQN}(E) \mathbin{\Vert} \text{Discriminant}(\kappa_E) \mathbin{\Vert} \text{id}_E) \\
(\kappa_E = \text{BinaryOp}(/, E_1, E_2) \wedge \text{IsZero}(E_2)) &\implies \text{Diagnostic}(E, \text{E0200}) \in \mathcal{D}_{\text{sink}} \\
(\kappa_E = \text{Invocation}(F, A) \wedge \exists i : \neg \text{ValidArg}(a_i, p_i) \wedge \text{dir}(p_i) \ne \text{In}) &\implies \text{Diagnostic}(a_i, \text{E0201}) \in \mathcal{D}_{\text{sink}} \\
(E \to^+ E \text{ in constant dependency DAG}) &\implies \text{Diagnostic}(E, \text{E0203}) \in \mathcal{D}_{\text{sink}}
\end{aligned}
```

## 3. Computational Complexity & Algorithmic Bounds

The expression lowering and type checking pipeline operates strictly within Complexity Class $`\mathbf{P}`$. Contiguous arena node allocation and symbol interning execute in amortized $`O(1)`$ time and $`O(1)`$ space. Bottom-up post-order type inference traverses expression trees in deterministic linear time $`O(N)`$ for $``N = |\mathcal{E}_{\text{expr}}|``$ nodes, performing $`O(1)`$ signature and subtyping lookups per node. Constant expression cycle detection executes in $``O(N_{\text{const}} + E_{\text{const}}) \subseteq O(N)``$ via Tarjan SCC. While subtyping in arbitrary posets is NP-complete (NP-3), restricting expressions to bounded meet-semilattices with C3 linearization guarantees deterministic $`O(N)`$ execution without backtracking.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Literal Ingestion & Feature Navigation Typing

- **Given:** Literals (`true`, `42`, `3.14159`, `"symbol_token"`, `*`, `null`) and scoped feature reference `Classifier_Alpha.param_x : Real`.
- **When:** Lowering executes literal ingestion and scoped identifier resolution.
- **Then:** Literals receive standard library scalar types, strings are interned, valid references resolve to type `Real`, and ungrounded identifiers or missing members are rejected.
- **Diagnostic:** `E0200` emitted on unresolved identifier, missing member, or literal overflow.

### AC-02: Operator Conformance, Division-by-Zero & Conditional Unification

- **Given:** Operations `param_x + 5.0`, static zero division `param_x / 0.0`, invalid addition `"token" + 42`, and conditional `if flag then param_x else 0.0`.
- **When:** The type checker validates operator typing and conditional branch unification.
- **Then:** Valid expressions type-check successfully; operand mismatches, static division by literal zero, and un-unifiable conditional branches are rejected at compile time.
- **Diagnostic:** `E0200` emitted on operator signature mismatch, division by zero, or branch unification failure.

### AC-03: Invocation Parameter Directionality & Mutability LValue Gate

- **Given:** Function `Function_Alpha(in p_in : Integer, out p_out : Integer, inout p_io : Integer) : Boolean`.
- **When:** Invocations bind arguments to parameters, including binding constant literal `10` or expression `param_x + 1` to `p_out` or `p_io`.
- **Then:** Valid bindings are accepted; arity or type mismatches emit `E0200`; passing immutable rvalues to $`\text{Out}`$ or $`\text{InOut}`$ parameters is rejected.
- **Diagnostic:** `E0200` emitted on arity or type mismatch; `E0201` emitted on parameter directionality or mutability violation.

### AC-04: Referential Transparency, Cycle Detection & Error Recovery

- **Given:** Pure expression `Expression_1`, circular constant chain ($``c_1 = c_2 + 1, c_2 = c_1 * 2``$), and error limit $``C_{\text{max\_errors}} = 50``$.
- **When:** The compiler executes constant evaluation, cycle detection, and error recovery.
- **Then:** Pure expression evaluation preserves store state ($``\sigma_{\text{post}} \equiv \sigma_{\text{pre}}``$); cyclic constants emit `E0203` with precise spans; sentinel $``\bot_{\text{expr}}``$ is substituted, and reaching $``C_{\text{max\_errors}}``$ emits `E0199` and halts.
- **Diagnostic:** `E0203` emitted on circular constant dependency; `E0199` emitted when diagnostic capacity reaches $``C_{\text{max\_errors}}``$.
