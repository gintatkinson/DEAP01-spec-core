## 1. Normative Statement

The functional lowering engine of Subsystem 4 shall formalize KerML `Function` classifiers as pure mathematical morphisms from input parameter domains to output result codomains. A `Function` specializes `Behavior` (and transitively `Class`, `Classifier`, `Type`) under referential transparency, total determinism, and side-effect freedom.

The lowering engine shall enforce the following normative rules:
1. **Parameter Directionality and Immutability**: Formal parameters must declare direction $`\text{dir}(p) \in \{ \text{In}, \text{Out}, \text{Return} \}`$. Input parameters must declare $`\text{In}`$ and remain immutable. The function must declare exactly one result parameter with direction $`\text{Return}`$ or $`\text{Out}`$ typing return codomain $``T_{\text{ret}}``$. Declaring $`\text{InOut}`$ on a `Function` shall trigger diagnostic `E0201`.
2. **Referential Transparency and Purity**: Evaluation must satisfy $`\mathbf{a} = \mathbf{b} \implies ⟦ F ⟧(\mathbf{a}) = ⟦ F ⟧(\mathbf{b})`$. The body expression shall read strictly from inputs or constants, execute zero state writes, and preserve store equivalence ($``\sigma_{\text{post}} \equiv \sigma_{\text{pre}}``$). State mutation or impure behavior calls shall trigger diagnostic `E0200`.
3. **Return Typing and Body Conformance**: The body expression must evaluate to a type conforming to declared return type $``T_{\text{ret}}``$ ($``\tau(E_{\text{body}}) \le T_{\text{ret}}``$). Incompatible or unresolvable types shall trigger diagnostic `E0200`.
4. **Call-Site Invocation Conformance**: Invocations $``F(a_1, \dots, a_m)``$ must match arity ($`m = k`$) and argument subtyping ($``\tau(a_i) \le T_i``$). Violations shall trigger diagnostic `E0200`.
5. **Call Graph Cycle Detection**: Unbounded recursive cycles lacking a well-founded terminating measure and base condition shall trigger diagnostic `E0203`. Pure non-recursive functions evaluate with $`O(1)`$ stack overhead.

## 2. Formal Invariant

Let $`\mathcal{T}`$ denote the classifier universe ordered by subtyping relation $`\le`$. Taxonomic specialization satisfies:

```math
\text{Function} \le \text{Behavior} \le \text{Class} \le \text{Classifier} \le \text{Type}
```

A function $`F`$ with inputs $``\mathcal{P}_{\text{in}}(F) = (x_1: T_1, \dots, x_k: T_k)``$ and result $``p_{\text{ret}}(F)``$ of type $``T_{\text{ret}} = \tau(p_{\text{ret}}(F))``$ defines mathematical mapping:

```math
⟦ F ⟧ : \prod_{i=1}^k ⟦ T_i ⟧ \longrightarrow ⟦ T_{\text{ret}} ⟧
```

Referential transparency and store invariance over store $``\sigma \in \Sigma_{\text{store}}``$ satisfy:

```math
\begin{aligned}
\forall \mathbf{a}, \mathbf{b} \in \prod_{i=1}^k ⟦ T_i ⟧, \quad \mathbf{a} = \mathbf{b} &\implies ⟦ F ⟧(\mathbf{a}) = ⟦ F ⟧(\mathbf{b}) \\
\text{Reads}(F) \subseteq \{ x_1, \dots, x_k \} \cup \mathcal{C}_{\text{const}} \;\wedge\; \text{Writes}(F) = \emptyset &\implies \sigma_{\text{post}} \equiv \sigma_{\text{pre}}
\end{aligned}
```

Parameter directionality, return typing conformance, and non-mutation satisfy:

```math
\begin{aligned}
\forall p \in \mathcal{P}_{\text{in}}(F), \, \text{dir}(p) = \text{In} &\;\wedge\; \text{dir}(p_{\text{ret}}(F)) \in \{ \text{Return}, \text{Out} \} \;\wedge\; \forall p \in \text{Params}(F), \, \text{dir}(p) \ne \text{InOut} \\
\Gamma \vdash E_{\text{body}}(F) : T_{\text{eval}} &\implies T_{\text{eval}} \le T_{\text{ret}} \;\wedge\; T_{\text{ret}} \ne \bot_{\text{type}}
\end{aligned}
```

Invocation validity and recursion well-foundedness satisfy:

```math
\begin{aligned}
\text{ValidInvocation}(I, F) &\iff (m = k) \;\wedge\; \left( \forall i \in \{ 1, \dots, k \}, \, \Gamma \vdash a_i : T_{a_i} \;\wedge\; T_{a_i} \le T_i \right) \\
\forall (F, F) \in \mathcal{E}_{\text{call}}^+, &\quad \exists \mu_{\text{term}}, \, \forall \mathbf{x}, \, \text{RecCond}(\mathbf{x}) \implies \mu_{\text{term}}(\text{RecArgs}(\mathbf{x})) \lt \mu_{\text{term}}(\mathbf{x})
\end{aligned}
```

Deterministic RFC 4122 UUIDv5 topological anchoring satisfies:

```math
\forall u \in \mathcal{V}_{\text{func}} \cup \mathcal{V}_{\text{param}}, \quad \Delta_u = \text{UUIDv5}(\text{NS}_{\text{DEAP}}, \text{FQN}(u))
```

## 3. Computational Complexity & Algorithmic Bounds

Function lowering, signature verification, and static type checking execute within Complexity Class $`\mathbf{P}`$. For $`M`$ functions with $`K`$ parameters, $`N`$ expression nodes, and call graph $``G_{\text{call}} = (V, E)``$:
- Arena allocation and symbol interning take amortized $`O(1)`$ per node, yielding $`O(M + K + N)`$ initialization.
- Parameter directionality and multiplicity validation execute in $`O(K)`$ time.
- Body expression type inference and subtyping conformance execute in $`O(N)`$ time. Subtyping checks $``T_{\text{eval}} \le T_{\text{ret}}``$ execute in $`O(1)`$ time via precomputed reachability bitsets ($`h \le 32`$), grounding the tractable subclass of NP-3 (Subtyping Lattice & C3 Linearization) without backtracking.
- Invocation checking executes in $`O(k)`$ for $`k`$ arguments.
- Call graph cycle detection executes in deterministic $`O(V + E)`$ time via Tarjan's SCC algorithm.
- Pure non-recursive expressions evaluate with strictly $`O(1)`$ stack overhead.

Total sequential complexity is $`O(M + K + N + V + E)`$. Parallel validation on a work-stealing pool scales as $``O((M + K + N + V + E) / N_{\text{max\_workers}} + \log N_{\text{max\_workers}})``$.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Pure Mathematical Morphism & Referential Transparency

- **Given:** Function `Function_Alpha(Param_1 : Type_A, Param_2 : Type_B) : Type_A` declaring pure expression body $``E_{\text{body}}``$.
- **When:** Functional lowering evaluates morphism $``⟦ \text{Function\_Alpha} ⟧``$ under store $`\sigma`$.
- **Then:** Input parameters are immutable, evaluation produces identical outputs for identical inputs ($`\mathbf{a} = \mathbf{b} \implies ⟦ F ⟧(\mathbf{a}) = ⟦ F ⟧(\mathbf{b})`$), $``\sigma_{\text{post}} \equiv \sigma_{\text{pre}}``$, and zero diagnostics are emitted.
- **Diagnostic:** `E0200` emitted on side-effect detection or state mutation within a function body.

### AC-02: Parameter Directionality & Prohibition of `inout`

- **Given:** Model declaring `Function_Beta` containing a formal parameter with direction `inout`.
- **When:** Semantic parameter validation inspects directionality tags $`\text{dir}(p) \in \{ \text{In}, \text{Out}, \text{Return} \}`$.
- **Then:** The compiler rejects `Function_Beta`, binds error sentinel $``\bot_{\text{type}}``$, and emits diagnostic `E0201`.
- **Diagnostic:** `E0201` emitted on illegal `inout` parameter declaration on a `Function`.

### AC-03: Return Type Specialization & Body Expression Conformance

- **Given:** Function `Function_Alpha` with return type `Type_A`, whose body expression evaluates to `Type_B`.
- **When:** Semantic type checking evaluates subtyping conformance $``\tau(E_{\text{body}}) \le T_{\text{ret}}``$.
- **Then:** If `Type_B` specializes `Type_A`, compilation succeeds; otherwise, the compiler rejects the function, binds $``\bot_{\text{type}}``$, and emits diagnostic `E0200`.
- **Diagnostic:** `E0200` emitted on return type incompatibility or unresolved return/parameter types.

### AC-04: Call-Site Arity & Argument Subtyping Conformance

- **Given:** Function `Function_Alpha(Param_1 : Type_A, Param_2 : Type_B) : Type_A` and calls $``I_1 = \text{Function\_Alpha}(a_1)``$, $``I_2 = \text{Function\_Alpha}(a_1, a_2, a_3)``$, and $``I_3 = \text{Function\_Alpha}(a_1, a_{\text{invalid}})``$.
- **When:** Call-site validation checks arity and argument types against formal signatures.
- **Then:** Arity mismatches ($``I_1, I_2``$) and argument type mismatch ($``I_3``$) are rejected with diagnostic `E0200`.
- **Diagnostic:** `E0200` emitted on invocation arity mismatch or argument type incompatibility.
