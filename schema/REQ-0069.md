## 1. Normative Statement

The behavioral lowering engine of Subsystem 4 SHALL formalize behaviors, actions, invocations, and temporal performance occurrences in strict accordance with the OMG Kernel Modeling Language (KerML) and Systems Modeling Language (SysML v2) specifications. `Behavior` SHALL specialize `Class` (and transitively `Classifier`, `Type`), formalizing behavioral definitions. Invocations of behaviors within enclosing scopes SHALL be formalized as `Step` features specializing `Feature` and typed by a `Behavior` classifier ($``\tau(s) \le \text{Behavior}``$). Typing a `Step` with a non-behavioral classifier SHALL emit diagnostic `E0200`.

Every execution of a behavior over physical or simulated time SHALL be formalized as a `Performance` occurrence specializing `Occurrence`. The lowering engine MUST enforce the following formal semantic rules:
1. **Parameter Conformance and Directionality**: A behavior declares an ordered list of parameters with declared types, multiplicities $``\mu(p) = [m_{\min}, m_{\max}]``$, and directions $``\text{dir}(p) \in \{ \text{In}, \text{Out}, \text{InOut}, \text{Return} \}``$. Arguments bound to parameters at a call site MUST conform to declared parameter types ($``\tau(a) \le \tau(p)``$); subtyping violations SHALL emit diagnostic `E0202`. Directionality violations (assigning to immutable `In` parameters or reading unassigned `Out` parameters) SHALL emit diagnostic `E0201`.
2. **Performance Lifecycle State Automaton**: Each performance occurrence executes over interval $``[t_{\text{start}}, t_{\text{end}}]``$ with $``t_{\text{start}} \le t_{\text{end}}``$. Inverted bounds SHALL emit diagnostic `E0200`. The performance tracks discrete state $``\sigma_{\text{perf}} \in \{ \text{Unstarted}, \text{Executing}, \text{Suspended}, \text{Completed}, \text{Terminated} \}``$. Starting validates pre-conditions $``\mathcal{C}_{\text{pre}}``$, and completing validates post-conditions $``\mathcal{C}_{\text{post}}``$. Contract violations transition to `Terminated` and emit diagnostic `E0202`. Illegal transitions outside the automaton emit diagnostic `E0201`.
3. **Sub-Step Temporal Containment**: For composite behaviors with constituent sub-steps $``\mathcal{S}_B``$, the temporal extent of each sub-step MUST be contained within the parent performance bounds: $``[t_{\text{start}}(s_i), t_{\text{end}}(s_i)] \subseteq [t_{\text{start}}(P), t_{\text{end}}(P)]``$. Out-of-bounds execution SHALL emit diagnostic `E0200`.

## 2. Formal Invariant

Let $``\mathcal{M}_{\text{perf}}``$ denote the performance lifecycle automaton and $``\mathcal{S}_B``$ denote the set of constituent sub-steps. Mathematical state mapping:

```math
\begin{aligned}
\mathcal{Q}_{\text{perf}} &= \{ \text{Unstarted}, \text{Executing}, \text{Suspended}, \text{Completed}, \text{Terminated} \} \\
\delta_{\text{perf}} &: \mathcal{Q}_{\text{perf}} \times \Sigma_{\text{event}} \longrightarrow \mathcal{Q}_{\text{perf}} \\
\forall s \in \Sigma, \quad \text{Pre}(s(t_{\text{start}})) &\equiv \text{true} \implies \text{Post}(s(t_{\text{start}}), s(t_{\text{end}})) \equiv \text{true}
\end{aligned}
```

Sub-step temporal containment, parameter subtyping, and RFC 4122 UUIDv5 invariants:

```math
\begin{aligned}
\forall s_i \in \mathcal{S}_B, \quad [t_{\text{start}}(s_i), t_{\text{end}}(s_i)] &\subseteq [t_{\text{start}}(P), t_{\text{end}}(P)] \\
\forall a_k \in \text{Args}(s), \quad \tau(a_k) &\le \tau(p_k) \\
\forall n \in \mathcal{V}_{\text{perf}}, \quad \Delta_n &= \text{UUIDv5}(\text{NS}_{\text{DEAP}}, \text{FQN}(n))
\end{aligned}
```

## 3. Computational Complexity & Algorithmic Bounds

The behavior, step, and performance lowering passes execute strictly within Complexity Class $\mathbf{P}$.

For a behavioral model with $V$ step nodes and $E$ precedence edges:
1. Node allocation in typed AST memory and symbol interning execute in amortized $O(1)$ time per node, totaling $O(V)$ time.
2. Parameter directionality and multiplicity checking execute in $O(K)$ time for $K$ parameters.
3. Precomputed monotonic subtyping lattice queries execute in $O(1)$ time per argument, grounding the tractable polynomial fragment of NP-3 (Subtyping Lattice & C3 Linearization).
4. Sub-step temporal containment and precedence verification execute in $O(V + E)$ time without backtracking.

Total sequential verification complexity is $O(V + E)$. Parallel package execution scales as $``O((V + E) / N_{\text{max\_workers}} + \log N_{\text{max\_workers}})``$.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Canonical Behavior, ActionUsage & Performance Lowering
- **Given:** A model declaring `Behavior_Alpha` with parameter `Param_1 : Real [In]` and nested `Step_Alpha : Behavior_Alpha`.
- **When:** The compiler lowers the behavior definition and action step into the AST.
- **Then:** Both elements are lowered with valid 32-bit handles, verified parameter types, and zero diagnostic emissions.
- **Diagnostic:** Diagnostic sink remains empty.

### AC-02: Non-Behavioral Step Type Rejection
- **Given:** A structural classifier `Classifier_Alpha` that does not specialize `Behavior`.
- **When:** A step is declared with invalid typing (`Step_Bad : Classifier_Alpha`).
- **Then:** The compiler rejects the step declaration, binds error sentinel $``\bot_{\text{type}}``$, and emits diagnostic code `E0200`.
- **Diagnostic:** `E0200` emitted for non-behavioral step typing.

### AC-03: Parameter Subtyping & Directionality Violation Rejection
- **Given:** `Behavior_Alpha` declaring parameter `Param_In : Real [In]`.
- **When:** An invocation passes an argument with incompatible type `Classifier_Beta` or attempts to mutate `Param_In` inside the body.
- **Then:** The compiler rejects the invocation with diagnostic code `E0202` on subtyping failure or `E0201` on illegal mutation.
- **Diagnostic:** `E0201` emitted for directionality breach; `E0202` emitted for subtyping mismatch.

### AC-04: Sub-Step Temporal Containment Boundary Breach
- **Given:** Performance `Performance_1` with lifetime `[10.0, 50.0]`.
- **When:** A constituent sub-step `Step_Child` declares temporal execution bounds `[5.0, 30.0]` ($``t_{\text{start}} \lt 10.0``$) or `[20.0, 60.0]` ($``t_{\text{end}} \gt 50.0``$).
- **Then:** The compiler rejects the containment violation with exact source byte spans and emits diagnostic code `E0200`.
- **Diagnostic:** `E0200` emitted for sub-step temporal containment breach.
