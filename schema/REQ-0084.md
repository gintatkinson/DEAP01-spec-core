## 1. Normative Statement

The KerML/SysML v2 lowering engine SHALL lower assert constraint declarations (`assert constraint`, `AssertConstraintUsage`) into invariant assertions specializing KerML `ConstraintUsage` and `Invariant`. Every `AssertConstraintUsage` binds Boolean predicate $\Phi$ to a classifier context (`part def`, `item def`, `action def`, or `state def`) or package, asserting temporal invariance $\square \Phi$ across reachable execution traces.

The lowering engine MUST enforce four static invariants:
1. **Specialization & Codomain**: `AssertConstraintUsage` specializes KerML `ConstraintUsage` with codomain `Boolean` and `is_asserted` true. Predicate $\Phi$ MUST unify with `Boolean`; non-Boolean expressions SHALL emit diagnostic `E0200`.
2. **Directionality & Purity**: Parameters MUST declare directional `in` semantics (`E0201` on violation). Evaluation MUST be functionally pure ($``\Delta\text{State} \equiv \emptyset``$; `E0200` on state mutation).
3. **Binding & Acyclicity**: Argument vector $``\mathbf{A}_{ACU}``$ MUST match parameter vector $``\mathbf{P}_{CD}``$ in arity and subtyping ($``\tau(a_i) \le \tau(p_i)``$; `E0200` on mismatch). Anonymous blocks synthesize arena definitions. The constraint call graph MUST be a DAG (`E0203` on cycles).
4. **Dual Synthesis Obligations**: Synthesis SHALL emit SMT-LIB2 proof obligations ($``\text{Reachable}(\sigma) \wedge \neg \Phi \implies \text{UNSAT}``$, emitting `E0200` on refutation) and zero-allocation runtime monitors $``\mathcal{M}_{\text{monitor}}(\sigma_t)``$ evaluating $``\Phi(\sigma_t)``$ in $O(1)$ time with failsafe containment.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Canonical Assert Constraint Lowering
- **Given:** Classifier `Classifier_Alpha` with definition `ConstraintDef_Alpha` (`in param_x : Real; in param_y : Real; param_x <= param_y;`) and usage `AssertConstraint_1`.
- **When:** Lowering and parameter binding execute.
- **Then:** `AssertConstraint_1` lowers into arena storage with `is_asserted` true and empty diagnostic sink.
- **Diagnostic:** Diagnostic sink remains empty.

### AC-02: Non-Boolean Codomain & Impure Expression Rejection
- **Given:** Assert constraint evaluating to `Real` (`attr_a + attr_b`) or mutating state (`attr_a = param_x`).
- **When:** Type checking and purity validation execute.
- **Then:** Lowering rejects declaration, assigns sentinel $``\bot_{\text{assert}}``$, and emits diagnostic `E0200`.
- **Diagnostic:** `E0200` (Non-Boolean codomain or state mutation).

### AC-03: Parameter Directionality & Arity Violation Rejection
- **Given:** Assert constraint referencing definition with `out` parameter, or binding 1 argument for a 2-parameter definition.
- **When:** Parameter directionality and binding verification execute.
- **Then:** Lowering rejects non-`in` parameters with `E0201` and arity mismatches with `E0200`.
- **Diagnostic:** `E0201` (Invalid parameter direction); `E0200` (Parameter arity mismatch).

### AC-04: Circular Constraint Dependency Detection
- **Given:** Mutually recursive definitions `ConstraintDef_Alpha` and `ConstraintDef_Beta`.
- **When:** Cycle detection evaluates call graph $``\mathcal{R}_{\text{c\_dep}}``$.
- **Then:** Compiler detects dependency cycle, halts topological sorting, and emits diagnostic `E0203`.
- **Diagnostic:** `E0203` (Circular constraint dependency).
