## 1. Normative Statement

The Core Metamodel, Node Arena & AST Graph Engine shall bind item flow payloads to authoritative classifier definitions and validate stream transmission rate multiplicities across connectors and channels. Every item flow (`ItemFlow` or `FlowUsage`) connecting source port $``P_{\text{src}}``$ and target port $``P_{\text{tgt}}``$ must specify payload classifier $``\tau_F``$ and rate multiplicity interval $``R_{\text{flow}} = [r_{\min}, r_{\max}]``$ in Hertz.

The type checking engine shall enforce endpoint payload compatibility. Without an explicit serialization adapter ($``\mathcal{A}_F = \bot``$), payload $``\tau_F``$ must satisfy subtyping covariance: $``\tau_F :> \tau(P_{\text{src}})``$ and $``\tau_F :> \tau(P_{\text{tgt}})``$. With an adapter $``\mathcal{A}_F``$, the engine shall verify signature conformance: $``\tau(P_{\text{src}}) \le \text{InType}(\mathcal{A}_F)``$ and $``\text{OutType}(\mathcal{A}_F) \le \tau(P_{\text{tgt}})``$. Incompatible payloads without adapters shall emit diagnostic error code `E0202`.

Rate intervals must satisfy $``0 \le r_{\min} \le r_{\max}``$. Peak throughput $``\Theta(F) = r_{\max} \cdot \text{sizeof}(\tau_F)``$ must not exceed channel capacity $``C_{\text{channel}}``$, where $``\text{sizeof}(\tau_F)``$ is the serialized byte footprint of $``\tau_F``$. Multiplexed channels must satisfy $``\sum \Theta(F) \le C_{\text{channel}}``$. Violations shall emit diagnostic error code `E0202`.

## 2. Formal Invariant

Let $``\mathcal{E}_{\text{flow}}``$ denote the universe of lowered item flow AST entities. Each entity $``F \in \mathcal{E}_{\text{flow}}``$ is formalized as an 8-tuple:

```math
F = \langle \text{id}_F, P_{\text{src}}, P_{\text{tgt}}, \tau_F, R_{\text{flow}}, C_{\text{channel}}, \mathcal{A}_F, \text{span}_F \rangle
```

where $``\text{id}_F \in \mathbb{N}_{32}``$, $``P_{\text{src}}, P_{\text{tgt}} \in \mathcal{H}_{\text{port}}``$, $``\tau_F \in \mathcal{C}``$, $``R_{\text{flow}} = [r_{\min}, r_{\max}]``$, $``C_{\text{channel}} \in \mathbb{R}_{\ge 0} \cup \{ \infty \}``$, $``\mathcal{A}_F \in \mathcal{H}_{\text{adapter}} \cup \{ \bot \}``$, and $``\text{span}_F``$ denotes source provenance.

Let $`\tau(P)`$ denote the declared payload type of port $`P`$, and let $`(\mathcal{C}, \le)`$ denote the subtyping poset ($`A \le B \iff B :> A`$). Payload compatibility predicate $``\Phi_{\text{type}}(F)``$ satisfies:

```math
\Phi_{\text{type}}(F) \iff \begin{cases}
(\tau_F :> \tau(P_{\text{src}})) \;\wedge\; (\tau_F :> \tau(P_{\text{tgt}})), & \text{if } \mathcal{A}_F = \bot \\
(\tau(P_{\text{src}}) \le \text{InType}(\mathcal{A}_F)) \;\wedge\; (\text{OutType}(\mathcal{A}_F) \le \tau(P_{\text{tgt}})), & \text{if } \mathcal{A}_F \ne \bot
\end{cases}
```

Rate multiplicity interval and channel throughput predicates satisfy:

```math
\begin{aligned}
\Phi_{\text{rate}}(F) &\iff (0 \le r_{\min}) \;\wedge\; (r_{\min} \le r_{\max}) \\
\Phi_{\text{cap}}(F) &\iff r_{\max} \cdot \text{sizeof}(\tau_F) \le C_{\text{channel}} \\
\Phi_{\text{mux}}(\kappa) &\iff \sum_{F \in \mathcal{E}_{\text{flow}}(\kappa)} r_{\max}(F) \cdot \text{sizeof}(\tau_F) \le C_{\text{channel}}(\kappa)
\end{aligned}
```

Diagnostic code binding per REQ-0191 and deterministic UUIDv5 anchoring satisfy:

```math
\begin{aligned}
\neg \Phi_{\text{type}}(F) \;\vee\; \neg \Phi_{\text{rate}}(F) \;\vee\; \neg \Phi_{\text{cap}}(F) &\implies \text{DiagnosticCode::E0202} \in \mathcal{D} \\
\neg \Phi_{\text{mux}}(\kappa) &\implies \text{DiagnosticCode::E0202} \in \mathcal{D} \\
|\mathcal{D}| \ge C_{\text{max\_errors}} &\implies \text{DiagnosticCode::E0199} \in \mathcal{D} \\
\forall F \in \mathcal{E}_{\text{flow}}, \quad \text{UUID}(F) &= \text{UUIDv5}(\text{NS}_{\text{DEAP}}, \text{FQN}(F))
\end{aligned}
```

## 3. Computational Complexity & Algorithmic Bounds

Flow payload binding and stream rate validation execute within Complexity Class $`\mathbf{P}`$. Evaluating subtyping covariance $``\tau_F :> \tau(P)``$ executes in $`O(H)`$ steps with lattice depth $`H \le 32`$, bounded by $`O(1)`$ amortized operations via bitset reachability (tractable monotonic poset subtyping avoiding general poset NP-completeness per NP-3). Serialized size lookup $``\text{sizeof}(\tau_F)``$, rate interval verification, and capacity checks execute in $`O(1)`$ scalar operations.

For an AST graph with $``E = |\mathcal{E}_{\text{flow}}|``$ flows and $``K = |\mathcal{K}_{\text{channel}}|``$ channels, total verification executes in deterministic linear time $`O(E + K) \subseteq O(V + E)`$. Parallel validation on a bounded work-stealing pool with $``N_{\text{max\_workers}}``$ threads executes in $``O\left(\frac{E + K}{N_{\text{max\_workers}}} + \log N_{\text{max\_workers}}\right)``$. Auxiliary space complexity is strictly $`O(1)`$ beyond contiguous AST storage and $``O(C_{\text{max\_errors}}) = O(1)``$ preallocated diagnostic records.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Valid Payload Type Binding and Covariance
- **Given:** Ports `Port_1 : Classifier_Beta` and `Port_2 : Classifier_Alpha` with `Classifier_Beta :> Classifier_Alpha`, connected by flow `Flow_A` with payload `Classifier_Beta` and rate `[10.0, 50.0]` Hz.
- **When:** Flow type checking executes.
- **Then:** The engine validates $``\tau_F :> \tau(P_{\text{src}})``$ and $``\tau_F :> \tau(P_{\text{tgt}})``$, passing with zero diagnostics.
- **Diagnostic:** `E0202` on covariance failure.

### AC-02: Incompatible Payload Type Rejection Without Adapter
- **Given:** Disjoint ports `Port_1 : Classifier_Alpha` and `Port_2 : Classifier_Gamma` connected by flow `Flow_Err` with payload `Classifier_Gamma` without an adapter ($``\mathcal{A}_F = \bot``$).
- **When:** Flow type checking executes.
- **Then:** Rejects flow, binds sentinel $``\bot_{\text{flow}}``$, and emits structured diagnostic `E0202` with source byte span coordinates.
- **Diagnostic:** Emits `E0202` (`PayloadTypeIncompatibility`).

### AC-03: Adapter-Mediated Payload Conformance
- **Given:** Ports `Port_1 : Classifier_Alpha` and `Port_2 : Classifier_Gamma` connected by flow `Flow_Adapt` with adapter `Adapter_AlphaToGamma` ($``\text{InType} = \text{Classifier\_Alpha}``$, $``\text{OutType} = \text{Classifier\_Gamma}``$).
- **When:** Evaluating adapter payload compatibility.
- **Then:** Confirms $``\tau(P_{\text{src}}) \le \text{InType}(\mathcal{A}_F)``$ and $``\text{OutType}(\mathcal{A}_F) \le \tau(P_{\text{tgt}})``$, passing with zero diagnostics.
- **Diagnostic:** `E0202` on adapter mismatch.

### AC-04: Rate Multiplicity Well-Formedness and Channel Capacity Bounds
- **Given:** Channel `Channel_0` ($``C_{\text{channel}} = 1000``$ bytes/sec), flow `Flow_Err1` with rate $`[100.0, 10.0]`$ Hz, and flow `Flow_Err2` with peak throughput $`1280`$ bytes/sec.
- **When:** Validating rate multiplicity and channel capacity constraints.
- **Then:** Rejects `Flow_Err1` for inverted rate bounds and `Flow_Err2` for capacity overflow, emitting structured diagnostics.
- **Diagnostic:** Emits `E0202` (`MalformedRateMultiplicityInterval` or `ChannelCapacityOverflow`).
