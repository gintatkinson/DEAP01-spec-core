## 1. Normative Statement

The core metamodel shall enforce a strict formal duality and architectural partition between classifier definitions (`ClassifierDef`) representing reusable types and feature usages (`FeatureUsage`) representing contextual occurrences within enclosing namespaces. Structural elements in the abstract syntax graph shall belong exclusively to either partition, with empty intersection ($`\mathcal{C} \cap \mathcal{U} = \emptyset`$).

Every feature usage shall bind to an authoritative classifier definition via a typed reference relation $`\tau : \mathcal{U} \longrightarrow \mathcal{C}`$. Un-typed feature usages ($`\tau(u) = \bot`$), unresolved classifier references, and cyclic definition-usage instantiation chains are strictly prohibited at compile time. In accordance with the subtyping partial order $`(\mathcal{C}, \le)`$, if a feature usage $`u`$ has resolved type $``\tau(u) = C_1``$ and $``C_1``$ specializes $``C_2``$ ($``C_1 \le C_2``$), then $`u`$ conforms to $``C_2``$. When a feature usage binds to an interface slot, parameter, port, or connector end expecting target classifier $``C_{\text{target}}``$, the type checker shall enforce type conformance $``\tau(u) \le C_{\text{target}}``$.

Feature usages may redefine inherited features strictly under monotonic covariance rules:
1. **Type Covariance:** $``\tau(u_{\text{redef}}) \le \tau(u_{\text{base}})``$.
2. **Multiplicity Narrowing:** $``[l_u, u_u] \subseteq [l_{\text{base}}, u_{\text{base}}]``$.
3. **Default Value Containment:** $``v_{\text{default}} \in \text{Domain}(\tau(u_{\text{base}}))``$.
4. **Directional Invariance:** Port directionality ($`\text{in}`$, $`\text{out}`$, $`\text{inout}`$) must be preserved across redefinitions.

Contravariant type redefinition, multiplicity widening, or invalid default values shall deterministically emit diagnostic error code `E0200` per REQ-0191. The engine shall bind error sentinel $``\bot_{\text{type}}``$ on violation, guaranteeing total-function panic-free execution.

## 2. Formal Invariant

Let $``\mathcal{V}_{\text{structural}}``$ denote the set of structural AST nodes. The metamodel partitions structural nodes into disjoint sets of classifier definitions $`\mathcal{C}`$ and feature usages $`\mathcal{U}`$:

```math
\mathcal{V}_{\text{structural}} = \mathcal{C} \cup \mathcal{U}, \quad \mathcal{C} \cap \mathcal{U} = \emptyset
```

The typing relation is a total function mapping every valid feature usage to an authoritative classifier definition:

```math
\tau : \mathcal{U} \longrightarrow \mathcal{C}
```

Subtyping Partial Order and Conformance:

```math
\begin{aligned}
\forall C \in \mathcal{C}, &\quad C \le C \\
\forall C_1, C_2, C_3 \in \mathcal{C}, &\quad (C_1 \le C_2 \wedge C_2 \le C_3) \implies C_1 \le C_3 \\
\forall C_1, C_2 \in \mathcal{C}, &\quad (C_1 \le C_2 \wedge C_2 \le C_1) \implies C_1 = C_2 \\
\text{ConformsTo}(u, C_{\text{target}}) &\iff \tau(u) \le C_{\text{target}}
\end{aligned}
```

Monotonic Covariance Redefinition Invariant:

```math
\begin{aligned}
\text{ValidRedef}(u, u_{\text{base}}) &\iff \Phi_{\text{type}} \wedge \Phi_{\text{mult}} \wedge \Phi_{\text{env}} \wedge \Phi_{\text{dir}} \\
\Phi_{\text{type}} &\iff \tau(u) \le \tau(u_{\text{base}}) \\
\Phi_{\text{mult}} &\iff (l_{\text{base}} \le l_u \wedge u_u \le u_{\text{base}}) \\
\Phi_{\text{env}} &\iff (v_{\text{default}}(u) \ne \bot \implies v_{\text{default}}(u) \in \text{Domain}(\tau(u_{\text{base}}))) \\
\Phi_{\text{dir}} &\iff (\delta(u_{\text{base}}) \ne \text{None} \implies \delta(u) = \delta(u_{\text{base}}))
\end{aligned}
```

Diagnostic Code Binding Invariant:

```math
\begin{aligned}
(\tau(u) = \bot) \vee \neg \text{ConformsTo}(u, C_{\text{target}}) \vee \neg \text{ValidRedef}(u, u_{\text{base}}) \implies \text{Diagnostic}(u, \text{DiagnosticCode::E0200}) \in \mathcal{D}_{\text{sink}}
\end{aligned}
```

## 3. Computational Complexity & Algorithmic Bounds

The classifier typing and feature usage resolution engine executes strictly within Complexity Class $`\mathbf{P}`$. Type resolution executes in $`O(1)`$ amortized time via interned symbol handles and scoped hash tables. Subtyping reachability queries ($``\tau(u) \le C_{\text{target}}``$) evaluate in $`O(1)`$ time via bitset masks or bounded tree traversal in $`O(h)`$ with inheritance depth $`h \le 32`$. Multiplicity and direction checks execute in $`O(1)`$ scalar operations. Total typing verification across $`|\mathcal{U}|`$ usages requires $`O(|\mathcal{U}| \cdot h) = O(|\mathcal{U}|)`$ linear time and $`O(|\mathcal{C}| + |\mathcal{U}|)`$ arena storage.

NP Frontier Reference: While general poset subtyping can be NP-complete (NP-3, REQ-0061--REQ-0063), monotonic covariance over single/acyclic inheritance hierarchies is solvable deterministically in $`O(V + E)`$ without backtracking.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Disjoint Duality Partition Enforcement

- **Given:** An input AST containing structural definitions and usages within `Package_0`.
- **When:** The compiler lowers nodes into core AST arena structures.
- **Then:** Every structural node is partitioned into $`\mathcal{C}`$ or $`\mathcal{U}`$ such that $`\mathcal{C} \cap \mathcal{U} = \emptyset`$; instantiating a definition directly as a bare usage fails compilation.
- **Diagnostic:** `E0200` emitted on structural definition-usage partition violation.

### AC-02: Authoritative Classifier Typing Resolution

- **Given:** A classifier definition `Classifier_Alpha` and feature usages `Usage_1 : Classifier_Alpha` and `Usage_2 : Classifier_Alpha`.
- **When:** The type checker executes symbol typing pass $`\tau : \mathcal{U} \longrightarrow \mathcal{C}`$.
- **Then:** 100% of feature usages resolve to the arena handle of `Classifier_Alpha` with zero diagnostics emitted.
- **Diagnostic:** `E0200` emitted if a feature usage contains an unresolved classifier reference or lacks a type binding.

### AC-03: Subtyping Conformance Verification

- **Given:** `Classifier_Beta` specializing `Classifier_Alpha` (`Classifier_Beta :> Classifier_Alpha`) and feature usage `Usage_Sub : Classifier_Beta`.
- **When:** `Usage_Sub` is assigned to an interface slot, parameter, or port expecting `Classifier_Alpha`.
- **Then:** The type checker evaluates $``\text{ConformsTo}(\text{Usage\_Sub}, \text{Classifier\_Alpha}) = \text{true}``$ because $``\tau(\text{Usage\_Sub}) \le \text{Classifier\_Alpha}``$, accepting the binding.
- **Diagnostic:** `E0200` emitted if an incompatible classifier type `Classifier_Gamma` ($``\text{Classifier\_Gamma} \not\le \text{Classifier\_Alpha}``$) is bound to the target slot.

### AC-04: Monotonic Covariance in Multiplicity Narrowing

- **Given:** `Classifier_Alpha` declaring feature `Feature_A` with multiplicity interval $`[0, 10]`$.
- **When:** A specializing classifier or usage redefines `Feature_A` with narrowed interval $`[1, 5]`$.
- **Then:** The compiler verifies $`[1, 5] \subseteq [0, 10]`$ and accepts the redefinition; redefining with widened interval $`[0, 20]`$ fails compilation.
- **Diagnostic:** `E0200` emitted on non-monotonic multiplicity interval widening.
