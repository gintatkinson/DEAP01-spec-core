## 1. Normative Statement

The compiler ingestion engine shall compute, record, verify, and persist a multi-file cryptographic manifest recording SHA-256 content hashes, byte sizes, line counts, and AST entity counts for all workspace schema input files and the emitted canonical model (`schema/model.sysml`). The manifest shall be serialized as a canonical JSON document and written atomically to `.pipeline/schema-digest.json`.

For each schema input file ($``F_{i} \in \mathcal{F}_{\text{inputs}}``$) and `schema/model.sysml`, the engine shall compute a 5-tuple digest record: normalized workspace-relative path ($``P_{i}``$), 64-character lowercase hexadecimal SHA-256 hash ($``H_{i}``$), exact 64-bit byte size ($``S_{i}``$), line break count ($``L_{i}``$), and synthesized AST entity count ($``N_{i}``$).

The manifest shall be written to `.pipeline/schema-digest.json.tmp.<pid>`, flushed via `fsync`, and atomically renamed to `.pipeline/schema-digest.json`.

On subsequent compilation, if all live input file digests match `.pipeline/schema-digest.json`, the engine shall register a cache hit, skip parsing and lowering, reuse the cached model, and bypass re-emission of `schema/model.sysml`. Any modified, added, or deleted input file, or corrupted manifest, triggers a cache miss and complete manifest regeneration.

## 2. Formal Invariant

Let $``\mathcal{F}_{\text{manifest}} = \mathcal{F}_{\text{inputs}} \cup \{ \text{"schema/model.sysml"} \}``$ denote the tracked file set where $``\mathcal{F}_{\text{inputs}} = \{ F_{1}, \dots, F_{K} \}``$. For each file $``F_{i} \in \mathcal{F}_{\text{manifest}}``$, its digest tuple is:

```math
\text{Digest}(F_{i}) = \langle P_{i}, H_{i}, S_{i}, L_{i}, N_{i} \rangle
```

where:

```math
\begin{aligned}
P_{i} &= \text{RelPath}(F_{i}, \text{Root}_{\text{ws}}) \in \mathcal{P}_{\text{rel}} \\
H_{i} &= \text{Hex}(\text{SHA256}(F_{i})) \in \Sigma_{\text{hex}}^{64} \\
S_{i} &= |F_{i}| \in \mathbb{N}_{0} \\
L_{i} &= \text{Lines}(F_{i}) \in \mathbb{N}_{0} \\
N_{i} &= |\text{Entities}(F_{i})| \in \mathbb{N}_{0}
\end{aligned}
```

Deterministic Lexicographical Order Invariant:

```math
\forall i \in \{1, \dots, |\mathcal{F}_{\text{manifest}}| - 1\}, \quad P_{i} \prec_{\text{lex}} P_{i+1}
```

Composite Root Hash Invariant:

```math
\mathcal{H}_{\text{root}} = \text{Hex}\left( \text{SHA256}\left( \bigoplus_{i=1}^{|\mathcal{F}_{\text{manifest}}|} \left( P_{i} \mathbin{\Vert} \text{SYM}_{\text{DELIM}} \mathbin{\Vert} H_{i} \mathbin{\Vert} \text{SYM}_{\text{DELIM}} \mathbin{\Vert} \text{Dec}(S_{i}) \mathbin{\Vert} \text{SYM}_{\text{DELIM}} \mathbin{\Vert} \text{Dec}(L_{i}) \mathbin{\Vert} \text{SYM}_{\text{DELIM}} \mathbin{\Vert} \text{Dec}(N_{i}) \mathbin{\Vert} \text{SYM}_{\text{LF}} \right) \right) \right)
```

Deterministic Manifest UUIDv5 Invariant:

```math
\text{UUID}_{\text{manifest}} = \text{UUIDv5}(\text{NS}_{\text{DEAP}}, \mathcal{H}_{\text{root}})
```

Atomic Persistence Invariant:

```math
\text{PersistManifest}(\mathcal{J}) \implies \text{Write}(\text{TmpPath}, \mathcal{J}) \;\wedge\; \text{FSync}(\text{TmpPath}) \;\wedge\; \text{AtomicRename}(\text{TmpPath}, \text{".pipeline/schema-digest.json"})
```

Manifest Cache Invalidation and Reuse Invariant:

```math
\Psi_{\text{cache}}(\mathcal{M}_{\text{cached}}, \mathcal{M}_{\text{active}}) \iff \left( \mathcal{M}_{\text{cached}}.\text{composite\_hash} = \mathcal{M}_{\text{active}}.\text{composite\_hash} \;\wedge\; |\mathcal{M}_{\text{cached}}.\text{entries}| = |\mathcal{M}_{\text{active}}.\text{entries}| \right)
```

```math
\Psi_{\text{cache}}(\mathcal{M}_{\text{cached}}, \mathcal{M}_{\text{active}}) \implies \text{ReuseCachedModel}() \;\wedge\; \text{BypassModelEmission}()
```

Diagnostic Code Binding Invariant:

```math
\begin{aligned}
\text{IOError}(F_{i}) &\implies \text{Diagnostic}(P_{i}, \text{E0100}) \in \mathcal{D} \\
\text{MalformedJSON}(\mathcal{J}_{\text{disk}}) &\implies \text{Diagnostic}(\text{".pipeline/schema-digest.json"}, \text{E0102}) \in \mathcal{D}
\end{aligned}
```

## 3. Computational Complexity & Algorithmic Bounds

The multi-file cryptographic digest engine operates strictly within Complexity Class $`\mathbf{P}`$. For $``K = |\mathcal{F}_{\text{manifest}}|``$ tracked files with aggregate byte size $``B = \sum_{i=1}^K |F_{i}|``$, SHA-256 digest and line computations execute in $`O(B)`$ linear time via a single streaming pass. Lexicographical sorting of $`K`$ path descriptors of bounded length $``L_{\max} \le 1024``$ executes in $``O(K \log K \cdot L_{\max}) = O(K \log K)``$ operations. Manifest serialization and composite hashing execute in $`O(K)`$ time. Total sequential runtime is strictly $`O(B + K \log K) = O(B)`$ deterministic linear time in input byte size $`B`$ (since $`K \log K \ll B`$)., parallel wall-clock runtime scales as $``O(B / N_{\text{max\_workers}} + \max_{i} |F_{i}| + K \log K)``$. Auxiliary space is bounded by $`O(K)`$ for manifest records in AST storage and $`O(1)`$ streaming state per thread. The pipeline performs zero combinatorial search, bypassing NP-complete frontiers (NP-1 through NP-8) and ensuring polynomial termination.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Multi-File Digest Manifest Generation & Content Invariants
- **Given:** A workspace with input schemas (`schema/Table_0.md`, `schema/Schema_1.proto`, `schema/Interface_2.idl`) defining generic elements (`Package_0`, `Classifier_Alpha`, `Port_1`, `Flow_A`, `param_x : Real`) and emitted `schema/model.sysml`.
- **When:** The compiler executes schema ingestion and manifest generation.
- **Then:** `.pipeline/schema-digest.json` is generated containing a 5-tuple record for every file with matching SHA-256 hex string, exact byte count, line count, and AST entity count.
- **Diagnostic:** `E0100` emitted if any file cannot be read or hashing fails.

### AC-02: Deterministic Lexicographical Sorting & Diff Invariance
- **Given:** Input schema files discovered across varying filesystem traversal orders.
- **When:** Manifest generation evaluates entry order and composite hash $``\mathcal{H}_{\text{root}}``$.
- **Then:** Entries are sorted strictly by ascending ASCII path ($``P_{i} \prec_{\text{lex}} P_{i+1}``$), producing identical composite hashes and 0-byte diff churn across repeated runs.
- **Diagnostic:** `E0100` emitted on determinism failure or sorting inconsistency.

### AC-03: Single-Byte Invalidation & Cache Model Reuse
- **Given:** A cached `.pipeline/schema-digest.json` file and subsequent compiler invocation.
- **When:** Live workspace digests are compared against the cached manifest ($``\Psi_{\text{cache}}``$).
- **Then:** Identical inputs reuse the pre-compiled AST and bypass re-emission of `schema/model.sysml`; modifying a single byte invalidates the cache and triggers full recompilation.
- **Diagnostic:** None emitted on valid cache hit or normal recompilation.

### AC-04: Atomic Staging & Crash-Consistent Persistence
- **Given:** An active manifest write targeting `.pipeline/schema-digest.json`.
- **When:** The engine serializes the manifest document to disk.
- **Then:** Content is written to `.pipeline/schema-digest.json.tmp.<pid>`, flushed with `fsync`, and atomically renamed to `.pipeline/schema-digest.json`, preventing corrupted or partial file states.
- **Diagnostic:** `E0100` emitted on filesystem write permission failure or disk saturation.
