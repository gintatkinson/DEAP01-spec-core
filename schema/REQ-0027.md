## 1. Normative Statement

The compiler ingestion engine shall provide a native Protocol Buffer version 3 (Proto3) parser that ingests `.proto` schemas into intermediate schema representation (IR) without external toolchain dependencies. The engine shall lower Protobuf messages to `IngestedPart` definitions, fields to typed `IngestedAttr` properties, service RPCs to `IngestedAction` operations, and enums to `IngestedClassifierDef` data types.

Field declarations shall preserve names, types, tags $`i`$, and multiplicity intervals $``\langle l, u \rangle \in \mathbb{N}_0 \times (\mathbb{N}_0 \cup \{\infty\})``$, mapping \texttt{repeated} to $`\langle 0, \infty \rangle`$, \texttt{optional} to $`\langle 0, 1 \rangle`$, and singular fields to $`\langle 1, 1 \rangle`$. Declared field tags must satisfy validity invariant $`i \in [1, 2^{29}-1] \setminus [19000, 19999]`$ ($`2^{29}-1 = 536{,}870{,}911`$); tags $`i \le 0`$, $`i \gt 2^{29}-1`$, or $`i \in [19000, 19999]`$ shall emit diagnostic `E0103`. Duplicate field tags within a message shall trigger diagnostic `E0102`.

Proto3 enums must bind tag 0 to the first enumerator; missing tag 0 shall emit diagnostic `E0103`. Nested messages shall recursively lower to child classifiers scoped under the parent message package. Service RPCs shall synthesize `IngestedAction` operations with ordered input and output parameters, mapping \texttt{stream} qualifiers to multiplicity $`\langle 0, \infty \rangle`$ and unary parameters to $`\langle 1, 1 \rangle`$.

## 2. Formal Invariant

Let $``\mathcal{P}_{\text{proto}}``$ denote a parsed Protocol Buffer unit:

```math
\mathcal{P}_{\text{proto}} = \langle \mathcal{H}_{\text{syntax}}, \mathcal{N}_{\text{pkg}}, \mathcal{I}_{\text{imp}}, \mathcal{M}, \mathcal{E}, \mathcal{S} \rangle
```

where $``\mathcal{H}_{\text{syntax}} \in \{ \text{"proto3"} \}``$, package $``\mathcal{N}_{\text{pkg}}``$, imports $``\mathcal{I}_{\text{imp}}``$, messages $`\mathcal{M}`$, enums $`\mathcal{E}`$, and services $`\mathcal{S}`$.

The lowering transformation $``\mathcal{T}_{\text{proto}}``$ maps AST declarations into schema IR:

```math
\begin{aligned}
\text{message } M \{ \dots \} &\longmapsto \text{IngestedPart}(M) \\
\text{field } T \, f = i &\longmapsto \text{IngestedAttr}(f, \text{type}: T, \text{tag}: i, \text{mult}: \mu(f)) \\
\text{rpc } R(A) \text{ returns } (B) &\longmapsto \text{IngestedAction}(R, \text{in}: [\langle \text{param}_{\text{in}}, A, \mu_{\text{req}} \rangle], \text{out}: [\langle \text{param}_{\text{out}}, B, \mu_{\text{resp}} \rangle]) \\
\text{enum } E \{ \dots \} &\longmapsto \text{IngestedClassifierDef}(E, \text{kind}: \text{Enum})
\end{aligned}
```

Multiplicity mapping $`\mu(f)`$ satisfies:

```math
\mu(f) = \begin{cases}
\langle 0, \infty \rangle, & \text{if } f \text{ is \texttt{repeated}} \\
\langle 0, 1 \rangle, & \text{if } f \text{ is \texttt{optional}} \\
\langle 1, 1 \rangle, & \text{otherwise}
\end{cases}
```

Field tag validity, uniqueness, enum defaults, and nested message scoping satisfy:

```math
\begin{aligned}
\forall M \in \mathcal{M}, \forall f \in \text{Fields}(M): &\quad \text{Tag}(f) \in [1, 2^{29}-1] \setminus [19000, 19999] \\
\forall M \in \mathcal{M}, \forall f_1 \ne f_2 \in \text{Fields}(M): &\quad \text{Tag}(f_1) \ne \text{Tag}(f_2) \\
\forall E \in \mathcal{E}: &\quad \exists v_0 \in \text{Values}(E) : (\text{Index}(v_0) = 0 \wedge \text{Tag}(v_0) = 0) \\
\forall M_{\text{child}} \in \text{NestedMessages}(M_{\text{parent}}): &\quad \text{FQP}(M_{\text{child}}) = \text{FQP}(M_{\text{parent}}) \mathbin{::} \text{Name}(M_{\text{child}})
\end{aligned}
```

Diagnostic bindings per REQ-0191 satisfy:

```math
\begin{aligned}
\text{Tag}(f) \notin [1, 2^{29}-1] \setminus [19000, 19999] &\implies \text{Diagnostic}(f, \text{DiagnosticCode::E0103}) \in \mathcal{D} \\
(\exists f_1 \ne f_2 \in \text{Fields}(M) : \text{Tag}(f_1) = \text{Tag}(f_2)) &\implies \text{Diagnostic}(f_2, \text{DiagnosticCode::E0102}) \in \mathcal{D} \\
(\text{Index}(v_0) = 0 \wedge \text{Tag}(v_0) \ne 0) &\implies \text{Diagnostic}(E, \text{DiagnosticCode::E0103}) \in \mathcal{D} \\
(\mathcal{H}_{\text{syntax}} \ne \text{"proto3"} \vee \text{SyntaxFault}(\text{span})) &\implies \text{Diagnostic}(\text{span}, \text{DiagnosticCode::E0100}) \in \mathcal{D}
\end{aligned}
```

## 3. Computational Complexity & Algorithmic Bounds

The Proto3 AST ingestion engine executes in Complexity Class $`\mathbf{P}`$. Monotonic single-pass lexing and recursive descent parsing run in deterministic $`O(N)`$ linear time over $`N`$ input bytes using LL(1) lookahead. Identifier interning operates in $`O(1)`$ amortized time. Field tag validation per message with $`F`$ fields uses a dense bitset in $`O(F)`$ time, bounding aggregate validation across all messages by $`O(\sum F) \le O(N)`$. AST memory node allocation executes in $`O(1)`$ constant time. Message nesting recursion depth is bounded by $`D \le 64`$, requiring $`O(1)`$ auxiliary stack space. Parallel compilation across $`K`$ schemas on a bounded work-stealing pool ($``N_{\text{max\_workers}}``$) runs in $``O(\lceil K / N_{\text{max\_workers}} \rceil \cdot N_{\text{max}})``$ time. Deterministic linear parsing operates strictly in polynomial time, bypassing combinatorial NP-complete frontiers (NP-1--NP-8).

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Canonical Message and Field Lowering
- **Given:** Valid Proto3 schema with message `Message_Alpha`, fields (`Field_1 : int32 = 1`, `Field_2 : string = 2`, `Field_3 : Message_Beta = 3`), and multiplicity qualifiers (\texttt{repeated}, \texttt{optional}, singular).
- **When:** Lowering the AST into intermediate schema IR.
- **Then:** Emits `IngestedPart` and `IngestedAttr` with exact types, tags, and multiplicities ($`\langle 0, \infty \rangle`$, $`\langle 0, 1 \rangle`$, $`\langle 1, 1 \rangle`$) without diagnostics.
- **Diagnostic:** `E0100` on parsing failure.

### AC-02: Field Tag Range and Reserved Boundary Enforcement
- **Given:** Proto3 messages with field tags at boundaries ($`i = 1`$, $`i = 536{,}870{,}911`$), out-of-range ($`i = 0`$, $`i = 536{,}870{,}912`$), or in reserved range ($`i \in [19000, 19999]`$).
- **When:** Evaluating field tag validity during ingestion.
- **Then:** Boundary tags lower cleanly; invalid tags ($`i \le 0`$, $`i \gt 2^{29}-1`$, or $`i \in [19000, 19999]`$) emit structured diagnostics.
- **Diagnostic:** `E0103` on invalid field tags.

### AC-03: Duplicate Field Tag Collision Detection
- **Given:** Message `Message_Alpha` declaring fields `Field_1` and `Field_2` both with tag $`i = 5`$.
- **When:** Ingesting field declarations within `Message_Alpha`.
- **Then:** Detects tag collision, logs structured diagnostic, and substitutes sentinel $``\bot_{\text{field}}``$.
- **Diagnostic:** `E0102` on duplicate field tag collision.

### AC-04: Enum Tag-Zero Default and Nested Scope Resolution
- **Given:** Enum `Enum_0` with first constant at tag 1, and parent message `Message_Alpha` declaring inner message `Message_Beta`.
- **When:** Ingesting enum definitions and resolving nested scopes.
- **Then:** Rejects `Enum_0` for missing tag-0 default, and resolves `Message_Beta` to path `Package_0::Message_Alpha::Message_Beta`.
- **Diagnostic:** `E0103` on missing tag-0 default; `E0100` on scope failure.
