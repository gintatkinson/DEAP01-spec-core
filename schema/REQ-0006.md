## 1. Normative Statement

The compiler platform shall maintain fine-grained dependency tracking across all modular compilation units within an explicit compilation unit dependency directed acyclic graph (DAG). The incremental compilation subsystem must compute deterministic cryptographic content digests for each input compilation unit upon ingestion. When input schema compilation units are modified, added, or removed, the compiler shall identify the mutated seed set $`M`$ and compute the exact forward reachability closure across the dependency DAG.

The compiler must invalidate and recompute strictly the AST subgraphs, symbol tables, and lowering artifacts belonging to this transitively affected closure. All unaffected compilation units outside the transitive invalidation set shall be reused directly from the compiler AST cache without disk re-reads, re-lexing, or re-parsing. The synthesized composite AST resulting from incremental recomputation shall be bitwise and structurally equivalent to the AST produced by clean compilation from scratch, exhibiting zero diff churn in emitted Merkle roots. If an unresolvable dependency cycle, invalidation fault, or corrupted cache record occurs, the compiler shall reject the invalid state, invalidate the affected cache partition, and emit diagnostic error code `E0100` detailing the affected unit identifier, dependency coordinates, and source byte spans.

## 2. Formal Invariant

Let $`G = (V, E)`$ be the compilation unit dependency DAG, where each vertex $`v \in V`$ represents a compilation unit and directed edge $`(u, v) \in E`$ denotes that unit $`v`$ directly depends on unit $`u`$. Let $`\mathcal{H} : \text{Unit} \to \{0, 1\}^{256}`$ be a deterministic cryptographic hash function. For modified units, the mutated seed set $`M \subseteq V`$ is:

```math
M = \{ u \in V \mid \mathcal{H}(u) \neq \mathcal{H}_{\text{cached}}(u) \}
```

The transitive invalidation closure $`\text{Invalidated}(M) \subseteq V`$ is the forward reachability set:

```math
\text{Invalidated}(M) = \{ v \in V \mid \exists u \in M, \; u \to^* v \}
```

where $`u \to^* v`$ represents a reflexive-transitive directed path in $`G`$.

For every unimpacted unit $`w \in V \setminus \text{Invalidated}(M)`$, parsing and cache lookup cost satisfy:

```math
\forall w \in V \setminus \text{Invalidated}(M), \quad T_{\text{parse}}(w) = 0 \quad \land \quad T_{\text{compile}}(w) \in O(1)
```

Cache Semantic Equivalence and Graph Invariants: let $``\mathcal{A}_{\text{inc}}``$ denote the composite AST from incremental compilation and $``\mathcal{A}_{\text{full}}``$ denote the AST synthesized from clean compilation:

```math
\begin{aligned}
\mathcal{A}_{\text{inc}} &\equiv \mathcal{A}_{\text{full}} \\
\forall w \in V \setminus \text{Invalidated}(M), \quad \text{AST}_{\text{cached}}(w) &\equiv \text{AST}_{\text{full}}(w) \\
\forall v \in \text{Invalidated}(M), \quad \text{AST}_{\text{recomputed}}(v) &\equiv \text{AST}_{\text{full}}(v) \\
\text{MerkleRoot}(\mathcal{A}_{\text{inc}}) &= \text{MerkleRoot}(\mathcal{A}_{\text{full}}) \\
\forall v \in V, \quad \neg (v &\to^+ v)
\end{aligned}
```

## 3. Computational Complexity & Algorithmic Bounds

The incremental dependency tracking and invalidation pipeline executes within Complexity Class $`\mathbf{P}`$. Forward reachability closure computation for $`\text{Invalidated}(M)`$ over DAG $`G = (V, E)`$ executes in deterministic linear time $`O(|V| + |E|)`$ via breadth-first search or topological order traversal. Cache lookup and reuse for unimpacted units execute in $`O(1)`$ amortized time per unit. Incremental AST recomputation scales strictly as $``O(N_{\text{inv}})``$ time, where $``N_{\text{inv}} = \sum_{v \in \text{Invalidated}(M)} |\text{Tokens}(v)| \le N``$, with $`N`$ denoting total model tokens. Peak auxiliary memory for the dependency DAG and cache structures is bounded by $`O(|V| + |E|)`$. Unlike downstream NP-hard scheduling (NP-7 in REQ-0180) or allocation problems (NP-2 in REQ-0147), DAG invalidation closure belongs strictly to deterministic polynomial time $`\mathbf{P}`$.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Leaf Compilation Unit Mutation and Transitive Invalidation
- **Given:** Multi-unit model in `Package_0` comprising `CompilationUnit_Alpha`, `CompilationUnit_Beta`, and `CompilationUnit_Gamma` with dependency path $`\text{Alpha} \to \text{Beta} \to \text{Gamma}`$, with all units cached in the compiler AST cache.
- **When:** Leaf unit `CompilationUnit_Gamma` content digest changes and incremental compilation executes.
- **Then:** The compiler marks strictly $``\text{Invalidated}(M) = \{ \text{CompilationUnit\_Gamma} \}``$, re-parses only `CompilationUnit_Gamma`, reuses cached AST nodes for `CompilationUnit_Alpha` and `CompilationUnit_Beta` ($``T_{\text{parse}} = 0``$), and emits composite AST $``\mathcal{A}_{\text{inc}}``$ where $``\text{MerkleRoot}(\mathcal{A}_{\text{inc}}) = \text{MerkleRoot}(\mathcal{A}_{\text{full}})``$.
- **Diagnostic:** `E0100` on redundant re-parsing of unaffected units or AST parity mismatch.

### AC-02: Root Dependency Mutation and Full Forward Closure Propagation
- **Given:** Multi-unit DAG $`G = (V, E)`$ with root unit `CompilationUnit_Alpha` and dependents `CompilationUnit_Beta` and `CompilationUnit_Gamma`.
- **When:** Root unit `CompilationUnit_Alpha` content digest changes and incremental compilation executes.
- **Then:** Forward reachability identifies $``\text{Invalidated}(M) = \{ \text{CompilationUnit\_Alpha}, \text{CompilationUnit\_Beta}, \text{CompilationUnit\_Gamma} \}``$, recomputing all three units, updating cache records, and emitting AST $``\mathcal{A}_{\text{inc}} \equiv \mathcal{A}_{\text{full}}``$.
- **Diagnostic:** `E0100` if any transitively dependent unit is omitted from invalidation.

### AC-03: Dependency Cycle Detection and Invalidation Fault Rejection
- **Given:** An incremental edit introducing a cyclic dependency $`u \to^+ u`$ (e.g., `CompilationUnit_Alpha` imports `CompilationUnit_Gamma`).
- **When:** The compiler executes dependency DAG update and cycle detection.
- **Then:** The compiler detects non-acyclicity, aborts AST merge, invalidates affected cache entries, and emits diagnostic error code `E0100` detailing circular path coordinates and affected unit identifiers without panicking.
- **Diagnostic:** `E0100` (Cyclic dependency detected in compilation unit DAG).

### AC-04: Corrupted Cache Record Invalidation and Fallback Recovery
- **Given:** An AST cache state where the cached entry for `CompilationUnit_Beta` is missing or fails hash integrity verification.
- **When:** Incremental compilation queries the cache during dependency resolution.
- **Then:** The compiler detects cache inconsistency, discards corrupted entries for `CompilationUnit_Beta` and its dependents, recomputes the affected subgraph from source, updates cache records, and emits valid AST $``\mathcal{A}_{\text{inc}} \equiv \mathcal{A}_{\text{full}}``$.
- **Diagnostic:** `E0100` on unhandled cache read faults or unverified AST emission.
