## 1. Normative Statement

The compiler SHALL lower SysML v2 action definitions (`action def`, `ActionDefinition`) as process classifiers specializing KerML `Behavior` and `OccurrenceDefinition`, and action usages (`action`, `ActionUsage`) as discrete steps specializing KerML `Step` and `OccurrenceUsage`.

The lowering engine MUST enforce five core invariants:
1. **Parameter Directionality**: Parameters declare $\delta(p) \in \{ \text{In}, \text{Out}, \text{InOut} \}$. Flow edges $``e_{\text{data}}``$ MUST connect `Out`/`InOut` to `In`/`InOut` pins; invalid polarities emit `E0201`.
2. **Payload Subtyping & Multiplicity**: Source payload MUST specialize target type ($``\tau(p_{\text{src}}) \le \tau(p_{\text{tgt}})``$) and source multiplicity MUST NOT exceed target bound ($``\mu(p_{\text{src}}).m_{\max} \le \mu(p_{\text{tgt}}).m_{\max}``$); violations emit `E0202`.
3. **Control Topology**: Control nodes $``V_{\text{ctrl}}``$ in $``G_{\text{flow}}``$ MUST satisfy degree bounds: initial ($0, 1$), final ($\ge 1, 0$), fork/decision ($1, \ge 2$), and join/merge ($\ge 2, 1$); violations emit `E0200`.
4. **Step Lifecycle**: Steps satisfy $\text{State}(s) \in \{ \text{Waiting}, \text{Ready}, \text{Executing}, \text{Completed} \}$, transitioning to `Ready` when incoming control tokens and data inputs arrive.
5. **Dependency Acyclicity**: Step dependency graph $``G_{\text{dep}}``$ MUST be a DAG; cycles emit `E0203`.

## 2. Formal Invariant

Metamodel specialization, data flow, step readiness, and dependency acyclicity invariants:

```math
\begin{aligned}
\text{ActionDef} &\le \text{Behavior} \le \text{OccurrenceDef}, \quad \text{ActionUsage} \le \text{Step} \le \text{OccurrenceUsage} \\
\forall (u, p_1, v, p_2) \in E_{\text{data}}, \quad &\delta(p_1) \in \{ \text{Out}, \text{InOut} \} \wedge \delta(p_2) \in \{ \text{In}, \text{InOut} \} \wedge \tau(p_1) \le \tau(p_2) \\
\text{Ready}(s) \iff &(\forall (u, s) \in E_{\text{ctrl}}, \, \text{Token}(u, s) = 1) \wedge (\forall (u, p_1, s, p_2) \in E_{\text{data}}, \, \text{Bound}(p_2) = 1) \\
\forall v \in V_{\text{steps}}, \quad &(v, v) \notin E_{\text{dep}}^+, \quad \forall n \in \mathcal{D}_{\text{action}} \cup \mathcal{U}_{\text{action}}, \quad \Delta_n = \text{UUIDv5}(\text{NS}_{\text{DEAP}}, \text{FQN}(n))
\end{aligned}
```

| Symbol / Term | Domain / Formal Definition |
| :--- | :--- |
| $``\mathcal{D}_{\text{action}}, \mathcal{U}_{\text{action}}``$ | Action definitions and step usages arena records |
| $``G_{\text{flow}}, E_{\text{dep}}``$ | Workflow multigraph and unified step dependency edges |
| $\delta(p), \tau(p), \mu(p)$ | Parameter directionality, type, and multiplicity interval |
| $``\Delta_n``$ | Deterministic RFC 4122 UUIDv5 hash from $``\text{NS}_{\text{DEAP}}``$ and FQN |

## 3. Computational Complexity & Algorithmic Bounds

Action lowering and verification execute strictly within Complexity Class $\mathbf{P}$.

For action definition with $``V = |V_{\text{steps}}| + |V_{\text{ctrl}}|``$ nodes and $``E = |E_{\text{ctrl}}| + |E_{\text{data}}|``$ edges:
- Node allocation and symbol interning execute in amortized $O(1)$ time per element ($O(V)$).
- Parameter directionality and subtyping evaluate in $O(1)$ checks via precomputed bitsets (NP-3 fragment).
- Control degree checking traverses incident edges in $``O(|V_{\text{ctrl}}| + |E_{\text{ctrl}}|)``$ time.
- Dependency acyclicity evaluates in deterministic $O(V + E)$ time using Kahn's algorithm or Tarjan's SCC.

Total sequential complexity is $O(V + E)$. Parallel package lowering scales as $``O((V + E) / N_{\text{max\_workers}} + \log N_{\text{max\_workers}})``$. While concurrent reachability across orthogonal regions is PSPACE/NP-complete (NP-5 in REQ-0124), structured DAG workflows ensure polynomial tractability.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Canonical Action Definition and Step Lowering
- **Given:** Valid `action def ActionDef_Alpha` with steps `action Step_Alpha : ActionDef_Beta` and `action Step_Beta : ActionDef_Gamma`.
- **When:** Lowering constructs the action workflow AST.
- **Then:** Nodes are lowered into arena storage with dual KerML specializations (`Behavior`, `Step`) and zero diagnostics.
- **Diagnostic:** Diagnostic sink remains empty.

### AC-02: Conflicting Parameter Directionality Rejection
- **Given:** Action workflow binding input pin `in param_in : Real` as data source or output pin `out param_out : Real` as target.
- **When:** Data flow parameter polarity validation executes.
- **Then:** Compiler rejects inverted bindings with sentinel $``\bot_{\text{action}}``$ and diagnostic `E0201`.
- **Diagnostic:** `E0201` (Parameter direction mismatch).

### AC-03: Data Flow Payload Subtyping and Multiplicity Overflow
- **Given:** Data flow binding output of type `Classifier_Alpha` to incompatible input `Classifier_Beta`, or exceeding target multiplicity.
- **When:** Type and multiplicity conformance checking executes.
- **Then:** Compiler rejects incompatible edge and emits diagnostic `E0202`.
- **Diagnostic:** `E0202` (Payload type mismatch or multiplicity overflow).

### AC-04: Control Node Degree Topology Violation
- **Given:** Action definition with malformed control node (e.g., fork with in-degree 2 or join with out-degree 2).
- **When:** Control node degree validation executes.
- **Then:** Compiler rejects malformed topology with source spans and diagnostic `E0200`.
- **Diagnostic:** `E0200` (Malformed control topology).
