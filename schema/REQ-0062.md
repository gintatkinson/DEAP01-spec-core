## 1. Normative Statement

The metamodel lowering engine shall formalize the KerML and SysML v2 feature redefinition relationship (`:>>`, `redefines`) as contextual slot replacement over multiple inheritance directed acyclic graphs (DAGs), enforcing monotonic C3 superclass linearization, subtyping conformance, and multiplicity interval tightening within the bounded meet-semilattice $`(\text{Types}, \le)`$.

When specializing classifier $`C`$ declares feature $``f_{\text{redef}}``$ redefining inherited feature $``f_{\text{orig}}``$ ($``f_{\text{redef}} :>> f_{\text{orig}}``$), the compiler shall enforce:
1. **Contextual Slot Replacement**: $``f_{\text{redef}}``$ shall shadow and replace $``f_{\text{orig}}``$ in $`C`$ and its specializations. References targeting $``f_{\text{orig}}``$ in scope $`C`$ shall resolve directly to $``f_{\text{redef}}``$.
2. **Monotonic C3 Linearization (NP-3)**: Precedence for $`C`$ with direct parents $``P_1, \dots, P_n``$ shall be computed deterministically via C3 linearization. Conflicting precedence orders shall trigger diagnostic error code `E0200`.
3. **Subtyping Conformance**: Redefining type $``\tau(f_{\text{redef}})``$ must co-vary with $``\tau(f_{\text{orig}})``$ ($``\tau(f_{\text{redef}}) \le \tau(f_{\text{orig}})``$). Incompatible types shall trigger diagnostic error code `E0200`.
4. **Multiplicity Interval Tightening**: Multiplicity $``\mu(f_{\text{redef}})``$ must be a sub-interval of $``\mu(f_{\text{orig}})``$ ($``[l_{\text{redef}}, u_{\text{redef}}] \subseteq [l_{\text{orig}}, u_{\text{orig}}]``$). Interval widening shall trigger diagnostic error code `E0200`.
5. **Structural & Directional Invariance**: Directed features shall preserve directional polarity ($``\delta(f_{\text{redef}}) = \delta(f_{\text{orig}})``$) unless conjugated (`~`) per REQ-0063. Direction inversion shall trigger diagnostic error code `E0200`. Ordering and uniqueness flags must be preserved or strengthened.
6. **Acyclicity Enforcement**: Circular redefinitions ($``f_1 :>> f_2 :>> \dots :>> f_1``$) shall be rejected with diagnostic error code `E0203`.
7. **Disambiguation**: Converging inherited redefinitions without C3 ancestor precedence require explicit redefinition in $`C`$; absence shall trigger diagnostic error code `E0200`.
8. **Recovery & Storage**: Violations shall record diagnostics, bind error sentinel $``\bot_{\text{redef}}``$, and continue compilation without panic. AST nodes shall use typed arena handles with interned symbols and RFC 4122 UUIDv5 identifiers.

## 2. Formal Invariant

Let $`\mathcal{C}`$ denote classifier definitions and $`\mathcal{F}`$ denote feature usages. Each feature $`f \in \mathcal{F}`$ is defined as a tuple:

```math
f = \langle \text{id}_f, \text{name}_f, \text{owner}_f, \tau(f), \mu(f), \delta(f), \text{ord}(f), \text{uniq}(f), \mathcal{R}_f \rangle
```

where $`\tau(f) \in \mathcal{C}`$, $``\mu(f) = [l_f, u_f] \subseteq \mathbb{N}_0 \cup \{ \infty \}``$, $`\delta(f) \in \{ \text{In}, \text{Out}, \text{InOut}, \text{None} \}`$, and $``\mathcal{R}_f \subseteq \mathcal{F}``$ is the set of directly redefined features.

Monotonic C3 Linearization Invariant:

```math
\text{C3}(C) = [C] \mathbin{\Vert} \text{merge}(\text{C3}(P_1), \dots, \text{C3}(P_n), [P_1, \dots, P_n])
```

Feature Redefinition Conformance Invariant:

```math
\begin{aligned}
\tau(f_{\text{redef}}) &\le \tau(f_{\text{orig}}) \iff \tau(f_{\text{redef}}) \wedge \tau(f_{\text{orig}}) = \tau(f_{\text{redef}}) \\
\mu(f_{\text{redef}}) &\subseteq \mu(f_{\text{orig}}) \iff (l_{\text{orig}} \le l_{\text{redef}} \;\wedge\; u_{\text{redef}} \le u_{\text{orig}}) \\
\delta(f_{\text{orig}}) &\ne \text{None} \implies \delta(f_{\text{redef}}) = \delta(f_{\text{orig}}) \\
\text{ord}(f_{\text{orig}}) &\implies \text{ord}(f_{\text{redef}}) \\
\text{uniq}(f_{\text{orig}}) &\implies \text{uniq}(f_{\text{redef}})
\end{aligned}
```

Contextual Slot Replacement Mapping:

```math
\text{ResolveSlot}(C, s) = \begin{cases}
f_{\text{redef}} & \text{if } \exists f_{\text{redef}} \in \text{Features}(C) : (f_{\text{redef}} :>> f_{\text{orig}}) \wedge (\text{name}(f_{\text{orig}}) = s) \\
f & \text{if } \exists f \in \text{Features}(C) : \text{name}(f) = s \\
\text{ResolveSlot}(P, s) & \text{where } P = \text{head}(\text{tail}(\text{C3}(C))) \text{ if inherited} \\
\bot_{\text{slot}} & \text{otherwise}
\end{cases}
```

Acyclicity and Diagnostic Binding:

```math
\begin{aligned}
(f, f) \in \mathcal{R}_{\text{redef}}^+ &\implies \text{Diagnostic}(f, \text{E0203}) \\
\tau(f_{\text{redef}}) \not\le \tau(f_{\text{orig}}) &\implies \text{Diagnostic}(f_{\text{redef}}, \text{E0200}) \\
\mu(f_{\text{redef}}) \not\subseteq \mu(f_{\text{orig}}) &\implies \text{Diagnostic}(f_{\text{redef}}, \text{E0200}) \\
\delta(f_{\text{orig}}) \ne \delta(f_{\text{redef}}) &\implies \text{Diagnostic}(f_{\text{redef}}, \text{E0200}) \\
\text{C3}(C) = \bot_{\text{c3}} &\implies \text{Diagnostic}(C, \text{E0200})
\end{aligned}
```

Deterministic RFC 4122 UUIDv5 Relationship Anchor:

```math
\text{UUID}(r) = \text{UUIDv5}(\text{NS}_{\text{DEAP}}, \text{FQN}(f_{\text{redef}}) \mathbin{\Vert} \text{":>>"} \mathbin{\Vert} \text{FQN}(f_{\text{orig}}))
```

## 3. Computational Complexity & Algorithmic Bounds

The redefinition lowering pass executes within Complexity Class $`\mathbf{P}`$. In unconstrained posets, subtyping satisfiability and multiple-inheritance redefinition resolution is NP-complete (NP-3). Constraining type hierarchies to a monotonic meet-semilattice and resolving inheritance via deterministic C3 linearization without backtracking guarantees polynomial tractability:
- C3 linearization executes in $`O(V + E)`$ time, where $`V = |\mathcal{C}|`$ and $`E`$ is the number of specialization edges.
- Subtyping conformance and multiplicity checks evaluate in $`O(1)`$ amortized time per edge via reachability bitsets and bounded inheritance depth $`h \le 32`$.
- Redefinition cycle detection evaluates in $`O(V + E)`$ time via Tarjan's SCC algorithm.
- Total verification time across $``N_f``$ features and $``E_{\text{redef}}``$ redefinition edges is strictly $``O(V + E + N_f + E_{\text{redef}})``$, guaranteeing release latency $`< 25\text{ ms}`$ and memory $`< 100\text{ MB}`$ RSS.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Contextual Slot Replacement and Shadowing

- **Given:** Classifier `Classifier_Alpha` defining `Feature_A : Real [0..10]`, and `Classifier_Beta :> Classifier_Alpha` declaring redefinition `Feature_A_sub :>> Feature_A : Real [1..5]`.
- **When:** Lowering resolves slot bindings within `Classifier_Beta`.
- **Then:** Reference lookup for `Feature_A` in `Classifier_Beta` resolves to `Feature_A_sub`, contextually shadowing `Feature_A` while preserving it in `Classifier_Alpha`.
- **Diagnostic:** `E0200` emitted on slot resolution failure.

### AC-02: Covariant Subtyping and Multiplicity Interval Tightening

- **Given:** Classifier `Classifier_Alpha` defining `Feature_A : Classifier_Alpha [2..8]`, and `Classifier_Beta :> Classifier_Alpha` declaring `Feature_A_redef :>> Feature_A : Classifier_Beta [2..5]`.
- **When:** Type checking evaluates covariance $``\tau(\text{Feature\_A\_redef}) \le \tau(\text{Feature\_A})``$ and interval containment $``\mu(\text{Feature\_A\_redef}) \subseteq \mu(\text{Feature\_A})``$.
- **Then:** Conforming covariance and sub-intervals are accepted; contravariant types or widened intervals ($`[1..8]`$ or $`[2..10]`$) are rejected with error sentinel $``\bot_{\text{redef}}``$.
- **Diagnostic:** `E0200` emitted on type non-conformance or multiplicity interval widening.

### AC-03: Port Flow Direction and Structural Invariance

- **Given:** Classifier `Classifier_Alpha` defining directed port `Port_1 : in Classifier_Omega`, and `Classifier_Beta :> Classifier_Alpha` declaring redefinition `Port_1_redef :>> Port_1`.
- **When:** Lowering validates port directionality $`\delta`$ and structural flags (`isOrdered`, `isUnique`).
- **Then:** `Port_1_redef` must preserve `in` polarity ($`\delta = \text{In}`$) unless conjugated (`~`); unauthorized direction inversion or weakening flags is rejected.
- **Diagnostic:** `E0200` emitted on polarity mismatch (`RedefinitionDirectionMismatch`).

### AC-04: C3 Monotonicity, Diamond Disambiguation and Acyclicity

- **Given:** Diamond inheritance hierarchy (`Classifier_Beta :> Classifier_Alpha`, `Classifier_Gamma :> Classifier_Alpha`, `Classifier_Delta :> Classifier_Beta, Classifier_Gamma`).
- **When:** The compiler computes $``\text{C3}(\text{Classifier\_Delta})``$, verifies acyclicity via Tarjan's algorithm, and resolves redefinitions of `Feature_A`.
- **Then:** Precedence resolves in $`O(V + E)`$ time; conflicting unranked redefinitions trigger ambiguity errors; circular redefinitions ($``f_1 :>> f_2 :>> f_1``$) are rejected.
- **Diagnostic:** `E0200` emitted on C3 inconsistency or diamond ambiguity; `E0203` emitted on circular redefinition cycle.
