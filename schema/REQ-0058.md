## 1. Normative Statement

The semantic lowering engine shall formalize multi-ary relations as `Association` and `AssociationStructure` classifiers possessing $`k \ge 2`$ participant end features (`AssociationEnd`), enforcing relational constraints, directional navigability, and fiber cardinality bounds over extensional `Link` tuples. An association declaring $`k \lt 2`$ ends shall be rejected at compile time with diagnostic error code `E0200`.

Each participant end $``e_i``$ ($`1 \le i \le k`$) shall specify a classifier type $``C_i = \tau(e_i)``$, a multiplicity interval $``\mu_i = [l_i, u_i]``$ ($``l_i \le u_i``$, $``u_i \ge 1``$), navigability $``\text{nav}_i \in \{ \text{Navigable}, \text{NonNavigable} \}``$, and an interned role name.

Instantiated links $``L = (o_1, \dots, o_k) \in \prod_{i=1}^k ⟦ C_i ⟧``$ must satisfy participant type conformance $``\tau(o_i) \le C_i``$. Any type mismatch, un-typed participant, or unbound slot shall deterministically trigger diagnostic error code `E0200`.

For every participant instance $``x \in ⟦ C_j ⟧``$, the projected fiber on any target end $`i \ne j`$ shall satisfy $``l_i \le |\{ \pi_i(L) \mid L \in ⟦ A ⟧ \wedge \pi_j(L) = x \}| \le u_i``$; violations shall trigger diagnostic error code `E0200`. Expressions attempting traversal to an end marked `NonNavigable` shall trigger diagnostic error code `E0200`.

An `AssociationStructure` shall specialize both `Association` and `Structure`, binding relational semantics to internal structural features, lifecycles, and persistent object identity. Specialization $``A_{\text{sub}} \le A_{\text{base}}``$ shall preserve arity, participant type covariance, multiplicity narrowing, and navigability; non-monotonic specializations shall trigger diagnostic error code `E0200`.

## 2. Formal Invariant

Let $``\mathcal{A}_{\text{assoc}}``$ denote association classifiers. An association $``A \in \mathcal{A}_{\text{assoc}}``$ is formalized as a tuple:

```math
A = \langle \text{id}_A, \text{name}_A, (e_1, \dots, e_k), \Phi_A, \Delta_A \rangle, \quad k \ge 2
```

Each participant end $``e_i``$ satisfies:

```math
e_i = \langle C_i, [l_i, u_i], \text{nav}_i \rangle, \quad C_i \in \mathcal{C}, \; l_i \le u_i, \; u_i \ge 1
```

Each instantiated link $`L \in ⟦ A ⟧`$ is an extensional tuple satisfying end typing:

```math
L = (o_1, \dots, o_k) \in \prod_{i=1}^k ⟦ C_i ⟧, \quad \forall i \in \{1, \dots, k\}: \tau(\pi_i(L)) \le C_i
```

Fiber multiplicity bounds for participant instance $``x \in ⟦ C_j ⟧``$:

```math
\forall j \in \{1, \dots, k\}, \; \forall x \in ⟦ C_j ⟧, \; \forall i \ne j: \quad l_i \le |\{ \pi_i(L) \mid L \in ⟦ A ⟧ \wedge \pi_j(L) = x \}| \le u_i
```

Navigational projection $``\text{Nav}_{j \to i} : ⟦ C_j ⟧ \to \mathcal{P}(⟦ C_i ⟧) \cup \{ \bot \}``$ satisfies:

```math
\text{Nav}_{j \to i}(x) = \begin{cases}
\{ \pi_i(L) \mid L \in ⟦ A ⟧ \wedge \pi_j(L) = x \}, & \text{if } \text{nav}_i = \text{Navigable} \\
\bot, & \text{if } \text{nav}_i = \text{NonNavigable}
\end{cases}
```

Specialization $``A_{\text{sub}} \le A_{\text{base}}``$ requires:

```math
\begin{aligned}
|\mathcal{E}_{A_{\text{sub}}}| = |\mathcal{E}_{A_{\text{base}}}| &\;\wedge\; \forall i \in \{1, \dots, k\}, \; \tau(e_i^{\text{sub}}) \le \tau(e_i^{\text{base}}) \\
&\;\wedge\; \forall i \in \{1, \dots, k\}, \; [l_i^{\text{sub}}, u_i^{\text{sub}}] \subseteq [l_i^{\text{base}}, u_i^{\text{base}}] \\
&\;\wedge\; \forall i \in \{1, \dots, k\}, \; (\text{nav}_i^{\text{base}} = \text{Navigable} \implies \text{nav}_i^{\text{sub}} = \text{Navigable})
\end{aligned}
```

Deterministic UUIDv5 topological anchor and diagnostic triggers:

```math
\begin{aligned}
\Delta_A &= \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(A)) \\
(k \lt 2) \;\vee\; \exists i \, (\neg(\tau(o_i) \le C_i)) \;\vee\; \text{FiberViolation} &\implies \text{Diagnostic}(A, \text{E0200}) \in \mathcal{D}_{\text{sink}}
\end{aligned}
```

## 3. Computational Complexity & Algorithmic Bounds

The association lowering and link verification engine executes strictly within Complexity Class $`\mathbf{P}`$. For $`|A|`$ associations, $`M = |⟦ A ⟧|`$ links, and $`N`$ participant instances:
- Association arity and definition validation execute in $`O(|A| \cdot k)`$ time for bounded arity $`k \le 16`$.
- Link participant type checking evaluates in $`O(M \cdot k) = O(M)`$ time.
- Fiber multiplicity bound verification executes in $`O(M + N)`$ time via indexed hashing.

Total sequential runtime satisfies:

```math
T_{\text{total}} \in O(|A| + M + N)
```

Parallel execution over $``N_{\text{max\_workers}}``$ threads scales as $``O((|A| + M + N) / N_{\text{max\_workers}} + \log N_{\text{max\_workers}})``$. Memory footprint is bounded by $`O((|A| + M) \cdot k)`$ in the AST.

NP Frontier Reference: Decoupled from NP-hard subtyping posets (NP-3); participant conformance checks evaluate against single-inheritance chains or precomputed C3 linearizations in deterministic $`O(1)`$ time without backtracking.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Multi-Ary Association Arity Validation
- **Given:** `Association_Invalid` with $`k = 1`$ end and `Association_A` with $`k = 2`$ ends (`End_1`, `End_2`).
- **When:** Metamodel lowering performs association definition validation.
- **Then:** `Association_Invalid` is rejected with diagnostic `E0200`, whereas `Association_A` lowers successfully.
- **Diagnostic:** `E0200` emitted on arity $`k \lt 2`$.

### AC-02: Link Participant Type Conformance
- **Given:** `Association_A` over `Classifier_Alpha` and `Classifier_Beta`, and `Link_1` whose second participant has runtime type `Classifier_Gamma` ($``\text{Classifier\_Gamma} \not\le \text{Classifier\_Beta}``$).
- **When:** Semantic type checking validates `Link_1`.
- **Then:** Compilation rejects `Link_1` and records diagnostic `E0200` with exact source byte spans.
- **Diagnostic:** `E0200` emitted on participant type mismatch.

### AC-03: Fiber Multiplicity Bound Enforcement
- **Given:** `Association_A` between `Classifier_Alpha` and `Classifier_Beta` with interval $``\mu_2 = [1, 3]``$ on `Classifier_Beta`.
- **When:** Fiber validation evaluates instances of `Classifier_Alpha` with 0, 2, and 4 associated links.
- **Then:** Instances with 0 and 4 links trigger diagnostic `E0200`, while the instance with 2 links validates.
- **Diagnostic:** `E0200` emitted on fiber multiplicity bound violation.

### AC-04: Non-Navigable End Traversal Rejection
- **Given:** `Association_A` with `End_1` marked `Navigable` and `End_2` marked `NonNavigable`.
- **When:** An expression attempts traversal from `End_1` to `End_2`.
- **Then:** Semantic analysis halts traversal and emits diagnostic `E0200`.
- **Diagnostic:** `E0200` emitted on non-navigable end access attempt.
