## 1. Normative Statement

The Core Metamodel, Node Arena & AST Graph Engine shall enforce strongly typed port directionality (`in`, `out`, `inout`) on all port definitions and usages, verifying directional compatibility across topological connection bindings. Port definitions shall declare an immutable base direction $``d_{\text{decl}} \in \mathcal{D} = \{ \text{In}, \text{Out}, \text{InOut} \}``$. Port usages shall inherit $``d_{\text{decl}}``$, with optional conjugation (`~`) applying algebraic involution $``\tau_{\text{conj}}``$ to compute effective direction $``d_{\text{eff}} \in \mathcal{D}``$.

Connections are partitioned into two structural categories:
1. **Peer-to-Peer (Assembly) Connections:** For sibling component usages, the engine shall enforce anti-parallel directed flow (`Out` to `In`, `In` to `Out`) or bidirectional flow (`InOut` to `InOut`). Unidirectional matching (`In` to `In`, `Out` to `Out`) or mismatched `InOut` pairs without adapters shall emit diagnostic `E0201` per REQ-0191.
2. **Hierarchical Delegation Connections:** For enclosing parent boundary ports connecting to inner child ports, the engine shall enforce parallel flow preservation ($``P_{\text{outer}}.d_{\text{eff}} = P_{\text{inner}}.d_{\text{eff}}``$). Directional inversion across boundaries shall emit diagnostic `E0201`.

## 2. Formal Invariant

Let $`\mathcal{D} = \{ \text{In}, \text{Out}, \text{InOut} \}`$. The conjugation involution operator $``\tau_{\text{conj}} : \mathcal{D} \to \mathcal{D}``$ and its identity satisfy:

```math
\tau_{\text{conj}}(d) = \begin{cases}
\text{Out}, & \text{if } d = \text{In} \\
\text{In}, & \text{if } d = \text{Out} \\
\text{InOut}, & \text{if } d = \text{InOut}
\end{cases}, \qquad \forall d \in \mathcal{D}, \quad \tau_{\text{conj}}(\tau_{\text{conj}}(d)) \equiv d
```

For port usage $``P = \langle \text{id}, \text{owner}, d_{\text{decl}}, c \rangle``$ where $`c \in \{ \text{true}, \text{false} \}`$:

```math
d_{\text{eff}}(P) = \begin{cases}
\tau_{\text{conj}}(P.d_{\text{decl}}), & \text{if } P.c = \text{true} \\
P.d_{\text{decl}}, & \text{if } P.c = \text{false}
\end{cases}
```

Let connection $``C = \langle \text{id}, P_{\text{src}}, P_{\text{tgt}}, \kappa_{\text{conn}} \rangle``$ with $``\kappa_{\text{conn}} \in \{ \text{Assembly}, \text{Delegation} \}``$. Directional compatibility relations satisfy:

```math
\begin{aligned}
P_{\text{src}} \sim_{\text{peer}} P_{\text{tgt}} &\iff (P_{\text{src}}.d_{\text{eff}}, P_{\text{tgt}}.d_{\text{eff}}) \in \{ (\text{Out}, \text{In}), (\text{In}, \text{Out}), (\text{InOut}, \text{InOut}) \} \\
P_{\text{outer}} \sim_{\text{delegation}} P_{\text{inner}} &\iff P_{\text{outer}}.d_{\text{eff}} = P_{\text{inner}}.d_{\text{eff}}
\end{aligned}
```

Directional validity and diagnostic bindings per REQ-0191:

```math
\text{ValidDirection}(C) \iff \begin{cases}
P_{\text{src}} \sim_{\text{peer}} P_{\text{tgt}}, & \text{if } \kappa_{\text{conn}}(C) = \text{Assembly} \\
P_{\text{outer}} \sim_{\text{delegation}} P_{\text{inner}}, & \text{if } \kappa_{\text{conn}}(C) = \text{Delegation}
\end{cases}
```

```math
\begin{aligned}
\neg \text{ValidDirection}(C) &\implies \exists D \in \mathcal{D}_{\text{sink}} : \text{code}(D) = \text{DiagnosticCode::E0201} \\
|\mathcal{D}_{\text{sink}}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D}_{\text{sink}} : \text{code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
```

Deterministic UUIDv5 and Arena Node Addressing:

```math
\forall u \in \mathcal{V}_{\text{port}} \cup \mathcal{E}_{\text{conn}}, \quad \text{UUID}(u) = \text{UUIDv5}(\text{OID}_{\text{DEAP}}, \text{FQN}(u)), \quad \text{Handle}(u) = \langle \text{ArenaId}, \text{Offset}_u \rangle
```

## 3. Computational Complexity & Algorithmic Bounds

Port direction verification executes strictly within Complexity Class $`\mathbf{P}`$. Effective direction evaluation $``d_{\text{eff}}(P)``$ and connection compatibility checking execute in deterministic $`O(1)`$ constant time via direct arena offset dereferencing and 2-bit discriminant table lookup. For an AST interconnect graph $``G = (\mathcal{V}_{\text{port}}, \mathcal{E}_{\text{conn}})``$ with $``V = |\mathcal{V}_{\text{port}}|``$ ports and $``E = |\mathcal{E}_{\text{conn}}|``$ connections, total sequential verification runs in $`O(E) \subseteq O(V + E)`$ time with $`O(1)`$ auxiliary space beyond the AST memory and preallocated diagnostic sink $``O(C_{\text{max\_errors}})``$., parallel execution is bounded by $``O(E / N_{\text{max\_workers}} + \log N_{\text{max\_workers}})``$. Verification is local and acyclic; combinatorial NP frontiers (NP-1--NP-8) are bypassed with zero backtracking.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Peer-to-Peer Anti-Parallel Direction Verification
- **Given:** Sibling instances `Part_0` and `Part_1` declaring peer connections: `(Out, In)`, `(In, Out)`, and `(InOut, InOut)`.
- **When:** The AST type checking pass validates peer connection directionality.
- **Then:** All three connection edges evaluate to valid, node handles are marked validated, and zero diagnostics are emitted.
- **Diagnostic:** `E0201` on unexpected validation rejection.

### AC-02: Hierarchical Delegation Flow Preservation
- **Given:** Component `Component_Alpha` with boundary ports connected to child `Part_0` ports: outer `In` to inner `In`, inner `Out` to outer `Out`, and outer `InOut` to inner `InOut`.
- **When:** The type checking pass evaluates delegation connections across containment boundaries.
- **Then:** All delegation connections satisfy $``P_{\text{outer}}.d_{\text{eff}} = P_{\text{inner}}.d_{\text{eff}}``$ and are accepted with zero diagnostics.
- **Diagnostic:** `E0201` on valid delegation rejection.

### AC-03: Port Conjugation Involution and Effective Direction Resolution
- **Given:** Port usage `Port_2` with base direction `In` and conjugation flag $`c = \text{true}`$, connected to peer `Port_1` with base direction `In` and $`c = \text{false}`$.
- **When:** Resolving effective directions and checking peer connection validity.
- **Then:** Resolves $``d_{\text{eff}}(\text{Port\_2}) = \tau_{\text{conj}}(\text{In}) = \text{Out}``$, satisfies $``\text{In} \sim_{\text{peer}} \text{Out}``$, and accepts the connection with zero diagnostics.
- **Diagnostic:** `E0201` on conjugation involution evaluation failure.

### AC-04: Peer and Delegation Direction Mismatch Rejection
- **Given:** Invalid peer pairings (`(In, In)`, `(Out, Out)`, `(In, InOut)`) and inverted delegation pairings (outer `In` to inner `Out`, outer `Out` to inner `In`).
- **When:** Type checking processes connection topology.
- **Then:** Rejects each invalid edge, logs structured `E0201` diagnostics with byte spans and port handles, and continues verification via synchronization recovery.
- **Diagnostic:** `E0201` recorded in diagnostic sink $``\mathcal{D}_{\text{sink}}``$.
