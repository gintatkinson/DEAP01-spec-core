## 1. Normative Statement

The compiler SHALL lower SysML v2 requirement definitions (`requirement def`, `RequirementDefinition`) as contractual classifiers specializing KerML `ConstraintDefinition`, and requirement usages (`requirement`, `RequirementUsage`) as contextual features specializing KerML `ConstraintUsage`.

The lowering engine MUST enforce six core invariants:
1. **Specialization**: `RequirementDefinition` specializes KerML `ConstraintDefinition` with Boolean codomain; `RequirementUsage` specializes `ConstraintUsage`.
2. **Identifier Uniqueness**: Requirements SHALL declare an alphanumeric identifier ($``\text{req\_id}``$); duplicates across compilation units MUST emit diagnostic `E0200`.
3. **Normative Prose**: Definitions SHALL specify non-empty normative text; empty text emits `E0200`.
4. **Subject Binding & Direction**: Definitions declare subject parameter ($``p_{\text{subject}}``$). Parameters MUST declare `In` directionality ($\text{dir}(p) \equiv \text{In}$); non-`In` directions emit `E0201`. Usages MUST bind the subject to conforming types ($``\tau(a_{\text{subject}}) \le \tau(p_{\text{subject}})``$); mismatches emit `E0200`.
5. **Assume-Guarantee Contract**: Requirements formalize contract $``\mathcal{C}_R = (\mathcal{A}_{\text{assume}}, \mathcal{G}_{\text{require}})``$ ($``\mathcal{A}_{\text{assume}}``$ defaults to $\top$). Predicates MUST evaluate to `Boolean` and be functionally pure ($\Delta \text{State} \equiv \emptyset$); violations emit `E0200`.
6. **Acyclicity**: Dependency multigraph $``G_{\text{dep}}``$ MUST be a DAG; cycles emit `E0203`.

## 3. Computational Complexity & Algorithmic Bounds

Lowering and contract verification execute within Complexity Class $\mathbf{P}$.

For an AST model with $N = |\mathcal{RD}|$ definitions, $M = |\mathcal{RU}|$ usages, expression nodes $``E_{\text{nodes}}``$, and dependency edges $``|\mathcal{R}_{\text{req\_dep}}|``$:
- **Identifier Deduplication**: Interning and verifying identifiers takes amortized $O(1)$ time ($O(N + M)$ total).
- **Typing & Conformance**: Subtyping and arity evaluate in $O(1)$ amortized time via cached bitsets (NP-3 fragment).
- **Boolean Codomain**: AST traversal verifies Boolean predicate types in deterministic $``O(E_{\text{nodes}})``$ time.
- **DAG Acyclicity**: Topological sort over $``G_{\text{dep}}``$ executes in deterministic $``O(N + M + |\mathcal{R}_{\text{req\_dep}}|)``$ time.

Total sequential complexity is $``O(N + M + E_{\text{nodes}} + |\mathcal{R}_{\text{req\_dep}}|)``$. Work-stealing parallel lowering scales as $``O((N + M + E_{\text{nodes}} + |\mathcal{R}_{\text{req\_dep}}|) / N_{\text{max\_workers}} + \log N_{\text{max\_workers}})``$. Polynomial verification bypasses NP-hard solver synthesis (NP-1, NP-8) via static AST typing.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Canonical Requirement Lowering and Contract Resolution
- **Given:** `ReqDef_Alpha` with subject `Subject_A : Classifier_Alpha`, assume `Subject_A.attr_a >= 0.0`, require `Subject_A.attr_a <= 100.0`.
- **When:** Lowering `Req_1 : ReqDef_Alpha` binding `Subject_A = Classifier_Alpha`.
- **Then:** Nodes lower into arena storage with resolved subject binding and empty diagnostic sink.
- **Diagnostic:** Diagnostic sink remains empty.

### AC-02: Global Duplicate Requirement Identifier Rejection
- **Given:** Two declarations with duplicate identifier `req_id = "REQ-0085"`.
- **When:** Global identifier uniqueness validation executes.
- **Then:** Lowering rejects duplicate declaration with source spans and emits `E0200`.
- **Diagnostic:** `E0200` (Duplicate requirement identifier).

### AC-03: Subject Parameter Binding Mismatch and Missing Binding
- **Given:** Usage `Req_1 : ReqDef_Alpha` with missing subject or binding `Classifier_Beta` ($``\text{Classifier\_Beta} \not\le \text{Classifier\_Alpha}``$).
- **When:** Subject parameter subtyping validation executes.
- **Then:** Lowering rejects invalid binding with sentinel $``\bot_{\text{req}}``$ and emits `E0200`.
- **Diagnostic:** `E0200` (Subject parameter binding mismatch).

### AC-04: Non-Input Parameter Directionality Rejection
- **Given:** Requirement definition declaring parameter with direction `out` (`out param_x : Real`).
- **When:** Parameter signature directionality analysis executes.
- **Then:** Lowering rejects non-`In` directionality and emits `E0201`.
- **Diagnostic:** `E0201` (Invalid requirement parameter direction).
