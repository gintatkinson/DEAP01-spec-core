## 1. Normative Statement

The CommonMark table parser within the Universal Schema Ingestion Engine shall parse tabular schemas specifying directed ports into intermediate `IngestedPort` AST entities. For each data row, the parser shall extract the port identifier, owning component handle, declared direction (`in`, `out`, `inout`), interface payload data type handle, multiplicity bounds, and optional conjugated marker (`~`). Header columns shall normalize into canonical attributes order-independently.

The engine shall compute effective port direction via algebraic involution $``\tau_{\text{conj}}``$ when a conjugated marker is present. Conjugation shall invert directional polarity (`in` to `out`, `out` to `in`, `inout` to `inout`) while strictly preserving payload data type handles, multiplicity bounds, and contractual invariants. Within each parent component classifier, port identifiers must be pairwise distinct.

## 2. Formal Invariant

Let $``T = \langle R_1, R_2, \dots, R_M \rangle``$ denote a tabular port schema comprising $`M`$ rows and $`C`$ normalized columns ($`1 \le C \le 32`$). The discrete port direction domain and parsing operator are:

```math
\text{Dir} = \{ \text{In}, \text{Out}, \text{InOut} \}, \quad \text{ParseDir}(s) = \begin{cases}
\text{In}, & \text{if } s \in \{ \text{"in"}, \text{"input"} \} \\
\text{Out}, & \text{if } s \in \{ \text{"out"}, \text{"output"} \} \\
\text{InOut}, & \text{if } s \in \{ \text{"inout"}, \text{"in\_out"} \} \\
\bot, & \text{otherwise}
\end{cases}
```

The port conjugation involution operator $``\tau_{\text{conj}} : \text{Dir} \to \text{Dir}``$, effective direction resolution function $``d_{\text{eff}}``$, and involution identity satisfy:

```math
\begin{aligned}
\tau_{\text{conj}}(\text{In}) = \text{Out}, \quad \tau_{\text{conj}}(\text{Out}) &= \text{In}, \quad \tau_{\text{conj}}(\text{InOut}) = \text{InOut} \\
d_{\text{eff}}(d, c) &= \begin{cases} \tau_{\text{conj}}(d), & \text{if } c = \text{true} \\ d, & \text{if } c = \text{false} \end{cases} \\
\forall d \in \text{Dir}, \; \forall c \in \mathbb{B}, \quad d_{\text{eff}}(d_{\text{eff}}(d, c), c) &\equiv d
\end{aligned}
```

Each lowered port entity is represented as a 7-tuple:

```math
\text{PortDef} = \langle \text{id} \in \mathcal{S}_{\text{sym}}, \text{owner} \in \mathcal{H}_{\text{node}}, d_{\text{decl}} \in \text{Dir}, d_{\text{eff}} \in \text{Dir}, \tau_{\text{payload}} \in \mathcal{H}_{\text{type}}, c \in \mathbb{B}, \mu \in \mathbb{N}_0 \times (\mathbb{N}_0 \cup \{ \infty \}) \rangle
```

Conjugation preserves payload typing, multiplicity bounds, and contract invariants:

```math
\begin{aligned}
\text{PayloadType}(\tau_{\text{conj}}(P)) &\equiv \text{PayloadType}(P) \\
\text{Multiplicity}(\tau_{\text{conj}}(P)) &\equiv \text{Multiplicity}(P) \\
\text{ContractInvariants}(\tau_{\text{conj}}(P)) &\equiv \text{ContractInvariants}(P)
\end{aligned}
```

Scoped identifier uniqueness and diagnostic code bindings per REQ-0191 satisfy:

```math
\begin{aligned}
\forall P_a, P_b \in \mathcal{P}, \quad (P_a.\text{owner} = P_b.\text{owner} \;\wedge\; P_a.\text{id} = P_b.\text{id}) &\implies P_a = P_b \\
\text{ParseDir}(\text{Cell}(R_i, C_{\text{dir}})) = \bot &\implies \exists D \in \mathcal{D} : \text{Code}(D) = \text{DiagnosticCode::E0102} \\
(\exists k \ne i : P_k.\text{owner} = P_i.\text{owner} \;\wedge\; P_k.\text{id} = P_i.\text{id}) &\implies \exists D \in \mathcal{D} : \text{Code}(D) = \text{DiagnosticCode::E0102} \\
\text{Cell}(R_i, C_{\text{id}}) = \varepsilon &\implies \exists D \in \mathcal{D} : \text{Code}(D) = \text{DiagnosticCode::E0102} \\
|\mathcal{D}| \ge C_{\text{max\_errors}} &\implies \exists D_{\text{term}} \in \mathcal{D} : \text{Code}(D_{\text{term}}) = \text{DiagnosticCode::E0199}
\end{aligned}
```

## 3. Computational Complexity & Algorithmic Bounds

Tabular schema ingestion for directed ports executes within Complexity Class $`\mathbf{P}`$. Monotonic single-pass scanning advances through $`N`$ total bytes in deterministic $`O(N)`$ time without backtracking. Header mapping, direction parsing $`\text{ParseDir}`$, and involution $``\tau_{\text{conj}}``$ execute in $`O(1)`$ constant time with zero dynamic memory allocation. Scoped port uniqueness checks perform hash lookups in amortized $`O(1)`$ time per row. Total ingestion across $`R`$ rows and $`C \le 32`$ columns executes in $`O(R \cdot C) = O(N)`$ time and requires $``O(C + C_{\text{max\_errors}}) = O(1)``$ auxiliary memory relative to $`N`$. The deterministic pass operates strictly in polynomial time and avoids NP-hard combinatorial frontiers (NP-1--NP-8).

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Positive Ingestion of Directed Ports
- **Given:** Valid CommonMark table declaring directed ports (`Port_0`, `Port_1`, `Port_2`) on component `Classifier_Alpha` with directions `in`, `out`, `inout` and payload `Flow_A`.
- **When:** Lowering rows into AST entities during the port ingestion pass.
- **Then:** 100% of rows synthesize into `IngestedPort` AST nodes with declared directions and valid arena handles.
- **Diagnostic:** `E0102` on row parsing or lowering failure.

### AC-02: Conjugated Port Direction Involution
- **Given:** Schema rows specifying conjugated ports (`~Port_1` or conjugation flag `true`) for directions `in`, `out`, and `inout`.
- **When:** Evaluating effective directions via involution operator $``\tau_{\text{conj}}``$.
- **Then:** Directions invert polarity ($`\text{In} \mapsto \text{Out}`$, $`\text{Out} \mapsto \text{In}`$, $`\text{InOut} \mapsto \text{InOut}`$), satisfying identity $``\tau_{\text{conj}}(\tau_{\text{conj}}(d)) \equiv d``$.
- **Diagnostic:** `E0102` on direction polarity resolution failure.

### AC-03: Payload Typing and Contract Preservation
- **Given:** Declared ports with payload type `Flow_A`, multiplicity bounds $`[1..1]`$, and invariant constraints.
- **When:** Applying involution $``\tau_{\text{conj}}``$ during port lowering.
- **Then:** Inverted port entities retain bitwise identical payload type handles, multiplicity bounds, and invariant constraints.
- **Diagnostic:** `E0102` on payload mutation or type mismatch under conjugation.

### AC-04: Scoped Port Identifier Collision Rejection
- **Given:** Table rows declaring duplicate port identifier `Port_1` under the identical owning component `Classifier_Alpha`.
- **When:** Ingesting the colliding row during AST construction.
- **Then:** Emits structured diagnostic `E0102` with 1-indexed coordinates and byte span, substitutes sentinel $``\bot_{\text{port}}``$, and preserves the original port entity.
- **Diagnostic:** `E0102` emitted upon scoped identifier collision.
