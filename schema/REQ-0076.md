## 1. Normative Statement

The metamodel lowering engine SHALL formalize SysML v2 `flow` usages (`ItemFlow`) as directed transfers traversing connectors between port endpoints, specializing KerML `Step` and `OccurrenceUsage` in arena storage.

The engine MUST enforce four static invariants:
1. **Directional Compatibility**: Source port $``p_{\text{src}}``$ MUST emit ($``\text{dir}(p_{\text{src}}) \in \{ \text{Out}, \text{InOut} \}``$) and target port $``p_{\text{tgt}}``$ MUST ingest ($``\text{dir}(p_{\text{tgt}}) \in \{ \text{In}, \text{InOut} \}``$). Incompatible endpoints SHALL emit diagnostic `E0201`.
2. **Payload Covariance**: Flow payload $``I_{\text{payload}}``$ MUST specialize both endpoint payload types ($``I_{\text{payload}} \le \text{payload\_type}(p_{\text{src}})``$ and $``I_{\text{payload}} \le \text{payload\_type}(p_{\text{tgt}})``$) in meet-semilattice $(\mathcal{T}, \le, \wedge)$. Type violations SHALL emit diagnostic `E0202`.
3. **Rate and Capacity**: Rate interval $``R_{\text{flow}} = [r_{\min}, r_{\max}]``$ MUST satisfy $``0 \le r_{\min} \le r_{\max}``$; invalid bounds SHALL emit diagnostic `E0202`. Peak throughput $``r_{\max} \cdot \text{size}(I_{\text{payload}})``$ SHALL NOT exceed connector capacity $\text{Capacity}(C)$; overflow SHALL emit diagnostic `E0202`.
4. **Endpoint Scoping**: Ports $``p_{\text{src}}``$ and $``p_{\text{tgt}}``$ MUST resolve to accessible ports within scope; unresolvable endpoints SHALL emit diagnostic `E0200`.

## 2. Formal Invariant

KerML metamodel lowering specialization and streaming invariants for $``F = \langle \text{id}_F, p_{\text{src}}, p_{\text{tgt}}, I_{\text{payload}}, R_{\text{flow}}, C \rangle \in \mathcal{E}_{\text{flow}}``$:

```math
\begin{aligned}
\text{ItemFlow} &\le \text{Step} \le \text{Feature} \\
\text{ItemFlow} &\le \text{OccurrenceUsage} \le \text{OccurrenceDefinition} \\
\Phi_{\text{dir}}(F) &\iff \text{dir}(p_{\text{src}}) \in \{ \text{Out}, \text{InOut} \} \;\wedge\; \text{dir}(p_{\text{tgt}}) \in \{ \text{In}, \text{InOut} \} \\
\Phi_{\text{payload}}(F) &\iff I_{\text{payload}} \le \text{payload\_type}(p_{\text{src}}) \;\wedge\; I_{\text{payload}} \le \text{payload\_type}(p_{\text{tgt}}) \\
\Phi_{\text{rate}}(F) &\iff 0 \le r_{\min} \le r_{\max}, \quad R_{\text{flow}} = [r_{\min}, r_{\max}] \\
\Phi_{\text{cap}}(F, C) &\iff r_{\max} \cdot \text{size}(I_{\text{payload}}) \le \text{Capacity}(C) \\
\forall n \in \mathcal{E}_{\text{flow}}, \quad \Delta_n &= \text{UUIDv5}(\text{NS}_{\text{DEAP}}, \text{FQN}(n))
\end{aligned}
```

## 3. Computational Complexity & Algorithmic Bounds

Item flow lowering executes strictly within Complexity Class $\mathbf{P}$.

For $V$ ports, $E$ connectors, and $F$ item flows:
1. Endpoint resolution operates in $O(1)$ amortized time ($O(F)$ total).
2. Directional compatibility checks evaluate 2-bit direction flags in $O(1)$ time per flow.
3. Payload subtyping covariance evaluates in $O(1)$ time against the precomputed meet-semilattice (tractable fragment of NP-3).
4. Rate interval validation and bandwidth comparisons evaluate in $O(1)$ scalar operations.

Total verification complexity is $O(V + E + F)$. Parallel package lowering scales as $``O((V + E + F) / N_{\text{max\_workers}} + \log N_{\text{max\_workers}})``$.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Canonical ItemFlow Lowering
- **Given:** Component `Part_0` with `Port_Src : out Item_0` and `Port_Tgt : in Item_0` connected by `Conn_0`.
- **When:** Lowering `flow of Item_0 from Port_Src to Port_Tgt`.
- **Then:** Flow lowers as KerML `Step` and `OccurrenceUsage` with zero diagnostics.
- **Diagnostic:** Diagnostic sink remains empty.

### AC-02: Conflicting Port Direction Rejection
- **Given:** Flow streaming from `Port_Src : in Item_0` to `Port_Tgt : in Item_0`.
- **When:** Directionality validation evaluates endpoint modes.
- **Then:** Compiler rejects the declaration with diagnostic `E0201`.
- **Diagnostic:** `E0201` (Flow direction mismatch).

### AC-03: Incompatible Item Payload Subtyping
- **Given:** Ports `Port_Src : out Item_Super`, `Port_Tgt : in Item_Super`, and payload `Item_Unrelated` ($``\text{Item\_Unrelated} \not\le \text{Item\_Super}``$).
- **When:** Type checking validates payload covariance.
- **Then:** Compiler rejects the flow declaration with diagnostic `E0202`.
- **Diagnostic:** `E0202` (Payload type incompatibility).

### AC-04: Rate Interval and Capacity Bounds
- **Given:** Flow on `Conn_0` ($\text{Capacity} = 1000$ B/s) with inverted rate `[100.0, 10.0]` or throughput $> 1000$ B/s.
- **When:** Rate multiplicity and bandwidth checks execute.
- **Then:** Compiler isolates the invalid flow with diagnostic `E0202`.
- **Diagnostic:** `E0202` (Malformed rate or capacity overflow).
