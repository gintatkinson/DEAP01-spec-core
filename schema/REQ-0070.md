## 1. Normative Statement

The SysML v2 model organization engine SHALL structure models into modular `package` and subsystem hierarchies, formalizing visibility boundaries, package imports, and encapsulation boundaries as an acyclic package dependency graph. A package declaration (`package <name> {... }`) defines a sovereign namespace boundary specializing KerML `Namespace`.

The lowering engine MUST enforce the following formal semantic rules:
1. **Visibility and Encapsulation**: Element memberships within a package declare visibility $``v \in \{ \text{Private}, \text{Public} \}``$, defaulting to `public`. Public elements belong to $``\text{ExportedSymbols}(P)``$ and are accessible via qualified path resolution or package import declarations. Private elements are strictly encapsulated within the declaring package and its lexical children. Any unauthorized access from an external package SHALL emit diagnostic `E0200`.
2. **Package Import Semantics**: The compiler SHALL support single-element (`import P::C;`), namespace wildcard (`import P::*;`), recursive wildcard (`import P::**;`), and alias (`import P::C as A;`) imports. Private imports bind symbols locally; public imports re-export symbols. Every import declaration adds a directed dependency edge $``(P_{\text{src}}, P_{\text{tgt}}) \in \mathcal{D}_{\text{imp}}``$.
3. **Acyclic Package Dependency Graph**: The combined package dependency graph $``G_{\text{pkg}} = (\mathcal{P}, \mathcal{D}_{\text{imp}} \cup \mathcal{D}_{\text{ref}})``$ MUST be a directed acyclic graph (DAG). Any circular import or cross-package dependency cycle SHALL be detected via topological cycle detection and rejected with diagnostic `E0203`.
4. **Nesting Depth Upper Bound**: Package nesting depth SHALL NOT exceed $``D_{\max} = 16``$. Nesting beyond $``D_{\max}``$ SHALL emit diagnostic `E0200`.

## 2. Formal Invariant

Let $\mathcal{P}$ denote the set of packages and $``\mathcal{D}_{\text{imp}}``$ denote the directed import relation. Formal package graph and export mappings:

```math
\begin{aligned}
G_{\text{pkg}} &= (\mathcal{P}, \mathcal{E}_{\text{dep}}), \quad \mathcal{E}_{\text{dep}} = \mathcal{D}_{\text{imp}} \cup \mathcal{D}_{\text{ref}} \\
\text{ExportedSymbols}(P) &= \{ s \in \text{Symbols}(P) \mid \text{visibility}(s) = \text{Public} \} \\
\text{PrivateSymbols}(P) &= \{ s \in \text{Symbols}(P) \mid \text{visibility}(s) = \text{Private} \}
\end{aligned}
```

Acyclicity, nesting depth, and RFC 4122 UUIDv5 invariants:

```math
\begin{aligned}
\forall P \in \mathcal{P}, \quad &(P, P) \notin \mathcal{E}_{\text{dep}}^+ \\
\forall P \in \mathcal{P}, \quad &\text{Depth}(P) \le 16 \\
\forall n \in \mathcal{P}, \quad &\Delta_n = \text{UUIDv5}(\text{NS}_{\text{DEAP}}, \text{FQN}(n))
\end{aligned}
```

| Symbol / Term | Domain / Formal Definition |
| :--- | :--- |
| $\mathcal{P}$ | Set of all package and subsystem nodes in the model AST |
| $``\mathcal{E}_{\text{dep}}``$ | Directed package dependency edges ($``\mathcal{D}_{\text{imp}} \cup \mathcal{D}_{\text{ref}}``$) |
| $\text{ExportedSymbols}(P)$ | Set of public symbols accessible outside package $P$ |
| $\text{PrivateSymbols}(P)$ | Set of private symbols encapsulated within package $P$ |
| $\text{Depth}(P)$ | Hierarchical lexical nesting depth from root package ($D \le 16$) |
| $``\Delta_n``$ | Deterministic RFC 4122 UUIDv5 topological anchor string |

## 3. Computational Complexity & Algorithmic Bounds

The package organization, import resolution, and cycle validation passes execute strictly within Complexity Class $\mathbf{P}$.

For a package graph with $V = |\mathcal{P}|$ package nodes and $``E = |\mathcal{E}_{\text{dep}}|``$ dependency edges:
1. AST node construction and symbol interning execute in amortized $O(1)$ time per node.
2. Visibility checking and encapsulation filtering execute in $O(1)$ scalar checks per symbol reference.
3. Package graph acyclicity validation executes in $O(V + E)$ time via Tarjan's strongly connected components or Kahn's topological sort.
4. Wildcard and alias import bindings resolve in $O(S)$ time for $S$ exported symbols without backtracking.

Total sequential verification complexity is $O(V + E)$. Parallel package processing scales as $``O((V + E) / N_{\text{max\_workers}} + \log N_{\text{max\_workers}})``$.

## 4. Verification & Conformance Criteria (IEEE 29148 Acceptance Criteria)

### AC-01: Canonical Package Hierarchy & Public Export Lowering
- **Given:** A valid model declaring `Package_0` containing public `Classifier_Alpha` and a distinct `Package_1` with `import Package_0::*;`.
- **When:** The compiler executes package lowering and import symbol resolution.
- **Then:** `Package_0` and `Package_1` are lowered into the AST, and `Classifier_Alpha` is successfully resolved within `Package_1` with zero diagnostics.
- **Diagnostic:** Diagnostic sink remains empty.

### AC-02: Private Symbol Encapsulation Breach Rejection
- **Given:** `Package_0` declaring private member `Classifier_Beta` (`private Classifier_Beta`).
- **When:** An external `Package_1` attempts to reference or import `Package_0::Classifier_Beta`.
- **Then:** The compiler rejects the foreign access, records the offending source byte span, and emits diagnostic code `E0200`.
- **Diagnostic:** `E0200` emitted for private symbol encapsulation breach.

### AC-03: Circular Package Import Dependency Detection
- **Given:** Two packages declaring mutual imports (`Package_0` imports `Package_1` and `Package_1` imports `Package_0`).
- **When:** The compiler constructs and traverses the package dependency graph $``G_{\text{pkg}}``$.
- **Then:** The cycle is detected, topological sorting halts for the circular component, and diagnostic code `E0203` is emitted.
- **Diagnostic:** `E0203` emitted for circular package dependency.

### AC-04: Bounded Package Nesting Depth Enforcement
- **Given:** A deeply nested package hierarchy declaring 17 nested packages (`Package_0::Package_1::...::Package_16`).
- **When:** The compiler validates package lexical nesting depth.
- **Then:** The compiler detects depth $D = 17 \gt 16$, halts nested package lowering, and emits diagnostic code `E0200`.
- **Diagnostic:** `E0200` emitted for exceeding maximum package nesting depth.
