# Project-Scoped Rules

## 1. Coordinator Role, Planning Gate & Fast-Path Dispatch
Thought blocks MUST focus directly on technical reasoning -- never emit startup checklists, initialization receipt tables, or "Ready for instructions" prompts.

- **Coordinator Mutation Lock**: The Coordinator NEVER edits, copies, moves, or deletes repository files directly (nor via `cp`, `mv`, `rm`, `tee`, `sed -i`, `>`, `>>`). All repository writes are delegated to single-item subagents.
- **Two Execution Paths**:
  1. **Skill-Driven Pass-Through Dispatch (Zero Coordinator Pre-Analysis)**: When the user commands dispatching issue(s) to an investigative/diagnostic skill subagent (`debug-protocol` or `adversarial-code-auditor`), the Coordinator acts as a pure router. Do NOT read source files or pre-diagnose bugs. Query open issue IDs via `gh issue list` if a range is given, and dispatch one context-isolated subagent per issue instructing it to read the target `SKILL.md` first and appending `PROCEED`.
  2. **Planned Modification Gate**: For direct edits or feature/spec workflows where the Coordinator defines the changes, write an atomic (1-item max) `implementation_plan.md` at `<appDataDir>/brain/<conversation-id>/implementation_plan.md` (or `.pipeline/plans/<slug>.md`) and await explicit user approval (`PROCEED` / `Approved`) before dispatching modifying subagents. Never overwrite a root `./implementation_plan.md` or create `walkthrough.md` prior to completion.
- **Continuous Execution**: Once `PROCEED` is active, run subagent dispatches, verification gates, and git pushes continuously to completion. Stop ONLY on: (1) non-zero build/test/linter exit codes, (2) unresolvable requirement ambiguity, or (3) unapproved initial plans.

## 2. Repository Role, Clean Landing Zones & Black-Box Firewall
- **Role Detection**:
  - **`.pipeline/upstream/` present (`UPSTREAM_SPEC_CORE_COMPILER`)**: `DEAP01-spec-core` upstream compiler repo. Landing zones (`schema/`, `docs/epics/`, `docs/features/`, `docs/user-stories/`, `docs/use-cases/`) must contain ONLY `.gitkeep`. Never commit domain/customer specs here; bypass `.pipeline/profiles/*`.
  - **`.pipeline/upstream/` absent (`DOWNSTREAM_CUSTOMER_PROJECT`)**: Downstream workspace where `schema/` and `.pipeline/schema.sysml` are the 100% Single Source of Truth (SSOT). Load `.pipeline/profiles/<target_platform>.md` only during downstream implementation turns.
- **Pure Schema-Driven MBSE Compiler**: Never hardcode or invent domain-specific concepts in pipeline logic, templates, or plans. All specs and safety artifacts derive deterministically from AST nodes in `schema/`.
- **Downstream Binary-Only Firewall**: Tier-0 compiler source (`crates/*`, `Cargo.toml`, `Cargo.lock`), `.pipeline/upstream/`, and `docs/architecture/blueprints/` belong exclusively in `DEAP01-spec-core`. Never copy Tier-0 `crates/*` or run `cargo build` downstream, and never read `../DEAP01-spec-core/crates/*` from a downstream session (report upstream defects via `adversarial-code-auditor`). Downstream projects require a root `.gitignore`, zero `.DS_Store` files, and zero duplicated master blueprints.

## 3. Lazy Governance Loading & Subagent Isolation
- **Once-Per-Session Context Check**: Only when starting a pipeline spec or feature-implementation workflow for the first time in a session, silently check `test -d .pipeline/upstream`, `git status --short --branch`, `.pipeline/constitution.md`, and `.pipeline/ACTIVE_RULES_BUNDLE.md`. Skip governance reads entirely on diagnostic turns, surgical edits, and inside subagents receiving `---GOVERNANCE-END---`.
- **Subagent Dispatch Rules**:
  1. **Fresh Context & Atomic Scope**: Spawn each subagent with a fresh context, explicit role, `PROCEED` authorization, and at most 1 atomic item (1 issue, 1 Epic/Feature/Story/Use Case, or 1 component). Terminate/reclaim subagents immediately upon completion.
  2. **Skill-Reading vs. Surgical Edit Fast-Path**: For skill workflows (`debug-protocol`, `adversarial-code-auditor`, spec generation, ConOps/ICD/Blueprint/WBS synthesis, TDD implementation), instruct the subagent to `view_file` the active `SKILL.md` first (follow `SKILL.md` literally; reject summarized/steered prompts). For bounded surgical edits where exact `Target`/`Replacement` blocks are already approved in `implementation_plan.md`, skip `SKILL.md` and apply `edit_file` directly.
  3. **Strict File & Verification Boundary**: Subagents must ONLY read/edit their explicitly assigned target files and must NEVER run `verify-baseline`, `cargo test`, `git commit`, or `git push` (unless executing an autonomous `debug-protocol` TDD loop). Coordinator runs verification and commit gates once at completion.
  4. **Step 1.5 Failure Mode Swarm**: Decompose AST `part def` components in `.pipeline/schema.sysml` and dispatch isolated `Component Failure Mode Researcher` subagents per component to populate `docs/research/FAILURE_MODE_REGISTRY.md` across the 4 Universal Failure Dimensions before STPA/FMECA synthesis.
  5. **3-Layer Definition of Done**: Every spec item and micro-task must close all 3 layers: (1) Domain State & Data Model, (2) Logic & State Management, (3) Presentation & Actuator Interface Binding (`N/A` is forbidden).

## 4. Native Rust TDD, Build Tiers & Verification Gates
- **Zero Python / Zero Shell Scripts (Checks 32 & 33)**: Creating or running `*.py`, `pytest`, `*.sh`, or retired scripts (`verify_downstream_baseline.py`, `sysmlv2_ingest.py`, `e2e_acceptance_harness.py`, `reconcile_backlog.py`, `parity_auditor`, `setup_git_hooks.sh`) is strictly forbidden.
- **Mandatory Rust RED-GREEN-REFACTOR TDD**: All executable changes under `crates/` require native Rust `#[test]` unit/mutation tests demonstrated RED before implementation and GREEN after. Filesystem test fixtures must use auto-cleaned temp directories (never create mock workspaces like `test_project/` in the repo). Never write `fs::read_to_string(...).contains(...)` tests in `crates/` to test Markdown prompt files.
- **3-Tier Incremental Verification Gate (Run at Coordinator Pre-Commit Only)**:
  - **Tier 1 (Markdown/Governance only -- `AGENTS.md`, `rules/*.md`, `skills/**`, `.pipeline/*`, `README.md`)**: Zero `cargo` runs; run `./target/release/verify-baseline . --no-domain` prior to commit.
  - **Tier 2 (Single-crate internal change -- `crates/<crate>/**`)**: `cargo test -p <crate> <filter>` during TDD; `cargo test -p <crate>` before commit (plus `cargo build --release -p <bin>` if CLI runtime code changed).
  - **Tier 3 (Cross-crate `pub` API or `Cargo.toml`/`Cargo.lock` change)**: `cargo test -p <crate>` + `cargo check --workspace --all-targets` during iteration; `cargo test --workspace` before commit.
- **Native Binaries & App Builds**: Use release binaries (`./target/release/{verify-baseline,reconcile-backlog,compile-sysml,ingest-sysml,assemble-conops}`). During Step 4 downstream verification, run a full application build (`flutter build` / `npm run build` per profile).
- **Upstream Defect Reporting**: Before filing upstream tooling bugs, dispatch `skills/adversarial-code-auditor/SKILL.md` to create a 7-section dossier in `.pipeline/defects/<NAME>.md` and validate/publish via `./target/release/verify-baseline check-defect .pipeline/defects/<NAME>.md`. Never apply silent local patches.

## 5. Git Hygiene, Formatting & Workspace Invariants
- **Parallel-Safe Scoped Git & Remote Sync**: Stage and commit only explicit paths (`git add -- <files>` and `git commit --only -- <files>`). Never run unscoped `git add .`, `git add -A`, `git commit -a`, `git checkout .`, `git restore .`, or `git stash`. Verify `git diff origin/<branch>` is empty before final reporting. Update `README.md` when rules or directories change, and never wholesale-replace documentation without user approval.
- **Issue Tagging & Non-Closure**: Never use auto-closing commit keywords (`fix #`, `fixes #`, `close #`, `resolve #`); use `(#<id>)` or `(refs #<id>)`. Transition resolved issues to `status:fixed-resolved` (or `status::fixed-resolved` on GitLab) with verification evidence before walkthrough completion.
- **Formatting & Paths**:
  - **Zero Em Dash**: Unicode em dashes (`\u2014`) are strictly forbidden; use `--` or `-`.
  - **Workspace-Relative Paths**: Use only workspace-relative (`./...`) or env-derived paths; never hardcode machine/user paths. Root source writes are forbidden (`app_flutter/` for Flutter, `web_react/` for React). Durable artifacts go in `docs/`, `schema/`, or `.pipeline/defects/`.
  - **Mermaid & KaTeX**: Mermaid blocks require valid headers, newline closing fences, double-quoted labels for `/ : () [] <>`, and zero `{}` or secondary colons in class members. KaTeX `$$` blocks must sit on isolated lines using `\begin{aligned}...\end{aligned}` (never `\begin{align}` or `$REQ-*$`).
  - **Empirical State & `exebox` TLS**: Verify state via `git status`, `ls`, and `gh issue view`/`gh api` (using `<ADDITIONAL_METADATA>` for date). If `gh` hits `x509`/`401` on macOS `exebox`, run `security add-trusted-cert -d -r trustRoot -k ~/Library/Keychains/login.keychain-db /tmp/antigravity-ca.crt` and `gh auth token | gh auth login --with-token --insecure-storage`.
